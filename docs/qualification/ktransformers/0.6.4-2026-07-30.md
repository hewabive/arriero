wheel is therefore required on this host.

The qualified candidate repacks the same pure-Python wheel after applying

## Superseded 0.6.3.post1 result

The `0.6.3.post1` server reached HTTP 200 and served all tested OpenAI
endpoints, but generated semantically corrupted tokens. The failure remained
with:

- CUDA graph, radix cache, and deferred experts disabled;
- zero or 32 GPU experts;
- one CPU pool or two pools mapped to the single NUMA node;
- both the pinned `transformers-kt` package and standard
  `transformers==4.57.1`.

This excludes the model artifacts, Transformers warning, CUDA expert path,
deferred scheduling, and NUMA pool count as primary causes. Version
`0.6.3.post1` is not qualified for inference on this host.

## Live baseline

The patched `0.6.4` pair reached `/health` and `/v1/models` HTTP 200 in
5 minutes 39 seconds with the conservative profile:

- one KTransformers CPU pool using all 8 visible CPU cores;
- 32 GPU experts and no deferred experts;
- CUDA graph and radix cache disabled;
- two running requests and 8,192 total scheduled tokens;
- 0.8 static GPU-memory fraction.

The first semantic request, which also compiled the patched JIT kernel,
completed in 76.7 seconds. It produced coherent reasoning about `2 + 2`
instead of the corrupted output from the unpatched wheel. Deterministic
`/no_think` probes then returned exactly:

| Probe | Result | Wall time |
| --- | --- | --- |
| `2 + 2` | `4` | 3.63 s |
| `7 * 6` | `42` | 4.47 s |

Direct protocol checks passed for non-streaming and streaming
`/v1/chat/completions` and for `/v1/responses`. Two concurrent chat requests
returned the correct values `12` and `14` in 5.67 seconds total.

Arriero published the instance as `qwen3-30b-a3b-kt`. End-to-end requests
through the manager proxy passed:

| OpenAI Chat Completions | `10` / `10` | 200 |

The manager's engine probes report `/health` and `/v1/models` healthy. Its
