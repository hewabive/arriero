## Package pair — public PyPI wheels

Both roots use upstream `0.7.0` (released 2026-08-17/18), installed from the

| `sglang-kt` | `sglang_kt-0.7.0-py3-none-any.whl` | `27964c3a2dae9bcd99f1b43b5d19bbeb4ab27ba7d6aa4e3b17c7755c94a8efe3` |

`kt-kernel` 0.7.0 is a multi-variant ("fat") wheel: six extension builds
(`amx`, `avx512_bf16`, `avx512_vbmi`, `avx512_vnni`, `avx512_base`, `avx2`)
selected at import time by `kt_kernel/_cpu_detect.py` from `/proc/cpuinfo`,
with a guard refusing a variant newer than the host ISA and an explicit env
override (`KT_KERNEL_CPU_VARIANT`). On this host the dispatcher selects
`avx2` and `kt_kernel_ext.CPUInfer(1)` passes — the same smoke test that
SIGILLed with the public single-variant 0.6.4 wheel. The 0.6.4 "do not
substitute the public wheels" restriction is version-specific and does not
extend to 0.7.0.

The AVX2 extension compiles software-fallback MoE classes for `BF16`, `FP8`,
`GPTQ_INT4`, `RAWINT4`, `MXFP4` and `MXFP8`; `FP8_PERCHANNEL` remains
AVX-512/AMX-only. arriero preflight was updated to version-conditional ISA
rules (`METHOD_CPU_FEATURES` + `LEGACY_METHOD_CPU_FEATURES` in
`process/preflight-ktransformers.ts`): FP8 and BF16 require only `avx2` on
kt-kernel ≥ 0.7.0 and keep the AVX-512 requirements below it.

kt-kernel 0.7.0 widens the inference method set to 13 (adds `GPTQ_INT4`,
`SYCL_GPTQ_INT4`, `MXFP4`, `MXFP8`, `MOE_INT4`, `MOE_INT8`); the typed
`KTransformersMethodSchema` still exposes the qualified seven — extending it
is recorded follow-up work, not part of this gate.

## Live baseline

- KT placed 2 GPU experts on each of 40 MoE layers (uniform strategy, 80
  total); `FP8SafeTensorLoader` detected the block-wise
  (`weight_scale_inv`) scale format.
- `/health` and `/v1/models` reached HTTP 200 in **161 s** on the cold
  start and **107 s** on a second start with a warm page cache (0.6.4
  LLAMAFILE: 5 m 39 s). `/v1/models` reports the configured served name
  `qwen3.5-35b-a3b-kt` with `max_model_len` 262144.
- First semantic request (includes warmup/JIT): 116 tokens in 53.9 s.
  Deterministic warm probes with thinking disabled: `7 * 6` → `42` in
  5.7 s; streaming `3 + 5` → `8` in 3.9 s.
- Three concurrent probes against `--max-running-requests 2` (queue boundary
  exercised) returned `12` / `32` / `6` in 13 s total.
- Sustained decode: 128 forced tokens in 56.5 s ≈ **2.3 tok/s**. The AVX2
  FP8 fallback is a correctness path, not a performance path; upstream notes
  memory bandwidth as the bottleneck and this VM slice exposes 8 cores.
- Measured baseline receipt (memory-assessment, evidence `measured`):
  13.9 GiB device, 40.1 GiB anonymous host RSS, 2.7 GiB file-backed
  mappings, swap 0; measured draws gpu0 13.9 GiB / host 42.8 GiB. Declared
  draws were raised to 21 / 46 GiB accordingly.
- Health summary is intentionally `degraded` while serving correctly: swap
  is enabled host-wide, and the declared 46 GiB host draw exceeds the
  remaining available RAM once the model is resident.

## Lifecycle

- Editing manager sources restarted the dev API twice with the engine
  running; reconcile re-adopted the same pid both times (`adopted: true`)
  and a proxied semantic request passed after adoption (`9 + 9` → `18`).
- Stop during an active proxied request returned a controlled HTTP 502
  (`arriero_proxy_upstream_error`) and removed the root, all descendants,
  the port-30000 listener and the GPU compute process within seconds; the
  run closed with `stopReason: operator` (adopted runs expose no
  `exitCode`, by design).
- Stop while idle closed the run cleanly with the same full-tree cleanup.
- Production self-update drain is unavailable under `pnpm dev` (same scope
  note as the 0.6.4 record); manager reload/adoption and active-tree
  shutdown cover the local lifecycle work possible here.
- One operational lesson recorded: HF download jobs live in the API process,
  so a dev-server reload kills a running download (it resumes on re-POST).

## arriero changes motivated by this gate

- `process/preflight-ktransformers.ts`: version-conditional ISA rules — FP8
  and BF16 require only AVX2 on kt-kernel ≥ 0.7.0; the same-directory
  model/CPU-weights warning now fires only for `LLAMAFILE` (same-dir is the
  canonical 0.7.0 native-method configuration).
- `memory-assessment/measured.ts`: the measured-baseline readiness gate
  accepts the HTTP health probe as authority; the sglang log parser's
  `ready` flag is computed over a bounded log tail and regresses to `false`
  once startup lines scroll out of the window.

## Verdict

The public 0.7.0 wheel pair, the pinned `Qwen/Qwen3.5-35B-A3B-FP8` revision
and the tuned FP8 profile in this document are qualified on this host,
including proxy protocols, concurrency, adoption and shutdown behavior.
Decode throughput (~2.3 tok/s) marks this profile as functional rather than
fast on 8 AVX2 cores. AMX/AVX-512 hosts, the new 0.7.0-only methods,
multi-GPU and multi-NUMA topologies require their own recorded
qualification.

Repository verification in the qualification tree: `pnpm check` passed
(full gate incl. 1,676 api tests); the preflight ISA change carries a
dedicated test (`KTransformers 0.7.0 runtime allows FP8 and BF16 on AVX2
hosts`).
