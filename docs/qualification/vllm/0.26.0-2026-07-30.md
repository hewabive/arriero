## Qualified managed profile

The instance `qwen3-4b-vllm` uses:

```text
model=/home/maxim/arriero/runtime/models/Qwen3-4B-1cfa9a72
CUDA_VISIBLE_DEVICES=0
VLLM_USE_FLASHINFER_SAMPLER=0
--host 127.0.0.1
--port 8000
--served-model-name qwen3-4b-vllm
--gpu-memory-utilization 0.85
--max-model-len 8192
--max-num-seqs 2
--max-num-batched-tokens 4096
--tensor-parallel-size 1
--reasoning-parser qwen3
--enable-prefix-caching
--generation-config vllm
```

The explicit sampling-backend override is part of this host profile. The
default FlashInfer sampler attempted a JIT build with the host CUDA 12.0
compiler against the environment's CUDA 13 headers. The bundled CUDA compiler
was newer than PyTorch's CUDA 13.0 runtime. Disabling only the FlashInfer
sampler selected the PyTorch/Triton sampler and avoided that compiler coupling;
vLLM still selected FlashAttention for model attention.

The estimator reserves 21,893,637,734 bytes (85% of the selected GPU pool).
Host memory is a manual 8-GiB reservation. Scheduling is `preemptible`.

## Findings closed during qualification

- The estimator no longer assumes an upstream default for
  `--gpu-memory-utilization`; it requires an explicit value because the default
  changed from 0.9 in older versions to 0.92 in 0.26.0.
- The vLLM log parser no longer treats INFO text containing `mode=warn` as a
  warning or an access log for `/v1/models` as the loaded model path.
- The supported Model Runner V2 limitation is a capability notice, not degraded
  health.
- vLLM preflight now requires a model and rejects missing explicit local model
  paths before process launch.
- Python terminal exception lines such as `OSError:` are retained in the
  health summary.

## Qualification boundary

This record qualifies one Linux x86-64, NVIDIA CUDA, tensor-parallel-size 1,
text-generation profile. It does not qualify tensor parallelism across
multiple GPUs, multi-node serving, ROCm, CPU serving, quantized model loaders,
LoRA, multimodal models, tool-call parsers, sleep mode, or production
self-update drain. Those variants must repeat the release gate in
`docs/VLLM_OPERATIONS.md`; unit coverage of generic drain behavior is not a
substitute for a production deployment test.
