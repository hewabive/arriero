# --enable-tf32-matmul

## Кратко

Тело современной LLM считается в bf16/fp16/fp8, но отдельные операции остаются в float32 — в первую очередь GEMM гейта MoE-роутера, где точность влияет на выбор экспертов. По умолчанию PyTorch выполняет такие матмули «честно», на FP32-ALU. Флаг переводит их в режим `high`, то есть на тензорные ядра с представлением TensorFloat32: тот же диапазон экспоненты, но мантисса 10 бит вместо 23. На Ampere и новее это кратное ускорение fp32-матмулей. Флаг глобальный для процесса: он не выбирает конкретный слой, а меняет политику всех fp32-матмулей PyTorch.

## Оригинальная справка

```text
Enable float32 matmuls to use TensorFloat32 precision for better performance (via torch.set_float32_matmul_precision). CUDA only.
```

## Паспорт аргумента

- Флаги: `--enable-tf32-matmul`
- Группа: `exec.features`
- Тип значения: bool (флаг без значения, `store_true`)
- Допустимые значения: `choices` нет
- Значение по умолчанию: `false`
- Эффективное значение: **включается автоматически** реестром `arg_groups/overrides.py` для двух архитектур: `MiniMaxM2ForCausalLM` и `Glm4MoeForCausalLM`, обе с одинаковой формулировкой в логе — `Enable TF32 matmul for <Arch> model to improve gate gemm performance.` Для GLM-4 MoE переопределение безусловное, независимо от поколения GPU. Обратной операции нет: отключить TF32 на этих моделях флагом невозможно
- Где объявлен: `ServerArgs.enable_tf32_matmul`, файл — `sglang/python/sglang/srt/server_args.py`; поле помечено `resolvable=True`
- Статус: обычный
- Этап применения: разбор CLI → реестр переопределений (модельное включение) → `ModelRunner.__init__` (`torch.set_float32_matmul_precision("high")`) → все последующие fp32-матмули в процессе

## Что меняет в движке

Одна строка в `model_executor/model_runner.py`:

```python
if get_exec().features.enable_tf32_matmul:
    torch.set_float32_matmul_precision("high")
```

Вызывается в конструкторе `ModelRunner`, до `set_device`, то есть до загрузки весов и до любого форварда. Никаких дополнительных проверок в этом месте нет: справка говорит «CUDA only», но код не отбрасывает флаг на других устройствах — просто на не-CUDA бэкендах вызов не даст эффекта, потому что TF32 существует в тензорных ядрах NVIDIA.

Что на практике попадает под изменение:

- **GEMM гейта MoE.** Ради него флаг и включают автоматически для MiniMax-M2 и GLM-4 MoE: роутер считает логиты по экспертам в fp32, и это один из немногих fp32-GEMM на горячем пути.
- **LM-голова при `--enable-fp32-lm-head`.** Тут возникает прямой конфликт: вы просите fp32 ради точности, а этот флаг разрешает считать ее с мантиссой 10 бит. Совмещать их бессмысленно.
- **Прочие fp32-матмули**, попадающиеся в слоях нормализации, эмбеддингах и вспомогательных путях конкретных моделей.

Никакие bf16/fp16/fp8-ядра флаг не затрагивает: они и так на тензорных ядрах.

## Значения и формат

- Флаг без значения; парной `--no-…` формы нет.
- Настройка глобальная для процесса и необратимая в рамках его жизни: снять ее запросом или на лету нельзя.
- Эффект есть на GPU с тензорными ядрами, поддерживающими TF32 — Ampere (SM80) и новее. На более старых картах и на не-CUDA устройствах вызов безвреден и бесполезен.
- Промежуточных уровней («medium», то есть bf16-аппроксимация) флаг не предлагает: только `high`.

## Когда использовать

- Профилирование показало заметное время в fp32-GEMM, и вы готовы обменять точность роутера на скорость. На MoE-моделях это самый частый случай — но для двух архитектур движок уже сделал этот выбор за вас.
- Воспроизведение конфигурации, где TF32 был включен, чтобы числа сходились с эталоном.
- Не включайте вместе с `--enable-fp32-lm-head`: это взаимно отменяющие решения.
- Не включайте, если вы отлаживаете расхождение с эталонной реализацией: TF32 — типичный источник «почти совпало».
- Не ожидайте эффекта на модели без fp32-операций на горячем пути: у плотной bf16-модели ускорять почти нечего.

## Влияние на производительность и память

- **Latency и throughput.** Выигрыш ровно в той доле времени, которую занимают fp32-матмули. Для MoE-роутера это единицы процентов шага, для остальных путей обычно меньше.
- **VRAM.** Не меняется: формат хранения остается fp32, меняется только точность вычисления на тензорных ядрах.
- **Точность.** Мантисса результата эффективно падает до уровня TF32. Для выбора top-k экспертов это почти всегда безопасно (важен порядок, а не точные значения), для логитов LM-головы — нет.
- **Время старта.** Не меняется.
- **Хост.** Не меняется.

## Взаимодействие с другими аргументами

- `--enable-fp32-lm-head`: взаимно противоречат друг другу; включайте что-то одно.
- `--device`: эффект только на CUDA.
- `--dtype`: определяет, сколько fp32-операций вообще осталось на горячем пути.
- `--moe-runner-backend`: часть backend'ов считает гейт своими ядрами и на политику PyTorch не смотрит; тогда флаг ни на что не влияет.
- `--quantization`: на квантованных путях fp32-матмулей меньше, выигрыш меньше.
- `--enable-deterministic-inference`: флаг не сбрасывается детерминированным режимом, но TF32 меняет числовой результат относительно честного fp32 — если вы сравниваете два запуска, следите, чтобы значение флага совпадало.

## Типовые проблемы и диагностика

- **Симптом:** в дампе `server_args=` `enable_tf32_matmul=True`, хотя вы его не задавали. **Причина:** модель `MiniMaxM2ForCausalLM` или `Glm4MoeForCausalLM`. **Проверка:** строка `Enable TF32 matmul for … model to improve gate gemm performance.` в логе старта.
- **Симптом:** результаты слегка расходятся с эталоном на HF-трансформерах. **Причина:** TF32. **Решение:** убрать флаг — если модель не из списка авто-включения, для которого снятия не предусмотрено.
- **Симптом:** флаг включен, ускорения нет. **Причина №1:** карта старше Ampere. **Причина №2:** на горячем пути нет fp32-матмулей.
- **Симптом:** `--enable-fp32-lm-head` не дал ожидаемой точности. **Причина:** одновременно включен TF32.
- **Что смотреть:** итоговый дамп `server_args=` при старте и строки авто-включения из реестра переопределений.

## Примеры

```bash
python -m sglang.launch_server --model-path /models/Qwen3-30B-A3B --enable-tf32-matmul
```

```bash
python -m sglang.launch_server --model-path /models/Qwen3-30B-A3B --enable-tf32-matmul --moe-runner-backend auto
```
