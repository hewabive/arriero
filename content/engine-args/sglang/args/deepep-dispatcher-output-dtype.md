# --deepep-dispatcher-output-dtype

## Кратко

Перед тем как отправить токен на чужой ранг, DeepEP может сжать скрытое состояние. Чем компактнее тип, тем меньше байт по NVLink и RDMA, но тем раньше происходит потеря точности — квантизация выполняется до пересылки, а не внутри ядра эксперта. По умолчанию `auto`, и тогда тип выводится из квантизации модели и выбранного MoE-раннера. Аргумент нужен, когда автоматический вывод дает не тот тип, который ожидает ваша связка ядер.

## Оригинальная справка

```text
Select DeepEP dispatcher output dtype
```

## Паспорт аргумента

- Флаги: `--deepep-dispatcher-output-dtype`
- Группа: `exec.moe`
- Тип значения: перечисление
- Допустимые значения: `auto`, `bf16`, `fp8`, `int8`, `nvfp4`
- Значение по умолчанию: `auto`
- Эффективное значение: явное значение стоит первым в цепочке `get_deepep_output_dtype` и перебивает все остальные шаги; после этого его еще может поправить проверка железа — на GPU `int8` заменяется на `fp8` с предупреждением, на Ascend `fp8` заменяется на `int8`, а `nvfp4` там отвергается `RuntimeError`
- Где объявлен: `ServerArgs.deepep_dispatcher_output_dtype`, файл — `sglang/python/sglang/srt/server_args.py`
- Статус: обычный
- Этап применения: настройка квантизации диспетчера (`set_quant_config` при построении MoE-слоя) → каждый dispatch

## Что меняет в движке

`get_deepep_output_dtype` (`sglang/python/sglang/srt/layers/moe/utils.py`) проходит шаги по порядку и возвращает первый сработавший:

0. явное значение аргумента, если оно не `auto`;
1. устаревшая переменная `SGLANG_DEEPEP_BF16_DISPATCH` (с предупреждением о замене на этот аргумент);
2. `input_global_scale` в конфиге квантизации → NVFP4;
3. режимозависимый ключ конфига квантизации (`normal_dispatcher_output_dtype` / `low_latency_dispatcher_output_dtype`) — некоторым ядрам нужен разный формат для prefill и decode;
4. общий ключ `dispatcher_output_dtype` из конфига квантизации;
5. раннеры `flashinfer_cutedsl`, `cutlass`, `humming` → BF16, потому что они квантуют вход сами;
6. NPU → BF16;
7. иначе FP8 (это то, что получают DeepSeek-V3-подобные модели по умолчанию).

Результат превращается в пару флагов диспетчера `use_fp8` / `use_nvfp4`. Обратите внимание, что задание значения руками выключает шаги 2–4, то есть игнорирует то, что запросила квантизация модели. Именно поэтому явное значение — инструмент отладки и обхода, а не штатная настройка.

Проверка железа (`_validate_and_adjust_dtype`) выполняется после выбора:

- на GPU `int8` не поддерживается и молча (с `warning_once`) заменяется на `fp8`;
- на Ascend A2/A3 `fp8` заменяется на `int8`, а `nvfp4` дает `RuntimeError: Ascend A2/A3 NPU does not support nvfp4 deepep_dispatcher_output_dtype.`

## Значения и формат

- `auto` — цепочка выше. Правильный выбор в подавляющем большинстве случаев.
- `bf16` — без сжатия. Максимальный трафик, максимальная точность; нужен, когда ядро эксперта квантует вход само.
- `fp8` — вдвое меньше байт, чем bf16; де-факто основной боевой вариант на NVIDIA для FP8-моделей.
- `int8` — вариант для Ascend; на GPU будет заменен на `fp8`.
- `nvfp4` — самый компактный, требует поддержки NVFP4 в ядрах и соответствующей квантизации весов; на Ascend отвергается.
- Значение `mxfp8` существует во внутреннем перечислении `DispatcherOutputDtype`, но в `choices` этого аргумента его нет — задать его можно только через конфиг квантизации модели.

## Когда использовать

- Ядро эксперта падает или дает мусор на квантованном входе: временно поставьте `bf16` и проверьте, что дело именно в формате dispatch.
- Модель заявляет один формат в конфиге квантизации, а установленная версия ядер его не поддерживает: явное значение позволит запуститься, не переписывая конфиг модели.
- Упираетесь в межузловую сеть на prefill и уверены, что ядра переживут более компактный формат: `fp8`/`nvfp4` уменьшают трафик пропорционально.
- Не задавайте значение «для скорости» на модели, чья квантизация уже запросила формат через конфиг: вы отключите шаг, который знает про совместимость ядер.

## Влияние на производительность и память

- **Сетевой трафик и буферы.** Объем dispatch пропорционален числу байт на элемент: bf16 = 2 байта, fp8/int8 = 1 байт плюс масштабы, nvfp4 — около половины байта плюс масштабы. Буферы DeepEP считаются по `hidden_size * param_bytes`, поэтому тип влияет и на VRAM под коммуникацию.
- **Latency.** Более компактный тип сокращает время пересылки, но добавляет квантование перед dispatch и деквантование/обработку масштабов на приемной стороне.
- **Точность.** Квантизация активаций до пересылки — потеря, не восстанавливаемая на приемной стороне. Замечать ее надо на оценках качества, а не на perplexity одной фразы.
- На KV-кеш и веса аргумент не влияет.

## Взаимодействие с другими аргументами

- `--moe-a2a-backend`: значение читает диспетчер DeepEP; для `none` и не-DeepEP-путей неприменимо.
- `--deepep-mode`: цепочка авто-вывода умеет разные форматы для `normal` и `low_latency` через конфиг квантизации — явное значение это различие стирает.
- `--moe-runner-backend`: `flashinfer_cutedsl`, `cutlass`, `humming` в `auto` дают `bf16`; принудительный `fp8` вместе с ними, скорее всего, приведет к ошибке в ядре.
- `--quantization`: главный источник авто-решения (шаги 2–4).
- `--deepep-config`: тип и конфиг вместе определяют итоговый размер коммуникационных буферов.

## Типовые проблемы и диагностика

- `GPU does not support int8 deepep_dispatcher_output_dtype, switching to fp8...` — заданный `int8` на GPU; поставьте `fp8` явно, чтобы конфигурация была честной.
- `Ascend A2/A3 NPU does not support fp8 deepep_dispatcher_output_dtype, switching to int8...` — зеркальная ситуация на NPU.
- `RuntimeError: Ascend A2/A3 NPU does not support nvfp4 deepep_dispatcher_output_dtype.` — отказ на старте MoE-слоя.
- Предупреждение про `SGLANG_DEEPEP_BF16_DISPATCH` — переменная устарела, замените на `--deepep-dispatcher-output-dtype bf16`.
- Ошибка в ядре эксперта про неожиданный dtype входа — вероятно, явное значение разошлось с ожиданиями раннера; верните `auto`.
- Заданное значение видно в дампе `server_args=`; фактический выбор при `auto` в лог отдельно не печатается — определяйте его по конфигу квантизации модели и раннеру.

## Примеры

```bash
python -m sglang.launch_server --model-path deepseek-ai/DeepSeek-V3 --tp-size 8 --ep-size 8 --moe-a2a-backend deepep --deepep-mode normal --deepep-dispatcher-output-dtype fp8
```

```bash
python -m sglang.launch_server --model-path deepseek-ai/DeepSeek-V3 --tp-size 8 --ep-size 8 --moe-a2a-backend deepep --deepep-mode low_latency --deepep-dispatcher-output-dtype bf16
```
