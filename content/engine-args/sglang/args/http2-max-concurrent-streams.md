# --http2-max-concurrent-streams

## Кратко

В HTTP/2 один TCP-коннект несет много параллельных потоков, и сервер объявляет их предел параметром `SETTINGS_MAX_CONCURRENT_STREAMS` в кадре SETTINGS. `--http2-max-concurrent-streams` задает это число для Granian-сервера, который SGLang использует при `--enable-http2`. Дефолтные 200 означают: один клиентский коннект может держать до 200 одновременных запросов (в том числе долгоживущих SSE-стримов генерации); 201-й поток клиент обязан отложить или открыть второй коннект. Это ограничитель транспорта, не планировщика — на очередь и батчинг самого движка он не влияет.

## Оригинальная справка

```text
Maximum number of concurrent streams advertised on each HTTP/2 connection (1 to 2^32 - 1). Only applies with --enable-http2.
```

## Паспорт аргумента

- Флаги: `--http2-max-concurrent-streams`
- Группа: `serving`
- Тип значения: int
- Значение по умолчанию: `200`
- Эффективное значение: не переписывается; при `--enable-http2` `__post_init__` проверяет диапазон `1…4294967295`, без него значение игнорируется полностью
- Где объявлен: `ServerArgs.http2_max_concurrent_streams`, файл — `sglang/python/sglang/srt/server_args.py`
- Статус: обычный
- Этап применения: `__post_init__` (валидация диапазона) → конструирование Granian-сервера (`_run_granian_server`) → каждое HTTP/2-соединение

## Что меняет в движке

Единственный потребитель — `_run_granian_server` (`sglang/python/sglang/srt/entrypoints/http_server.py`): значение уходит в `HTTP2Settings(max_concurrent_streams=…)` и попадает в kwargs Granian в обеих ветках — embedded-сервера (`--tokenizer-worker-num 1`) и многопроцессного `Granian` (`workers > 1`). Дальше это чистая механика протокола: сервер анонсирует лимит в SETTINGS, соблюдение — обязанность клиента; превысивший его поток получает протокольную ошибку соединения.

Лимит действует **на соединение**, а не на сервер: десять клиентов с десятью коннектами дают до `10 × N` потоков. Общий ограничитель одновременных запросов — это по-прежнему очередь и настройки движка (`--max-running-requests` и очередь планировщика), а также `backpressure=2048` самого Granian.

В uvicorn-ветке (без `--enable-http2`) значение не читается нигде: HTTP/1.1 несет один запрос на соединение, и понятия параллельных потоков там нет.

## Значения и формат

- Целое от 1 до 4294967295 (2^32 − 1) — границы диапазона проверяются на старте, но только при включенном `--enable-http2`.
- `1` фактически выключает мультиплексирование: один запрос на коннект, как в HTTP/1.1, но с overhead'ом HTTP/2.
- Значения выше нескольких тысяч бессмысленны: каждый живой поток — это запрос, реально стоящий в очереди движка.

## Когда использовать

- Один агрегатор/шлюз держит к серверу единственный коннект и гонит через него больше 200 параллельных генераций — поднимите лимит, иначе клиентская библиотека начнет тихо сериализовать запросы, что выглядит как деградация throughput при холостом GPU.
- Понизить (10–50), если нужно грубо отсечь чрезмерный параллелизм одного клиента еще на транспорте, до очереди движка.
- Не трогать без `--enable-http2` — значение мертвое.
- Не использовать как замену лимитам движка: поток, принятый транспортом, все равно ждет в очереди планировщика.

## Влияние на производительность и память

- На VRAM, модель и скорость генерации не влияет: это анонс в кадре SETTINGS.
- RAM: каждый одновременный поток — буферы соединения и объект запроса в ASGI-приложении; при разумных значениях незаметно.
- Throughput: занижение относительно фактического параллелизма клиента — единственный сценарий, где флаг виден в метриках (запросы сериализуются на клиенте, до сервера не доходя).

## Взаимодействие с другими аргументами

- `--enable-http2`: обязательное условие — и применения, и самой валидации диапазона.
- `--tokenizer-worker-num`: выбирает embedded- или многопроцессный Granian; значение передается в обоих случаях.
- `--host` / `--port`: тот же сервер, то же соединение.
- `--log-level-http`: уровень логов того же Granian.
- Лимиты движка (`--max-running-requests`): реальный потолок одновременной работы; транспортный лимит имеет смысл держать не ниже него, если клиент один.

## Типовые проблемы и диагностика

- `ValueError: --http2-max-concurrent-streams must be between 1 and 4294967295.` на старте — значение вне диапазона при включенном `--enable-http2`.
- Клиент с одним коннектом не разгоняется выше ~200 параллельных запросов — уперся в анонсированный лимит; поднимите значение или откройте больше коннектов на клиенте.
- Задали флаг, а поведение не изменилось — `--enable-http2` не включен: работает uvicorn, значение игнорируется. Проверьте строку `Starting embedded Granian HTTP/2 server on <host>:<port>` в логе.
- Принятое значение видно в дампе `server_args=` (`http2_max_concurrent_streams=…`).

## В arriero

Для kind `ktransformers` флаг наследует все оговорки `--enable-http2`: прокси менеджера ходит в инстанс по HTTP/1.1 (undici), так что мультиплексирование не задействуется, а парсер логов теряет строку `Uvicorn running on`. Оставляйте дефолтный uvicorn — тогда и этот флаг не нужен.

## Примеры

```bash
python -m sglang.launch_server --model-path /models/Qwen3-30B-A3B --enable-http2 --http2-max-concurrent-streams 512
```

```bash
python -m sglang.launch_server --model-path /models/Qwen3-30B-A3B --enable-http2 --http2-max-concurrent-streams 32
```
