# --enable-precise-embedding-interpolation

## Кратко

Визуальный энкодер Qwen3-VL хранит позиционные эмбеддинги на фиксированной квадратной сетке и билинейно интерполирует их под фактический размер изображения. Флаг меняет способ построения координат: по умолчанию используются центры полупикселей (`align_corners=False`), с флагом — равномерный `linspace` от 0 до края (`align_corners=True`). Аргумент узкий: его читает единственный класс `Qwen3VLMoeVisionModel`, и в текущем состоянии кода он влияет на результат только на пути с CUDA graph визуального энкодера.

## Оригинальная справка

```text
Enable corner alignment for resize of embeddings grid to ensure more accurate(but slower) evaluation of interpolated embedding values.
```

## Паспорт аргумента

- Флаги: `--enable-precise-embedding-interpolation`
- Группа: `exec.kernel`
- Тип значения: bool (флаг без значения)
- Допустимые значения: `choices` нет
- Значение по умолчанию: `false`
- Эффективное значение: не переопределяется движком; значение читается один раз в конструкторе `Qwen3VLMoeVisionModel` как `self.align_corners`
- Где объявлен: `ServerArgs.enable_precise_embedding_interpolation`, файл — `sglang/python/sglang/srt/server_args.py`
- Статус: обычный
- Этап применения: разбор CLI → конструктор визуального энкодера при загрузке модели → подготовка позиционных эмбеддингов на каждом проходе энкодера

## Что меняет в движке

Единственный читатель — `sglang/python/sglang/srt/models/qwen3_vl.py`, класс `Qwen3VLMoeVisionModel` (он же используется наследниками: `Qwen3VLForConditionalGeneration`, `qwen3_vl_moe.py`, `qwen3_omni_moe.py`, `qwen3_5.py`).

`_get_interpolation_indices(dim_size)` строит координаты для билинейной интерполяции:

- `align_corners=True` (флаг задан): `np.linspace(0, num_grid_per_side - 1, dim_size)` — первая и последняя точки попадают ровно в углы исходной сетки;
- `align_corners=False` (по умолчанию): `(arange(dim_size) + 0.5) * num_grid_per_side / dim_size - 0.5` с обрезкой в `[0, num_grid_per_side - 1]` — центры ячеек, та же схема, что у `torch.nn.functional.interpolate(..., align_corners=False)`.

Дальше по этим координатам считаются индексы четырех соседей и веса `w00/w01/w10/w11`, и позиционный эмбеддинг собирается как их взвешенная сумма.

**Где это реально применяется.** В классе три реализации интерполяции, и `align_corners` учитывает только одна:

| функция | учитывает `align_corners` | где вызывается |
| --- | --- | --- |
| `fast_pos_embed_interpolate` (numpy-путь, через `_get_interpolation_indices`) | да | `_prepare_graph_inputs`, то есть путь CUDA graph визуального энкодера |
| `fast_pos_embed_interpolate_from_list` | нет, жестко `torch.linspace` | обычный (eager) `forward` |
| `fast_pos_embed_interpolate_vectorized` | нет, жестко `torch.linspace` | обычный `forward` при ≥ 6 изображениях, и путь CUDA graph — но там только если флаг **включен** |

Отсюда следствие, которое стоит понять до включения: обычный eager-путь энкодера всегда работает как `align_corners=True`, независимо от флага. CUDA graph визуального энкодера включается переменной `SGLANG_VIT_ENABLE_CUDA_GRAPH` (по умолчанию `false`), поэтому на дефолтной конфигурации флаг не меняет ничего.

В графовом пути логика такая: при включенном флаге и достаточном числе изображений берется векторизованная реализация (тоже linspace), иначе — numpy-путь, который и разворачивает `align_corners`. Комментарий в коде объясняет, зачем это связано: смешивать две схемы нельзя, иначе результат стал бы зависеть от количества картинок в батче.

## Значения и формат

- Флаг без аргумента; парной формы нет.
- Действует только на модели с визуальным энкодером Qwen3-VL. На текстовой модели и на других VL-архитектурах поле не читается.
- Значение фиксируется при загрузке модели; менять его на живом процессе нельзя.

## Когда использовать

- Когда вы приводите вывод визуального энкодера в соответствие с эталонной реализацией, которая использует выравнивание по углам, и работаете с включенным CUDA graph визуального энкодера (`SGLANG_VIT_ENABLE_CUDA_GRAPH=1`).
- Когда сравниваете качество на бенчмарке с изображениями нестандартного размера и хотите исключить схему интерполяции как источник расхождения.
- Не включайте на дефолтной конфигурации в надежде на «повышение точности»: без CUDA graph энкодера путь и так линспейсный, а без изображений во входе — тем более.
- Не используйте как ручку производительности: справка называет режим «более точным, но более медленным», однако разница — это выбор между двумя формулами координат и, в графовом пути, между векторизованной и поимиджевой реализацией.

## Влияние на производительность и память

- **VRAM.** Не меняется: обе схемы работают на одной и той же таблице эмбеддингов и выделяют одинаковые промежуточные тензоры.
- **Latency prefill с изображениями.** Значима не сама формула, а то, какая реализация выбрана: numpy-путь считает индексы и веса на CPU в цикле по изображениям, векторизованный — одним проходом на GPU. Комментарий к `_use_vectorized_pos_embed` фиксирует, что векторизация окупается начиная примерно с 6 изображений.
- **Время старта.** Не влияет.
- **Качество.** Разница в координатах — доли ячейки сетки; она заметна на изображениях, размер которых сильно отличается от исходной сетки эмбеддингов.

## Взаимодействие с другими аргументами

- `--enable-multimodal`: без мультимодального пути энкодер не запускается вовсе.
- `--mm-attention-backend`: другой аргумент того же визуального энкодера, влияет на ядра внимания, а не на позиционные эмбеддинги.
- `--json-model-override-args`: через него можно изменить `num_position_embeddings`/`patch_size`, то есть саму сетку, к которой применяется интерполяция.
- `--disable-fast-image-processor`: меняет препроцессинг изображения (и, значит, приходящий `grid_thw`), а не интерполяцию эмбеддингов.

## Типовые проблемы и диагностика

- **Симптом:** флаг включен, результат не изменился. **Причина:** визуальный энкодер идет по eager-пути (`SGLANG_VIT_ENABLE_CUDA_GRAPH` не выставлена), где `align_corners` не читается.
- **Симптом:** флаг включен, результат не изменился на батчах с большим числом изображений в графовом режиме. **Причина:** при включенном флаге графовый путь уходит в векторизованную реализацию, которая и без флага работает как linspace.
- **Симптом:** флаг задан на текстовой модели. **Последствие:** никаких — поле не читается, ошибки не будет.
- **Проверка:** дамп `server_args=` при старте показывает флаг; убедиться, что путь энкодера тот, который его читает, можно только по значению `SGLANG_VIT_ENABLE_CUDA_GRAPH` в окружении процесса.

## Примеры

```bash
python -m sglang.launch_server --model-path Qwen/Qwen3-VL-30B-A3B-Instruct --enable-precise-embedding-interpolation
```

```bash
python -m sglang.launch_server --model-path Qwen/Qwen3-VL-30B-A3B-Instruct --enable-precise-embedding-interpolation --mm-attention-backend fa3
```
