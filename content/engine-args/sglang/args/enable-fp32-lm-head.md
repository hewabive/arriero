# --enable-fp32-lm-head

## Кратко

LM-голова — последний слой, переводящий скрытое состояние в логиты по всему словарю. При bf16 у нее самый большой аккумулятор (сумма по `hidden_size`) и самый большой выход (`vocab_size`), поэтому именно здесь потеря мантиссы заметнее всего: близкие по вероятности токены могут поменяться местами. Флаг делает голову fp32: `hidden_states.to(torch.float32) @ lm_head.weight.to(torch.float32).T`. Работает только на непроквантованной голове с обычным `weight` — LoRA-обертка и квантованные `quant_method` идут своим путем и флаг не читают.

## Оригинальная справка

```text
If set, the LM head outputs (logits) are in FP32.
```

## Паспорт аргумента

- Флаги: `--enable-fp32-lm-head`
- Группа: `exec.features`
- Тип значения: bool (флаг без значения, `store_true`)
- Допустимые значения: `choices` нет
- Значение по умолчанию: `false`
- Эффективное значение: не переписывается ни `__post_init__`, ни реестром `arg_groups/overrides.py`
- Где объявлен: `ServerArgs.enable_fp32_lm_head`, файл — `sglang/python/sglang/srt/server_args.py`
- Статус: обычный
- Этап применения: разбор CLI → построение `LogitsProcessor` (значение читается один раз в конструктор, `self.use_fp32_lm_head`) → `_compute_lm_head` на каждом шаге сэмплинга. Кроме того, значение входит в структурную сигнатуру загрузчика весов (`model_loader/loader.py`), то есть кеш весов, снятый с одним значением флага, не подойдет к запуску с другим

## Что меняет в движке

`LogitsProcessor._compute_lm_head` (`layers/logits_processor.py`) выбирает ветку по типу головы, и флаг влияет только на две из них:

```python
elif hasattr(lm_head, "weight"):
    if self.use_fp32_lm_head:
        logits = torch.matmul(hidden_states.to(torch.float32),
                              lm_head.weight.to(torch.float32).T)
    ...
else:  # GGUF
    if self.use_fp32_lm_head:
        with torch.cuda.amp.autocast(enabled=False):
            logits = lm_head.quant_method.apply(lm_head, hidden_states.to(torch.float32), embedding_bias)
```

Ветки, которые флаг **не** затрагивает: LoRA-обернутая голова (`set_lora`/`apply_lora`), квантованная голова через `quant_method` (когда `should_apply_lm_head_quant_method` истинно), путь `intel_amx` и путь `rl_on_policy_target`. Если ваша модель квантована вместе с LM-головой, флаг ничего не изменит.

Обратите внимание, что `lm_head.weight.to(torch.float32)` создает копию весов головы **на каждом вызове** — это не одноразовое приведение при загрузке. Для словаря на 150 000 токенов и `hidden_size` 8192 матрица головы в bf16 — около 2.3 ГиБ; ее fp32-копия — около 4.6 ГиБ временной памяти на каждом шаге декодирования. С TP голова шардируется, и на ранг приходится соответствующая доля, но порядок величины сохраняется.

Что происходит дальше по конвейеру: логиты уходят в софткапинг (если он есть у модели), в all-gather по TP/attention-TP-группе и в сэмплер. То есть fp32 сохраняется до самого сэмплинга, а не сворачивается обратно сразу после GEMM.

## Значения и формат

- Флаг без значения; парной `--no-…` формы нет.
- Не зависит от `--dtype`: он про тело модели, этот флаг — только про последний GEMM.
- Не является режимом «полного fp32»: все слои до головы считаются в своем dtype.
- Не путайте с `SGLANG_DSPARK_FP32_LM_HEAD` — это отдельная переменная окружения для DSPARK-пути DeepSeek-V4, живущая независимо от этого флага.

## Когда использовать

- Модель с очень большим словарем, где вы наблюдаете «дрожание» топа при одинаковом входе или расхождение с эталонной реализацией на HF-трансформерах.
- Оценки, где важны сами значения логитов и logprob'ов, а не только выбранный токен: перплексия, скоринг, ранжирование, RLHF-награды.
- Сравнение с эталоном при отладке квантования: fp32-голова снимает один источник расхождения.
- Не включайте на обычном чат-инстансе: вы платите памятью и временем на каждом шаге ради разницы, которую в сэмплинге с температурой не видно.
- Не включайте, если голова квантована или обернута LoRA: соответствующие ветки флаг не читают.

## Влияние на производительность и память

- **VRAM.** Временная fp32-копия весов головы плюс fp32-тензор логитов (`batch × vocab_size × 4` байт вместо ×2). На большом словаре и большом батче это самый заметный всплеск во всем шаге декодирования.
- **Latency.** Каст весов на каждом вызове — это полное чтение и запись матрицы головы, то есть операция, ограниченная пропускной способностью памяти, добавленная к каждому шагу. На decode это ощутимо.
- **Throughput.** Падает, особенно при большом батче: и GEMM в fp32 медленнее, и all-gather логитов переносит вдвое больше байт.
- **Точность.** Ради нее флаг и существует: снимается округление аккумулятора и выхода головы.
- **Время старта.** Не меняется.

## Взаимодействие с другими аргументами

- `--dtype`: определяет исходный тип весов головы; флаг добавляет каст поверх.
- `--enable-dp-lm-head`: меняет группу, по которой собираются логиты (attention-TP вместо DP-all-gather); с fp32 объем этого all-gather удваивается, поэтому пара особенно чувствительна к ширине линков.
- `--enable-tf32-matmul`: относится к fp32-матмулям вообще. Включив оба флага, вы получите fp32-голову, считаемую на TensorFloat32, то есть с точностью мантиссы около 10 бит — это отменяет смысл fp32-головы. Совмещать их не надо.
- `--enable-deterministic-inference`: fp32-голова уменьшает зависимость результата от порядка суммирования, но детерминизм обеспечивает не она, а сам режим.
- `--quantization`: если LM-голова попала под квантование, флаг не сработает.
- `--weight-cache-mode`: значение флага входит в структурную сигнатуру загрузчика, поэтому его смена инвалидирует совместимость с ранее снятым кешем весов.

## Типовые проблемы и диагностика

- **Симптом:** флаг включен, разницы в логитах нет. **Причина:** голова идет по квантованной, LoRA- или AMX-ветке. **Проверка:** квантование модели и наличие LoRA в конфигурации инстанса.
- **Симптом:** OOM на шаге декодирования при большом батче после включения флага. **Причина:** fp32-копия весов головы плюс fp32-логиты. **Решение:** уменьшить `--max-running-requests` / `--cuda-graph-max-bs` либо выключить флаг.
- **Симптом:** TPOT заметно вырос. **Причина:** каст весов головы на каждом шаге.
- **Симптом:** после включения флага перестал подходить ранее снятый кеш весов. **Причина:** изменилась структурная сигнатура загрузчика.
- **Что смотреть:** итоговый дамп `server_args=` при старте — единственное подтверждение, что флаг принят; отдельной строки о fp32-голове движок не печатает.

## Примеры

```bash
python -m sglang.launch_server --model-path /models/Qwen3-8B --enable-fp32-lm-head
```

```bash
python -m sglang.launch_server --model-path /models/Qwen3-8B --enable-fp32-lm-head --max-running-requests 8 --cuda-graph-max-bs 8
```
