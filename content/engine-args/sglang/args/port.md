# --port

## Кратко

`--port` — порт, на котором слушает HTTP-сервер SGLang. Значение по умолчанию `30000` (не 8000 и не 8080), и оно же прописано как дефолт движка `ktransformers` в arriero.

Практическая тонкость одна, но дорогая: сокет открывается **последним**, уже после загрузки весов и инициализации KV-пула. Занятый порт роняет процесс не на первой секунде, а через минуты — все время загрузки потеряно.

## Оригинальная справка

```text
The port of the HTTP server.
```

## Паспорт аргумента

- Флаги: `--port`
- Группа: `serving`
- Тип значения: int
- Допустимые значения: `choices` нет; argparse примет любое целое, границы проверяет только ОС при `bind`
- Значение по умолчанию: `30000`
- Эффективное значение: совпадает с заданным; `__post_init__` `port` не переписывает. Обратное неверно — от `port` производятся другие значения: в устаревшем `--smg-grpc-mode` без явного `--grpc-port` он становится `port + 10000`, а при `--enable-dp-attention` на одном узле без `--dist-init-addr` база ZMQ-портов равна `port + 233` (константа `ZMQ_TCP_PORT_DELTA`), с откатом на `port − 233` при выходе за 65535
- Где объявлен: `ServerArgs.port`, файл — `sglang/python/sglang/srt/server_args.py`
- Статус: обычный
- Этап применения: разбор CLI → `__post_init__` (производные порты) → `PortArgs.init_new` → HTTP-слой (`uvicorn.run(port=...)` / `Granian(port=...)`), уже после `wait_for_ready()`

## Что меняет в движке

Значение попадает в `ServerArgs.port` и расходится по трем направлениям.

1. **HTTP-слушатель.** `_setup_and_run_http_server` передает `port=server_args.port` в `uvicorn.run` (обычная ветка, ветка `--enable-ssl-refresh` и multi-worker) и в `_run_granian_server` при `--enable-http2`.
2. **Внутренний URL.** `ServerArgs.url()` собирает `http(s)://<loopback-или-host>:<port>` — по нему warmup-поток стучится в собственный `/model_info` и `/generate`.
3. **Производные служебные порты.** В обычном режиме межпроцессное взаимодействие идет по unix-сокетам ZMQ (`ipc://<временный файл>`), и `--port` тут ни при чем. Но при `--enable-dp-attention` на одном узле `PortArgs.init_new` переключается на TCP и резервирует шесть портов подряд от `port + 233`, привязывая их к `127.0.0.1`. Порт `torch.distributed` (`--nccl-port`) от `--port` не производится: без явного значения берется случайный свободный.

Проверка на конфликт в коде ровно одна: `check_server_args` требует `grpc_port != port`, когда нативный gRPC включен не в legacy-режиме (`--grpc-port (<N>) must differ from --port (<M>)`). Пересечение с `--nccl-port` и с производными ZMQ-портами не проверяется — в исходниках рядом с этой проверкой оставлена явная пометка, что такая валидация отложена.

## Значения и формат

- Целое. Практически — `1..65535`; вне диапазона `bind` завершится ошибкой.
- Порты ниже 1024 требуют прав; без них `bind` даст `PermissionError`.
- Особых значений нет: `0` не означает «выбрать свободный» — он уйдет в `bind` как есть, и ОС выдаст случайный порт, о котором никто в конфигурации не узнает.
- При нескольких экземплярах на одном хосте разносите порты с запасом. Шаг в 1 достаточен только для обычного режима; при `--enable-dp-attention` каждый экземпляр дополнительно занимает диапазон `port+233 … port+239`, так что шаг меньше 250 создаст незаметное пересечение между двумя экземплярами.
- В устаревшем `--smg-grpc-mode` без `--grpc-port` занимается еще и `port + 10000`.

## Когда использовать

- Задавайте всегда явно, когда на хосте живет больше одного экземпляра, — дефолт `30000` одинаков у всех, и второй экземпляр упадет на `bind`.
- Оставляйте дефолт для единственного локального инстанса: arriero использует то же значение как дефолт движка, поэтому конфигурация остается короче.
- Не пытайтесь через `--port` «спрятать» сервер. Смена порта не заменяет `--host 127.0.0.1`: сканирование портов дешевле, чем кажется.

## Влияние на производительность и память

На VRAM, RAM и throughput не влияет. Единственный эффект по времени — если порт занят, вы узнаете об этом только в конце старта, потеряв все время загрузки весов.

## Взаимодействие с другими аргументами

- `--host`: пара, задающая точку прослушивания.
- `--grpc-port`: обязан отличаться от `--port` (проверка в `check_server_args`); в legacy `--smg-grpc-mode` по умолчанию равен `port + 10000`.
- `--enable-dp-attention` (одноузловой запуск без `--dist-init-addr`): резервирует шесть TCP-портов от `port + 233`.
- `--nccl-port` / `--dist-init-addr`: отдельная точка рандеву, от `--port` не зависит; пересечение не проверяется.
- `--enable-http2`: тот же порт слушает Granian вместо uvicorn.
- `--fastapi-root-path`: путь, а не порт; на привязку не влияет.

## Типовые проблемы и диагностика

- **Симптом:** `OSError: [Errno 98] Address already in use` через несколько минут после запуска. **Причина:** порт занят другим экземпляром или зависшим процессом. **Проверка:** `ss -ltnp | grep <port>`. **Лечение:** сменить `--port` или добить старый процесс.
- **Симптом:** `--grpc-port (30000) must differ from --port (30000)`. **Причина:** нативный gRPC получил тот же порт. **Лечение:** развести значения.
- **Симптом:** два экземпляра с `--enable-dp-attention` и портами `30000` и `30100` не поднимаются вместе. **Причина:** их производные ZMQ-диапазоны (`30233…30239` и `30333…30339`) не пересекаются, а вот пара `30000`/`30200` дала бы конфликт `30233` против `30200+233`. **Лечение:** разносить порты минимум на 250, либо задавать `--dist-init-addr` явно.
- **Симптом:** порт не отвечает, хотя процесс жив и лог идет. **Причина:** сокет открывается после загрузки весов; до этого момента соединения отбиваются. **Проверка:** ждать строки уровня `Uvicorn running on http://127.0.0.1:30000` (при `--enable-http2` этой строки не будет — там пишет Granian).
- **Симптом (arriero):** preflight пишет `Port <N> is already in use on <host>` или `Invalid port: <значение>`. **Причина:** менеджер валидирует значение и пробует забиндить пару до запуска (`apps/api/src/process/preflight.ts`). **Лечение:** сменить порт.
- **В arriero:** порт по умолчанию для kind `ktransformers` — тот же `30000` (`packages/core/src/engine-descriptor.ts`), и именно из `--port` менеджер строит адрес для health-проверки и для проксирования. Меняя порт на живом инстансе, помните: адрес пересчитывается из launch-снапшота запущенного процесса, а не из текущего JSON, — до перезапуска менеджер продолжит опрашивать старый порт.

## Примеры

```bash
python -m sglang.launch_server --model-path /models/Qwen3-30B-A3B --host 127.0.0.1 --port 30001
```

```bash
python -m sglang.launch_server --model-path /models/Qwen3-30B-A3B --host 127.0.0.1 --port 31000 --enable-dp-attention --dp-size 2 --tp-size 2
```
