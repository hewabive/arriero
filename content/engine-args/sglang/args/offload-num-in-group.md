# --offload-num-in-group

## Кратко

Вторая половина формулы выбора выгружаемых слоев во второй схеме оффлоада. Слои нумеруются подряд, разбиваются на группы длины `--offload-group-size`, и выгружаются **последние** `--offload-num-in-group` слоев каждой группы. Доля выгруженного равна `num_in_group / group_size`: `1` из `4` — четверть, `1` из `2` — половина, `4` из `4` — все. Значение по умолчанию `1`.

Аргумент читается только тогда, когда `--offload-group-size` больше нуля; сам по себе он ничего не включает.

## Оригинальная справка

```text
Number of layers to be offloaded within a group.
```

## Паспорт аргумента

- Флаги: `--offload-num-in-group`
- Группа: `exec.offload`
- Тип значения: int (число слоев)
- Допустимые значения: argparse ограничений не накладывает; осмысленный диапазон — от 1 до `--offload-group-size`
- Значение по умолчанию: `1`
- Эффективное значение: совпадает с заданным; автоподбора и нормализации нет
- Где объявлен: `ServerArgs.offload_num_in_group`, файл — `sglang/python/sglang/srt/server_args.py`
- Статус: обычный
- Этап применения: построение слоев модели (`OffloaderV2.wrap_modules`), однократно

## Что меняет в движке

Единственное место, где значение используется, — условие отбора в `OffloaderV2.wrap_modules` (`sglang/python/sglang/srt/utils/offloader.py`):

```python
if module_index % self.group_size >= self.group_size - self.num_in_group:
    ...  # этот слой выгружается
```

Разбор для `group_size = 4`:

| `--offload-num-in-group` | остатки, попадающие под выгрузку | выгружено |
| --- | --- | --- |
| 1 | 3 | 25 % |
| 2 | 2, 3 | 50 % |
| 3 | 1, 2, 3 | 75 % |
| 4 | 0, 1, 2, 3 | 100 % |

Значение больше `group_size` делает условие тождественно истинным — выгружаются все слои, дополнительного эффекта нет. Значение `0` (или отрицательное при `group_size` больше нуля) делает условие `module_index % group_size >= group_size`, которое никогда не выполняется: схема формально включена, но ни один слой не выгружен.

Выгружается не сам слой, а подмодуль, который указывает модель (`submodule_accessor`), и только перечисленные ею параметры (`whitelist_param_names_creator`). Для DeepSeek V2/V3 это `layer.mlp.experts` с `w13_weight`/`w2_weight`.

## Значения и формат

- Целое число слоев внутри группы.
- `1` — значение по умолчанию и типичный рабочий выбор: минимальная выгрузка при заданном периоде.
- Равное `--offload-group-size` — выгрузка всех целевых подмодулей модели.
- Больше `--offload-group-size` — эквивалентно равному; проверки нет.
- `0` — схема включена, но не выгружает ничего; предвыборка при этом обходит пустой список офлоадеров.
- Без `--offload-group-size` больше нуля значение не читается.

## Когда использовать

- Подбирать вместе с размером группы, а не отдельно: важно отношение. Для «выгрузить половину экспертов» есть два эквивалентных по объему набора — `2/1` и `4/2`, но у них разная зернистость и разный характер трафика по PCIe.
- Увеличивать, когда VRAM не хватает даже при выгрузке каждого четвертого слоя, и вы готовы платить пропускной способностью.
- Держать равным `1` и менять `--offload-group-size`, когда нужна плавная регулировка: так меняется период, а не плотность.
- Не задавать больше размера группы — это не ошибка, но и не выражает намерения; лучше `--offload-group-size 1 --offload-num-in-group 1`.

## Влияние на производительность и память

- VRAM: экономия пропорциональна доле `num_in_group / group_size` от суммарного объема целевых подмодулей.
- RAM хоста: в режиме `cpu` — ровно тот же объем в закрепленной памяти; в `shm_cpu` — одна общая копия на все DP-ранги.
- Время старта: пропорционально числу выгружаемых слоев (перенос при построении и распределение в `post_init`).
- Latency: чем больше выгружено, тем больше данных нужно успеть подкачать за время вычисления соседних слоев. Если полосы PCIe не хватает, ожидание события загрузки становится видимым и forward упирается в копирование.
- Throughput: при плотной выгрузке (`num_in_group` близко к `group_size`) предвыборка перестает спасать, потому что перекрывать копирование становится нечем.

## Взаимодействие с другими аргументами

- `--offload-group-size`: включает схему и задает знаменатель доли; без него значение мертво.
- `--offload-prefetch-step`: определяет, сколько выгруженных подмодулей одновременно резидентны в VRAM — при большой доле выгрузки и большой предвыборке экономия памяти съедается.
- `--offload-mode`: куда именно уезжают выгруженные параметры.
- `--cpu-offload-gb`: альтернативная схема, взаимно исключающая (ассерт на старте).
- `--mem-fraction-static`: освобожденная VRAM автоматически достается KV-пулу.

## Типовые проблемы и диагностика

- Схема включена, но ни одной строки `[offloader] offload module_index=…` в логе — значение `0` (или отрицательное), условие отбора никогда не выполняется.
- Выгрузились все слои, хотя вы этого не просили — значение больше или равно `--offload-group-size`.
- Резкое падение скорости при увеличении значения — предвыборка перестала перекрывать копирование; уменьшайте долю выгрузки либо увеличивайте `--offload-prefetch-step`, если позволяет VRAM.
- `TypeError: 'NoneType' object is not callable` — не про этот аргумент: модель не поддерживает вторую схему оффлоада вовсе.
- Что смотреть в логе: число строк `[offloader] offload module_index=… submodule=… params=[…] memory_allocated=…` — они прямо показывают, какие индексы слоев были отобраны.

## Примеры

```bash
python -m sglang.launch_server --model-path /models/DeepSeek-V2-Lite --offload-group-size 4 --offload-num-in-group 2
```

```bash
python -m sglang.launch_server --model-path /models/DeepSeek-V2-Lite --offload-group-size 2 --offload-num-in-group 1 --offload-prefetch-step 2 --offload-mode cpu
```
