# --cuda-graph-bs

## Кратко

Список размеров батча, под которые захватывается по одному decode-графу. Обычно его не задают: движок строит сетку сам из потолка `--cuda-graph-max-bs-decode`. Явный список нужен там, где реальное распределение батчей узкое и известно заранее — тогда две-три формы вместо двадцати заметно сокращают старт и память под графы. Флаг устарел и переименован в `--cuda-graph-bs-decode`.

## Оригинальная справка

```text
Deprecated alias for --cuda-graph-bs-decode.
```

## Паспорт аргумента

- Флаги: `--cuda-graph-bs`
- Группа: `null` — устаревший алиас объявлен литеральным `parser.add_argument` в `add_cli_args`, вне пофазной группы `exec.graph`
- Тип значения: список целых (`nargs="+"`), значения перечисляются через пробел
- Допустимые значения: положительные целые; argparse ограничений не накладывает, проверка приходит позже
- Значение по умолчанию: у алиаса значения по умолчанию нет; `dest` (`cuda_graph_bs_decode`) уже инициализирован значением `None` от актуального флага
- Эффективное значение: `None` означает «построить сетку из потолка». Если список задан, `_handle_gpu_memory_settings` дополнительно выставляет `cuda_graph_config.decode.max_bs = max(bs)`, то есть потолок берется из списка, а не из таблицы по объему карты
- Где объявлен: `ServerArgs.add_cli_args`, файл — `sglang/python/sglang/srt/server_args.py`; `dest` — `cuda_graph_bs_decode`
- Статус: устаревший (`DeprecatedAliasStoreAction`), замена — `--cuda-graph-bs-decode`
- Этап применения: разбор CLI (предупреждение) → `_handle_cuda_graph_config` → `_handle_gpu_memory_settings` → `get_batch_sizes_to_capture` (фильтрация) → захват decode-графа

## Что меняет в движке

### Предупреждение и трансляция

```text
'--cuda-graph-bs' is deprecated and will be removed in a future release. Use '--cuda-graph-bs-decode' instead.
```

Печатается на разборе аргументов, до `logging.basicConfig`, поэтому стоит в начале вывода без временного префикса. Значение записывается прямо в `cuda_graph_bs_decode`.

### Что означает список

Каждое число — это batch size (число запросов в decode-шаге), под который захватывается отдельный CUDA graph. При выполнении реальный батч **дополняется вверх** до ближайшей захваченной формы, поэтому дырки в списке не ломают работу, а лишь добавляют лишние строки-заглушки в графе. Батч больше максимума списка идет eager-путем.

Автоматическая сетка, которую список замещает, выглядит так:

```python
[1, 2, 4, 8, 12] + list(range(16, 257, 8)) + list(range(272, 512, 16)) + list(range(512, max_bs + 1, 32))
```

то есть плотная у нуля и разреженная дальше. При включенном спекулятивном декодировании применяется более частая сетка (`1..8` с шагом 1, затем 2, 4, 8, 16), потому что там цена padding'а выше — каждый «пустой» слот тянет за собой `num_tokens_per_req` токенов проверки.

### Фильтрация после разбора

Заданный список — не окончательный. `get_batch_sizes_to_capture` еще раз проходит по нему:

- отбрасывает размеры, у которых `bs * alignment_width` не кратно выравниванию attention-TP;
- отбрасывает размеры больше `req_to_token_pool.size` (и добавляет сам предел, если весь список выше него);
- сортирует и убирает дубликаты;
- падает на `assert len(capture_bs) > 0 and capture_bs[0] > 0`, если после фильтрации ничего не осталось.

Итоговый список печатается в логе строкой `Capture target decode CUDA graph begin. backend=…, bs=[…]` — сверяться надо именно с ней, а не с тем, что было передано в командной строке.

## Значения и формат

- Перечисление через пробел: `--cuda-graph-bs-decode 1 2 4 8`. Запятые не поддерживаются.
- Порядок значения не имеет: список сортируется. Дубликаты убираются.
- Захват идет от большего к меньшему (`reversed(self.capture_bs)`) — так графы лучше переиспользуют один пул памяти.
- Список полностью замещает сетку: значения, которых в нем нет, не захватываются, даже если они меньше максимума.
- Обязательно включайте единицу, если сервер обслуживает одиночные запросы, — иначе самый частый случай будет дополняться до ближайшей большей формы, а при списке вроде `64 128` еще и считать 64 запроса вместо одного.
- В YAML-конфиге через `--config` ключ `cuda-graph-bs-decode` задать нельзя: он отвергается из-за этого устаревшего алиаса на том же `dest`. Обходной путь — `cuda-graph-config`.

## Когда использовать

- Не использовать: пишите `--cuda-graph-bs-decode`.
- Сам параметр (под новым именем) оправдан, когда конкурентность жестко ограничена извне. Квалифицированный профиль KTransformers в arriero (`docs/KTRANSFORMERS_OPERATIONS.md`) именно такой: конкурентность 2, графы захвачены под batch 1 и 2 — остальные формы не нужны.
- Оправдан и на тесной карте: три формы вместо двадцати четырех сокращают и старт, и `mem usage` захвата.
- Не задавать при переменной нагрузке: любое попадание вне списка либо дополняется вверх (лишняя работа), либо уходит в eager (потеря latency).

## Влияние на производительность и память

- VRAM: пропорционально числу форм. Оценочный резерв движка считается не по длине списка, а по потолку (`max_bs * 2` МиБ), поэтому короткий список с высоким максимумом даст завышенный резерв — но реальный расход будет меньше, и это видно в `mem usage` строки `Capture … end`.
- Время старта: линейно по числу форм; каждая форма — отдельный прогон захвата.
- Latency: батчи из списка идут по графу; остальные дополняются вверх или выполняются eager.
- Throughput: косвенно, через оставшуюся под KV-пул память.

## Взаимодействие с другими аргументами

- `--cuda-graph-bs-decode`: актуальное имя того же поля.
- `--cuda-graph-max-bs-decode`: при заданном списке перезаписывается значением `max(bs)`; задавать оба одновременно смысла нет.
- `--cuda-graph-bs-prefill`: аналог для prefill, но там числа означают количество токенов, а не запросов.
- `--disable-cuda-graph-padding`: при нем автоматическая сетка становится сплошной `1..max_bs`; на явно заданный список не влияет, но сама идея явного списка с этим флагом плохо сочетается.
- `--max-running-requests`: определяет максимум, который вообще может встретиться; значения списка выше него бесполезны.
- `--speculative-algorithm`: меняет генератор автоматической сетки и смысл padding'а (в графе резервируются токены проверки на каждый слот).
- `--cuda-graph-backend-decode disabled`: список перестает что-либо значить.

## Типовые проблемы и диагностика

- `'--cuda-graph-bs' is deprecated …` — замените на `--cuda-graph-bs-decode`.
- `AssertionError: capture_bs=[]` — после фильтрации по выравниванию и размеру пула запросов не осталось ни одной формы. Обычно это список из значений, некратных `attn_tp_size`, либо значения выше размера пула запросов.
- Указанные формы не совпадают с тем, что в логе, — сработала фильтрация. Смотрите `bs=[…]` в строке `Capture target decode CUDA graph begin`.
- `cuda graph: False` в строках decode-батчей — реальный батч выше максимума списка.
- Latency одиночных запросов внезапно выросла — в списке нет единицы, и одиночный запрос дополняется до ближайшей большей формы.
- OOM в ходе `Capturing batches (bs=…)` — слишком много форм или слишком большой максимум; сократите список.

## Примеры

Актуальная форма вместо этого флага:

```bash
python -m sglang.launch_server --model-path /models/Qwen3-30B-A3B --cuda-graph-bs-decode 1 2 4
```

Узкий профиль с согласованной конкурентностью:

```bash
python -m sglang.launch_server --model-path /models/Qwen3-30B-A3B --cuda-graph-bs-decode 1 2 --max-running-requests 2 --mem-fraction-static 0.85
```
