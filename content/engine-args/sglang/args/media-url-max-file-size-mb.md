# --media-url-max-file-size-mb

## Кратко

Когда клиент присылает медиа ссылкой, скачивает ее сервер — и без лимита один URL на многогигабайтный файл занял бы IO-поток, память и сеть на неограниченное время. `--media-url-max-file-size-mb` ставит потолок на объем одной такой загрузки. Проверка двухступенчатая: заявленный `Content-Length` сверяется до чтения тела, а затем тело читается потоково кусками по 64 КиБ со счетчиком — сервер, соврущий в заголовке или не приславший его, все равно будет оборван на лимите, и огромное тело никогда не окажется в памяти целиком.

## Оригинальная справка

```text
Maximum size in MiB for one client-supplied remote media download. The limit is enforced while streaming; set to 0 to disable it.
```

## Паспорт аргумента

- Флаги: `--media-url-max-file-size-mb`
- Группа: `mm`
- Тип значения: int, мебибайты
- Значение по умолчанию: `64`
- Эффективное значение: не переписывается; `_handle_media_url_security` в `__post_init__` публикует `значение × 1024 × 1024` байт как процессный лимит через `configure_media_url_security`, отрицательное значение отвергается там же
- Где объявлен: `ServerArgs.media_url_max_file_size_mb`, файл — `sglang/python/sglang/srt/server_args.py`
- Статус: обычный
- Этап применения: `__post_init__` (валидация) → публикация политики в tokenizer-процессах и на encoder-сервере EPD → каждая загрузка медиа по URL

## Что меняет в движке

Лимит применяется в `download_remote_media` (`sglang/python/sglang/srt/utils/common.py`) — единственной точке скачивания клиентских URL, общей для image, video и audio:

1. если ответ несет `Content-Length` и заявленный размер больше лимита — `ValueError: Remote media exceeds the N byte download limit` до чтения тела;
2. тело читается потоково (`stream=True`, куски 64 КиБ); как только накопленный объем плюс очередной кусок превышает лимит — та же ошибка, соединение закрывается.

Редиректы разворачиваются вручную (до 5 переходов, каждый адрес проверяется по `--allowed-media-domains`), и на всю загрузку действует общий дедлайн по времени — лимит объема и лимит времени работают одновременно. Ошибка входит в `CLIENT_MEDIA_EXCEPTIONS` и возвращается клиенту как ошибка его запроса, а не роняет сервер.

На base64, `data:`-URI и локальные файлы лимит не действует — он только про сетевые загрузки.

## Значения и формат

- Неотрицательное целое, МиБ. Отрицательное — `ValueError: media_url_max_file_size_mb must be non-negative` на старте.
- `0` — проверка полностью отключена (внутренний лимит в байтах становится ложным и обе ступени пропускаются).
- Лимит на **один объект**, не на запрос: запрос с восемью картинками может скачать до `8 × N` МиБ; суммарный аппетит запроса режут `--limit-mm-data-per-request` и `--mm-process-config`.

## Когда использовать

- Оставить дефолтные 64 МиБ почти всегда: обычные картинки — единицы МиБ, и дефолт останавливает только явные аномалии.
- Понижать (8–16 МиБ) на публичных серверах, где картинки — единственная ожидаемая модальность: меньше окно для мусорного трафика.
- Повышать осознанно для видео/аудио по URL: ролик длиной в минуты в 64 МиБ может не уложиться; поднимайте лимит вместе с `max_frames`/`fps` в `--mm-process-config`, а не вместо них.
- `0` — только в замкнутом контуре, где все источники медиа свои.

## Влияние на производительность и память

- RAM хоста: успешная загрузка буферизуется целиком (`bytearray`), так что лимит — это и потолок памяти на один скачиваемый объект до декодирования; пиковый расход тракта ограничен произведением `лимит × число одновременных загрузок` (`--mm-io-worker-num` × tokenizer-воркеры).
- Сеть: обрыв на лимите экономит трафик — тело не дочитывается.
- VRAM и скорость инференса: не затрагиваются.
- На принятые в лимит загрузки никакого замедления нет: подсчет байтов на кусках по 64 КиБ бесплатен на фоне самой сети.

## Взаимодействие с другими аргументами

- `--allowed-media-domains`: первая половина той же политики (кто); этот флаг — вторая (сколько). Публикуются одним вызовом `configure_media_url_security`.
- `--limit-mm-data-per-request`: ограничивает число элементов в запросе — вместе с этим флагом дает верхнюю границу сетевого объема запроса.
- `--mm-io-worker-num`: число одновременных загрузок, то есть множитель пикового расхода RAM под сырые тела.
- `--mm-process-config`: режет уже декодированный объем (пиксели, кадры); лимит этого флага срабатывает раньше, на байтах.
- `--trust-mm-content-hashes`: при горячем попадании в кеш по доверенному хешу загрузки нет вовсе — лимит не применяется за отсутствием скачивания.

## Типовые проблемы и диагностика

- Запрос падает с `Remote media exceeds the 67108864 byte download limit` — объект больше лимита; число в сообщении — лимит в байтах, а не размер объекта.
- Та же ошибка на файле, который «точно меньше» — проверьте, не считаете ли вы в мегабайтах: лимит мебибайтный, и сравните с фактическим `Content-Length`.
- `ValueError: media_url_max_file_size_mb must be non-negative` на старте — отрицательное значение.
- Timed out while downloading media URL — сработал не этот лимит, а общий дедлайн загрузки; большой файл может упереться во время раньше, чем в байты.
- Принятое значение видно в дампе `server_args=` (поле `media_url_max_file_size_mb`).

## Примеры

```bash
python -m sglang.launch_server --model-path /models/Qwen3-VL-8B-Instruct --allowed-media-domains cdn.example.com --media-url-max-file-size-mb 16
```

```bash
python -m sglang.launch_server --model-path /models/Qwen3-VL-8B-Instruct --media-url-max-file-size-mb 256 --mm-process-config '{"video":{"fps":2,"max_frames":32}}'
```
