# --debug-tensor-dump-layers

## Кратко

Фильтр для режима `--debug-tensor-dump-output-folder`: список номеров слоев, чьи модули получат forward-хуки. Всё, что не является прямым числовым потомком контейнера `model.layers`, — эмбеддинги, финальная норма, `lm_head` — хукуется независимо от этого списка. Без аргумента дампятся все слои, и объем файла умножается на их число, поэтому на практике задавать его нужно почти всегда: разбор численного расхождения обычно начинается с одного-двух слоев.

## Оригинальная справка

```text
The layer ids to dump. Dump all layers if not specified.
```

## Паспорт аргумента

- Флаги: `--debug-tensor-dump-layers`
- Группа: `observability`
- Тип значения: список int (`Optional[List[int]]`); argparse получает `nargs="+"`, `type=int` — значения через пробел
- Допустимые значения: `choices` нет; диапазон не проверяется. Номера, которых в модели нет, молча ни на что не влияют
- Значение по умолчанию: `null` — «все слои», о чем прямо сказано комментарием в объявлении поля
- Эффективное значение: совпадает с заданным; ни один `_handle_*` его не переписывает. Полностью инертен без `--debug-tensor-dump-output-folder`
- Где объявлен: `ServerArgs.debug_tensor_dump_layers`, файл — `sglang/python/sglang/srt/server_args.py`
- Статус: обычный, отладочный
- Этап применения: загрузка весов в model runner, регистрация хуков (`register_forward_hook_for_model`)

## Что меняет в движке

Значение доходит до `TensorDumper._add_hook_recursive` (`sglang/python/sglang/srt/debug_utils/tensor_dump_forward_hook.py`), где проверяется ровно одно условие:

```python
if self._dump_layers is not None and name.isdigit() and prefix == layers_prefix:
    if int(name) not in self._dump_layers:
        continue
```

`layers_prefix` собирается как `<верхнеуровневый модуль>.<контейнер слоев>` — по умолчанию `model.layers` (имена переопределяются переменными окружения `TENSOR_DUMP_TOP_LEVEL_MODULE_NAME` и `TENSOR_DUMP_LAYERS_MODULE_NAME`). Проверка применяется только к **прямым** числовым потомкам этого контейнера, то есть к `model.layers.0`, `model.layers.1` и так далее.

Из этого следуют две неочевидные вещи.

Во-первых, всё вне `model.layers` хукуется всегда: `model.embed_tokens`, `model.norm`, `lm_head`, а также верхнеуровневый модуль, чей хук и выполняет сброс файла. Поэтому даже с одним слоем в списке дамп не будет пустым.

Во-вторых, если у архитектуры слои лежат не под `model.layers` (другое имя контейнера, вложенность глубже), условие `prefix == layers_prefix` не выполнится ни разу и фильтр не сработает — будут захуканы все листовые модули. Проверяется это по строке лога `Dump …th pass to …` и по размеру получившегося файла.

Нумерация — глобальная по модели, как в именах модулей. При `--pp-size` больше единицы каждая стадия держит свой поддиапазон слоев, и в подкаталоге ранга появятся только те номера из списка, которые ему принадлежат.

## Значения и формат

- Разделитель — пробел: `--debug-tensor-dump-layers 0 1 31`. Запятая даст `invalid int value: '0,1'`.
- Порядок значений роли не играет — список используется как множество.
- Повторы допустимы и безвредны.
- Пустой список задать нельзя: `nargs="+"` требует хотя бы одного значения. «Не дампить ни одного слоя» выражается только отсутствием `--debug-tensor-dump-output-folder`.
- Отрицательные числа argparse примет, но `name.isdigit()` для имен модулей истинно только для неотрицательных, так что отрицательный номер просто ни с чем не совпадет. Индексации с конца здесь нет.
- Номер вне диапазона модели не вызывает ошибки — соответствующего модуля просто не существует.
- Изменить у работающего сервера нельзя.

## Когда использовать

- Всегда, когда включен `--debug-tensor-dump-output-folder`. Это не оптимизация, а условие применимости: без фильтра один prefill-проход большой модели дает файл на гигабайты.
- Бинарный поиск по слоям при расхождении численных результатов: сначала `0` и последний слой, дальше сужение. Каждый прогон — один короткий запрос.
- Первый и последний слой вместе с эмбеддингами (они попадают в дамп сами) — минимальный набор, по которому видно, вошла ли ошибка уже на входе или накопилась по глубине.
- Не задавать «на всякий случай» половину слоев: объем растет линейно, а полезной информации почти не добавляется.

## Влияние на производительность и память

- Прямо пропорционально уменьшает и объем файла, и число синхронизаций `tensor.cpu()` на проход — а именно они дают основное замедление режима дампа.
- VRAM: не затрагивает.
- RAM хоста: пиковое потребление равно размеру одного файла, то есть тоже падает пропорционально.
- Время старта: не влияет.
- На конфигурацию сервера не влияет вообще: принудительное отключение CUDA graph и warmup делает `--debug-tensor-dump-output-folder`, а не этот аргумент.

## Взаимодействие с другими аргументами

- `--debug-tensor-dump-output-folder`: обязательное условие. Без него список никуда не передается — хуки не регистрируются.
- `--debug-tensor-dump-input-file`: в этом checkout'е неприменим вместе с дампом (warmup, который его читает, отключается тем же аргументом дампа).
- `--pp-size`: слои распределены по стадиям; номера из списка появятся только в подкаталогах тех рангов, которым они принадлежат.
- `--tp-size`: каждый ранг пишет свой подкаталог с одними и теми же номерами слоев — объем умножается на число рангов.
- `--forward-hooks`: если нужен не «все модули выбранных слоев», а точечный набор модулей, гибче использовать его: там шаблоны `fnmatch` по полным именам.

## Типовые проблемы и диагностика

- `argument --debug-tensor-dump-layers: invalid int value: '0,1'` — список задан через запятую.
- Файл всё равно огромный, хотя задан один слой — фильтр не сработал: скорее всего слои лежат не под `model.layers`. Проверьте имена модулей архитектуры и при необходимости задайте `TENSOR_DUMP_LAYERS_MODULE_NAME`.
- В дампе есть ключи, которых нет в списке слоев (`model.embed_tokens`, `model.norm`, `lm_head`) — так и должно быть, фильтр их не касается.
- Указанного слоя в файле нет — либо номер вне диапазона модели, либо этот слой принадлежит другой PP-стадии; смотрите подкаталог соответствующего ранга.
- Файлов нет вовсе — проблема не в этом аргументе; см. диагностику `--debug-tensor-dump-output-folder`.
- **В arriero:** аргумент попадет в конфигурацию инстанса как список значений и будет передан в argv через `argparse-flags` (`apps/api/src/process/argv.ts`). Практически же оба аргумента дампа имеет смысл держать вне постоянной конфигурации инстанса и добавлять только на время разбора.

## Примеры

```bash
python -m sglang.launch_server --model-path /models/Qwen3-30B-A3B --debug-tensor-dump-output-folder /var/tmp/sglang-tensors --debug-tensor-dump-layers 0
```

```bash
python -m sglang.launch_server --model-path /models/Qwen3-30B-A3B --debug-tensor-dump-output-folder /var/tmp/sglang-tensors --debug-tensor-dump-layers 0 1 46 47
```
