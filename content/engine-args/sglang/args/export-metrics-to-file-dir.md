# --export-metrics-to-file-dir

## Кратко

Вторая половина файлового экспорта метрик: сам путь. Каталог создается рекурсивно при инициализации tokenizer-процесса, то есть при старте сервера, а не при первой записи — недоступный путь валит старт. Внутри появляется по одному файлу на каждый календарный час, в котором был хотя бы один завершенный запрос. Механизм записи и состав строки описаны в `--export-metrics-to-file`; здесь важно другое — за объем и очистку этого каталога движок не отвечает вообще.

## Оригинальная справка

```text
Directory path for writing performance metrics files (required when --export-metrics-to-file is enabled).
```

## Паспорт аргумента

- Флаги: `--export-metrics-to-file-dir`
- Группа: `observability`
- Тип значения: str — путь к каталогу
- Допустимые значения: `choices` нет; никакой проверки формата пути нет, единственная проверка — успешный `os.makedirs(..., exist_ok=True)`
- Значение по умолчанию: `null`
- Эффективное значение: совпадает с заданным; `__post_init__` его не переписывает, но проверяет непротиворечивость пары аргументов
- Где объявлен: `ServerArgs.export_metrics_to_file_dir`, файл — `sglang/python/sglang/srt/server_args.py`
- Статус: обычный
- Этап применения: `__post_init__` (проверка пары) → конструктор `FileRequestMetricsExporter` (создание каталога) → каждая запись

## Что меняет в движке

Значение читается ровно один раз, в конструкторе экспортера:

```python
self.export_dir = getattr(server_args, "export_metrics_to_file_dir")
os.makedirs(self.export_dir, exist_ok=True)
```

Дальше путь используется для сборки имени файла: `os.path.join(self.export_dir, f"sglang-request-metrics-{hour_suffix}.log")`, где `hour_suffix` — `YYYYMMDD_HH` по **локальному** времени. При смене часа предыдущий дескриптор закрывается, новый открывается на дозапись (`"a"`), поэтому перезапуск сервера в пределах того же часа продолжит существующий файл, а не перезапишет его.

Сам по себе, без `--export-metrics-to-file`, аргумент не делает ничего: экземпляр `FileRequestMetricsExporter` создается только когда включен парный флаг, а значит и каталог не создается.

Обратная зависимость жестче: `__post_init__` проверяет только «включен экспорт — задан каталог», но не «задан каталог — включен экспорт». Одинокий `--export-metrics-to-file-dir` молча игнорируется.

## Значения и формат

- Абсолютный или относительный путь; относительный разрешается от рабочего каталога процесса, что в системе с супервизором предсказуемо только при явном `WorkingDirectory`. Пишите абсолютный.
- Каталог создается рекурсивно (`makedirs`), промежуточные уровни делать заранее не нужно.
- Существующий каталог не очищается — старые файлы остаются, записи дописываются.
- Специальных значений (`auto`, пустая строка, `-`) нет. Пустая строка приведет к `FileNotFoundError` в `makedirs`.
- Символические ссылки допустимы; ZMQ и pickle здесь не участвуют, это обычная файловая запись.
- Изменить путь у работающего сервера нельзя.

## Когда использовать

- Всегда вместе с `--export-metrics-to-file` — это не опция, а обязательное дополнение.
- Выбирайте каталог на том же локальном диске, где живут логи: запись идет с `flush` на каждый запрос, и сетевая ФС превратит это в постоянный источник задержек в пуле потоков.
- Заводите отдельный каталог на инстанс: имя файла содержит только час, поэтому два сервера, пишущие в один каталог, будут дописывать в один и тот же файл вперемешку. Строки не перемешаются посимвольно (каждая пишется одним `json.dump` + `\n` под своим локом), но разделить потоки постфактум будет нечем — имени модели в записи нет.
- Не указывать каталог внутри `data/config/` arriero: конфиг там может быть под git (`docs/CONFIG_GIT.md`), а это машинные данные неограниченного объема.
- Не полагаться на то, что кто-то почистит: ставьте `logrotate` или `tmpfiles.d` на этот каталог сразу.

## Влияние на производительность и память

- VRAM и RAM: не затрагивает.
- Диск: рост неограничен. Один файл в час, в файле — по строке на завершенный запрос, размер строки определяется в первую очередь длиной промпта (по умолчанию он записывается целиком, см. `--export-metrics-to-file`). Порядок величины — сотни мегабайт в час на нагруженном сервере с длинными промптами.
- Latency: путь сам по себе ничего не стоит; стоимость — в характеристиках выбранного носителя, потому что после каждой записи вызывается `flush`.
- Время старта: один `makedirs`.

## Взаимодействие с другими аргументами

- `--export-metrics-to-file`: обязательная пара. Без него аргумент инертен; без аргумента он валит старт.
- `--log-requests-level`: определяет, попадет ли в файлы текст промпта, а значит — реальную скорость роста каталога.
- `--crash-dump-folder` и `--debug-tensor-dump-output-folder`: другие каталоги, куда движок пишет данные. Держите их раздельно: у них принципиально разный жизненный цикл (постоянный поток против одноразового дампа) и разный объем.
- `--served-model-name`: в имя файла и в запись не входит; при нескольких моделях разделение возможно только каталогами.

## Типовые проблемы и диагностика

- `ValueError: --export-metrics-to-file-dir is required when --export-metrics-to-file is enabled` — задан только флаг, без каталога.
- `PermissionError` / `FileNotFoundError` на старте — каталог недоступен на запись или путь пуст. Ошибка приходит из конструктора `TokenizerManager`, то есть до готовности HTTP.
- Каталог задан, но пуст — вероятнее всего забыт `--export-metrics-to-file`: одинокий каталог не проверяется и молча игнорируется. Проверьте `export_metrics_to_file=True` в дампе `server_args=` при старте.
- В логе `Failed to open log file …: No space left on device` при смене часа — диск заполнен; записи с этого момента теряются, сервер продолжает работать.
- Файлы «за сегодня» вдруг перестали появляться после полуночи по UTC, хотя трафик есть — час берется по локальному времени процесса; сверяйте `TZ`.
- **В arriero:** путь попадет в аргументы инстанса (`config/instances/<name>.json`) как обычная строка. Если каталог лежит под управляемым корнем (`ARRIERO_HOME`, `ARRIERO_DATA_DIR`, …), он будет сохранен как плейсхолдер `${ARRIERO_*}` и развернут при чтении — см. `docs/PORTABLE_PATHS.md`; на работу движка это не влияет, ему всегда передается абсолютный путь.

## Примеры

```bash
python -m sglang.launch_server --model-path /models/DeepSeek-V3 --export-metrics-to-file --export-metrics-to-file-dir /var/log/sglang/kt-dsv3-a
```

```bash
python -m sglang.launch_server --model-path /models/DeepSeek-V3 --export-metrics-to-file --export-metrics-to-file-dir /var/log/sglang/kt-dsv3-a --log-requests --log-requests-level 0
```
