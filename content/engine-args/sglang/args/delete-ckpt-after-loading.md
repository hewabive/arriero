# --delete-ckpt-after-loading

## Кратко

Флаг делает ровно одно: после успешного прогрева сервера вызывает `shutil.rmtree(server_args.model_path)`. Смысл — освободить диск в эфемерном окружении (контейнер, спот-инстанс, CI), где чекпоинт больше не нужен, потому что веса уже в VRAM. Никакого подтверждения, никакого «в корзину» — каталог исчезает. На хосте, где модель лежит в постоянном каталоге, это уничтожение данных.

## Оригинальная справка

```text
Delete the model checkpoint after loading the model.
```

## Паспорт аргумента

- Флаги: `--delete-ckpt-after-loading`
- Группа: `model`
- Тип значения: bool (флаг без значения)
- Допустимые значения: присутствует / отсутствует
- Значение по умолчанию: `false`
- Эффективное значение: не переопределяется
- Где объявлен: `ServerArgs.delete_ckpt_after_loading`, файл — `sglang/python/sglang/srt/server_args.py`
- Статус: обычный
- Этап применения: `_wait_and_warmup` в HTTP-слое — **после** строки «The server is fired up and ready to roll!»

## Что меняет в движке

Единственная точка использования — `sglang/python/sglang/srt/entrypoints/http_server.py`:

```python
if server_args.delete_ckpt_after_loading:
    delete_directory(server_args.model_path)
```

`delete_directory` (`sglang/python/sglang/srt/utils/common.py`) — это `shutil.rmtree` с проглатыванием `OSError`: при неудаче печатается предупреждение «Failed to delete directory %s: %s», и сервер продолжает работать.

Ключевые детали момента вызова:

- удаление происходит **после** ожидания весов (`--checkpoint-engine-wait-weights-before-ready`) и после прогрева, то есть когда сервер уже отвечает на запросы;
- удаляется значение `server_args.model_path` в том виде, в каком оно осталось после `__post_init__` — для ModelScope это уже локальный snapshot-каталог, для обычного HF repo ID это остается идентификатором репозитория, и `rmtree` по нему просто не сработает (предупреждение в лог);
- для GGUF `--model-path` — это файл, а `rmtree` работает с каталогами; удаления не произойдет, будет предупреждение.

## Значения и формат

- Флаг без значения; парной формы `--no-…` нет.
- Отменить действие после старта невозможно — оно уже произошло.
- Никаких проверок «а не системный ли это каталог» нет: путь передается в `rmtree` как есть.

## Когда использовать

- Одноразовый контейнер/под, где образ или volume с весами занимает место, критичное для остальной работы (например, тот же диск нужен под кеш префиксов на хосте или под артефакты).
- CI-прогон, в котором модель скачана специально для теста.
- **Не включайте** на постоянном сервере, на общем хранилище и вообще везде, где чекпоинт — единственная копия. Перезапуск инстанса после этого невозможен без повторного скачивания.
- Не используйте как способ «почистить кеш HF»: удаляется `--model-path`, а не `--download-dir`.

## Влияние на производительность и память

- На VRAM, throughput и latency не влияет.
- Освобождает дисковое место, равное размеру чекпоинта.
- Побочный эффект, о котором стоит помнить: удаление файлов инвалидирует page cache, в котором лежали веса. Всё, что читается с диска после старта (LoRA-адаптеры, токенайзер при перезагрузке, дамп presharded), уже не найдет исходных файлов.
- Любая операция, требующая повторного чтения весов — обновление весов с диска, перезапуск воркера — станет невозможной.

## Взаимодействие с другими аргументами

- `--model-path`: то, что будет удалено. Для repo ID и для GGUF-файла удаление фактически не срабатывает.
- `--download-dir`: не удаляется. Если модель скачана с HF, `model_path` остался repo ID и каталог кеша уцелеет.
- `--model-checksum`: проверка проходит до загрузки, поэтому конфликта нет; но повторно проверить уже нечего.
- `--skip-server-warmup`: удаление стоит после блока прогрева и выполняется в обоих случаях.
- `--load-format presharded`: дамп пошардованного чекпоинта делается при загрузке; если он лежит внутри `<model_path>/presharded`, он тоже будет удален — то есть весь смысл `presharded` пропадет.

## Типовые проблемы и диагностика

- «Failed to delete directory /models/…: Permission denied» — процесс не имеет прав на удаление; сервер продолжит работать.
- Каталог не удалился и предупреждения нет — `model_path` не является путем (repo ID) либо это файл, а не каталог.
- Перезапуск инстанса падает на чтении конфига — ровно ожидаемое последствие; восстанавливать чекпоинт придется заново.
- Факт включения виден в дампе `server_args=`; сам момент удаления в лог не пишется — только сообщение об ошибке при неудаче.

## Примеры

```bash
python -m sglang.launch_server --model-path /scratch/Qwen3-30B-A3B --delete-ckpt-after-loading --port 30000
```

```bash
python -m sglang.launch_server --model-path /scratch/Qwen3-30B-A3B --model-checksum /scratch/Qwen3-30B-A3B/checksums.json --delete-ckpt-after-loading
```
