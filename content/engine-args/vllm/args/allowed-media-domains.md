# --allowed-media-domains

## Кратко

Мультимодальный запрос может содержать URL, который сервер скачивает сам. Без ограничений это классический SSRF: клиент заставляет vLLM ходить во внутреннюю сеть, к метаданным облака (`169.254.169.254`) или на очень большой файл.

`--allowed-media-domains` задаёт список хостов; всё, что не совпадает точно с одним из них, отвергается до сетевого запроса. Проверяются только `http`/`https` URL — `data:` и `file:` идут другими путями.

## Оригинальная справка

```text
If set, only media URLs that belong to this domain can be used for
multi-modal inputs. 
```

## Паспорт аргумента

- Флаги: `--allowed-media-domains`
- Группа argparse: `ModelConfig`
- Тип значения: список строк (`nargs="+"`, значения через пробел)
- Допустимые значения: не ограничены; элемент сравнивается с `hostname` разобранного URL на точное равенство
- Значение по умолчанию: `None` — ограничения нет, разрешён любой хост
- Эффективное значение: `None` превращается в пустой список в конструкторе `MediaConnector`, что означает «не проверять»
- Где объявлен: `vllm/config/model.py:ModelConfig.allowed_media_domains`
- Этап применения: HTTP-слой, на каждый медиа-URL в запросе (а также в `vllm run-batch`)

## Что меняет в движке

Значение доходит до `MediaConnector` тем же путём, что и `--allowed-local-media-path`: `MultiModalItemTracker` → конструктор коннектора, который создаётся лениво при первом запросе с медиа.

Проверка — `MediaConnector._assert_url_in_allowed_media_domains(url_spec)`:

```
if self.allowed_media_domains and url_spec.hostname not in self.allowed_media_domains:
    raise ValueError(...)
```

Она вызывается в `load_from_url` и `load_from_url_async` **только** в ветке `url_spec.scheme.startswith("http")` — то есть до похода в сеть и до чтения медиа-кэша. Второе место — батч-раннер `vllm/entrypoints/openai/run_batch.py`, где тот же список применяется к `file_url` в запросах транскрипции/перевода.

Важные границы механизма:

- Сравнение по `hostname`, без учёта схемы, порта и пути. `example.com` разрешает и `http://example.com:8080/x`, и `https://example.com/y`.
- Никаких подстановочных символов и суффиксного сопоставления. `example.com` **не** разрешает `cdn.example.com` — субдомены перечисляются явно.
- IP-литерал в URL сравнивается как строка: `--allowed-media-domains 10.0.0.5` разрешает ровно этот адрес.
- Редиректы по умолчанию разрешены: `VLLM_MEDIA_URL_ALLOW_REDIRECTS` в `vllm/envs.py` имеет дефолт `1`. Разрешённый хост может отдать `302` на запрещённый, и загрузка пройдёт. Апстрим-документация по безопасности прямо советует `VLLM_MEDIA_URL_ALLOW_REDIRECTS=0` вместе с этим флагом.
- Обход DNS-rebinding флаг не закрывает: имя разрешается уже HTTP-клиентом, после проверки.

## Значения и формат

- Один или несколько хостов через пробел: `--allowed-media-domains upload.wikimedia.org github.com`.
- Пишется только хост, без схемы и без пути. `https://example.com/` в списке не совпадёт ни с чем: `hostname` разобранного URL — это `example.com`.
- Не задан ⇒ `None` ⇒ проверок нет. Это и есть небезопасный дефолт.
- Пустой список задать через CLI нельзя: `nargs="+"` требует хотя бы одно значение.
- Значение `None` (строка) парсер превращает в `None`-элемент списка, что не даёт осмысленного правила; не используйте.

## Когда использовать

- Всегда, если инстанс мультимодальный и доступен кому-то кроме вас. Это единственный дешёвый барьер против SSRF.
- Вместе с `VLLM_MEDIA_URL_ALLOW_REDIRECTS=0` — иначе список обходится одним редиректом.
- Если весь медиа-трафик у вас идёт `data:` URL (клиент отправляет base64), можно вообще не открывать HTTP-канал; тогда список нужен как страховка от того, что кто-то пришлёт URL.
- В arriero: инстанс vLLM стоит за прокси, но прокси проксирует тело запроса как есть, поэтому `image_url` доходит до движка нетронутым. Ограничение источников (`config/proxy/sources.json`) отвечает за то, кто может слать запросы, а этот флаг — за то, куда сервер пойдёт по их указанию. Одно другого не заменяет.

## Влияние на производительность и память

На VRAM, KV-cache и планировщик не влияет. Косвенный эффект — отсечённая загрузка не тратит сеть, хостовую RAM на декодирование и место в медиа-кэше; попытка скачать гигантский файл прекращается до сетевого запроса, а не после.

## Взаимодействие с другими аргументами

- `--allowed-local-media-path`: закрывает другой канал (файлы на диске сервера). Оба нужны независимо.
- `--limit-mm-per-prompt`: ограничивает число медиа-элементов в одном запросе — вместе с белым списком доменов это ограничение объёма и направления загрузок.
- `--media-io-kwargs`: параметры декодирования уже скачанного; на допуск URL не влияют.

## Типовые проблемы и диагностика

- **Симптом:** `ValueError: The URL must be from one of the allowed domains: ['upload.wikimedia.org']. Input URL domain: cdn.example.com` **Причина:** хост не в списке (частый случай — забытый субдомен CDN). **Лечение:** добавить конкретный хост; подстановок нет.
- **Симптом:** список задан, но запросы всё равно уходят на посторонний хост. **Причина:** разрешённый хост отдаёт редирект, а `VLLM_MEDIA_URL_ALLOW_REDIRECTS` по умолчанию `1`. **Лечение:** `VLLM_MEDIA_URL_ALLOW_REDIRECTS=0` в окружении инстанса.
- **Симптом:** ограничение не срабатывает на `data:`-запросах. **Причина:** штатное поведение — `data:` разбирается до проверки домена и не является сетевой загрузкой.
- **Симптом:** в батч-режиме (`vllm run-batch`) отклоняется `file_url`. **Причина:** тот же список применяется и там. **Лечение:** добавить хост либо запускать батч с иным списком.
- **Проверка принятого значения:** отдельной строки в логе нет. Проверяйте отрицательным тестом: запрос с заведомо запрещённым хостом должен вернуть ошибку с перечислением вашего списка — в тексте ошибки виден фактически применённый список.

## Примеры

```bash
vllm serve /models/Qwen2.5-VL-7B-Instruct --allowed-media-domains upload.wikimedia.org github.com
```

```bash
vllm serve /models/Qwen2.5-VL-7B-Instruct --allowed-media-domains cdn.internal.example.com --limit-mm-per-prompt '{"image": 4}'
```
