# --download-dir

## Кратко

`--download-dir` — это `cache_dir` для `huggingface_hub.snapshot_download`, а не «папка, куда положить файлы модели». Внутри создается стандартная структура кэша HF (`models--<org>--<name>/blobs|snapshots|refs`), а фактические файлы весов появляются как symlink'и на blob'ы. Копировать туда веса руками бессмысленно — для готового каталога с весами используется путь модели, а не этот аргумент.

Второе, менее очевидное назначение: тот же каталог служит местом файловых блокировок (`get_lock`). Если два процесса на хосте одновременно поднимают одну модель, они синхронизируются именно через этот каталог; при незаданном значении блокировки уходят в системный `tempfile.gettempdir()`.

## Оригинальная справка

```text
Directory to download and load the weights, default to the default
cache directory of Hugging Face.
```

## Паспорт аргумента

- Флаги: `--download-dir`
- Группа argparse: `LoadConfig`
- Тип значения: str (путь к каталогу), `optional: true`
- Допустимые значения: не ограничены; каталог создается при необходимости самим `huggingface_hub`
- Значение по умолчанию: `None` — кэш Hugging Face по умолчанию (`HF_HUB_CACHE`, иначе `HF_HOME/hub`, иначе `~/.cache/huggingface/hub`)
- Эффективное значение: не переопределяется движком
- Где объявлен: `vllm/config/load.py:LoadConfig.download_dir`
- Этап применения: подготовка весов (`_prepare_weights`) до загрузки модели, а также загрузка конфигураций квантизации и sparse attention

## Что меняет в движке

Значение доходит до нескольких мест `vllm/model_executor/model_loader/`:

- `DefaultModelLoader._prepare_weights` → `download_weights_from_hf(model, cache_dir=download_dir, ...)` и `download_safetensors_index_file_from_hf(..., cache_dir=download_dir, ...)`;
- `np_cache_weights_iterator(model, cache_dir, ...)` — как каталог блокировки при формировании numpy-кэша;
- `get_quant_config` и `get_sparse_attention_config` (`weight_utils.py`) — как `cache_dir` для скачивания `*.json` квантизации;
- `RunaiModelStreamerLoader` и `ShardedStateLoader` — тем же способом;
- `get_lock(model, cache_dir)` — файловая блокировка `sha256(имя)+имя.lock` с правами `0o666`.

Чего аргумент **не** покрывает:

- скачивание `config.json` и файлов токенизатора через `transformers`/`AutoConfig` — они идут в стандартный кэш HF, потому что `cache_dir` туда не передается;
- `maybe_download_from_modelscope` внутри `_prepare_weights` вызывается без `download_dir` (в отличие от `get_quant_config`), поэтому при `VLLM_USE_MODELSCOPE=1` веса лягут в кэш ModelScope по умолчанию;
- локальную модель: если `os.path.isdir(model)` истинно, никакой загрузки нет и каталог не используется вовсе.

## Значения и формат

- Абсолютный путь предпочтителен: относительный будет разрешен от рабочего каталога процесса движка, который в управляемом запуске задан не вами.
- Каталог должен быть доступен на запись пользователю, от которого работает процесс.
- Специальных значений (`auto`, пустая строка) нет; «не задан» означает кэш HF по умолчанию.
- Аргумент не влияет на то, **что** скачивается, — за это отвечают `--load-format`, `--ignore-patterns` и `--revision`.

## Когда использовать

- Веса нужно держать на отдельном томе (быстрый NVMe, большой HDD), а системный `~/.cache` мал.
- Несколько инстансов должны разделять один кэш весов: общий `--download-dir` дает и переиспользование blob'ов, и корректную сериализацию параллельных загрузок через файловые блокировки.
- Не используйте, если модель задана локальным путем: в arriero это основной сценарий (`docs/VLLM_OPERATIONS.md` требует существующий читаемый путь либо repo id), и при локальном пути аргумент ничего не делает.
- Не используйте как способ «положить модель в конкретную папку в человекочитаемом виде» — layout будет кэшем HF, а не каталогом модели. Для этого выкачивайте репозиторий отдельным инструментом в обычный каталог и передавайте движку путь через `--model`.

## Влияние на производительность и память

- **Время старта.** Решающее при первом (холодном) старте: если модели в кэше нет, старт растягивается на время скачивания. Строка `Time spent downloading weights for <model>: X.XXXXXX seconds` печатается, если загрузка заняла больше 0.5 с.
- **Диск.** Полный размер весов в выбранном каталоге; при смене значения старый кэш не переносится и не удаляется — легко получить две копии.
- **VRAM.** Не влияет.
- **Скорость чтения.** Косвенно: расположение каталога определяет тип файловой системы, а он влияет на выбор стратегии загрузки safetensors (`--safetensors-load-strategy` при `None` включает prefetch только на NFS/Lustre).
- **RAM хоста.** Не влияет напрямую.

## Взаимодействие с другими аргументами

- `--model`: аргумент имеет смысл только когда модель задана Hugging Face repo id. Локальный путь отключает весь путь загрузки.
- `--revision`: определяет, какой snapshot окажется в кэше; разные ревизии сосуществуют в одном каталоге.
- `--load-format`: определяет набор скачиваемых файлов (`*.safetensors`, `*.bin`, `consolidated*.safetensors` и т. д.); `dummy` не скачивает веса вовсе.
- `--ignore-patterns`: исключает файлы из загрузки в этот каталог.
- `--hf-token`: нужен для приватных и gated-репозиториев; без него загрузка в указанный каталог упадет на 401/403.
- `--tokenizer`, `--config-format`: файлы токенизатора и конфигурации идут в стандартный кэш HF, а не сюда.
- `--model-loader-extra-config`: для `runai_streamer` источником может быть объектное хранилище, и тогда локальный каталог загрузки не участвует.

## Типовые проблемы и диагностика

- **Симптом:** место кончилось на системном разделе при первом старте. **Причина:** кэш по умолчанию в `~/.cache/huggingface`. **Лечение:** задать `--download-dir` на нужном томе (либо выставить `HF_HOME`/`HF_HUB_CACHE` в окружении инстанса).
- **Симптом:** каталог задан, но веса все равно оказались в `~/.cache/huggingface`. **Причина:** там лежат конфигурация и токенизатор — они скачиваются через `transformers` и этот аргумент не читают. **Проверка:** сравните размер содержимого; веса — это гигабайты в `blobs/`.
- **Симптом:** старт зависает без вывода. **Причина:** ожидание файловой блокировки, которую держит другой процесс, качающий ту же модель в тот же каталог. **Проверка:** файлы `*.lock` в каталоге загрузки.
- **Симптом:** `Cannot find any model weights with <model>` после смены каталога. **Причина:** офлайн-режим (`HF_HUB_OFFLINE=1`) при пустом новом кэше. **Лечение:** снять офлайн-режим или прогреть кэш.
- **Симптом (arriero):** аргумент задан, а поведение не меняется. **Причина:** модель инстанса задана локальным путем; preflight требует существующий читаемый путь, и загрузка не выполняется. **Лечение:** ничего — аргумент здесь лишний.

## Примеры

```bash
vllm serve Qwen/Qwen3-4B --download-dir /data/hf-cache --gpu-memory-utilization 0.85
```

```bash
vllm serve Qwen/Qwen3-4B --download-dir /data/hf-cache --revision main --ignore-patterns "original/**/*" "*.pth"
```
