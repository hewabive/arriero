# --enable-log-deltas

## Кратко

Флаг имеет смысл только вместе с `--enable-log-outputs`. Он решает, писать ли в лог каждую потоковую дельту отдельной строкой. Значение по умолчанию — `true`, поэтому включение логирования ответов в потоковом режиме сразу дает поток записей на каждый фрагмент генерации.

Отрицательная форма `--no-enable-log-deltas` оставляет только итоговую строку с полным текстом ответа — обычно это и нужно.

## Оригинальная справка

```text
If set to False, output deltas will not be logged. Relevant only if 
--enable-log-outputs is set.
```

## Паспорт аргумента

- Флаги: `--enable-log-deltas`, `--no-enable-log-deltas`
- Группа argparse: `Frontend`
- Тип значения: bool (`argparse.BooleanOptionalAction`)
- Допустимые значения: флаг без значения либо парная отрицательная форма
- Значение по умолчанию: `true` — редкий случай в этой группе, когда дефолт «включено»
- Эффективное значение: не переопределяется, но бездействует без `--enable-log-outputs` (проверка в коде — `if self.enable_log_outputs and self.request_logger:` и только внутри нее `if delta_content_parts and self.enable_log_deltas:`)
- Где объявлен: `vllm/entrypoints/openai/cli_args.py:BaseFrontendArgs.enable_log_deltas`
- Этап применения: HTTP-слой, потоковая ветка Chat Completions

## Что меняет в движке

В потоковой генерации на каждую дельту собирается строка из доступных частей: текст (`delta.content`), рассуждения в виде `[reasoning: ...]` и аргументы вызовов инструментов в виде `[tool_calls: ...]`. Если получившаяся строка непуста и флаг включен, вызывается `log_outputs(..., is_streaming=True, delta=True)` и в лог уходит запись с пометкой `(streaming delta)`.

Что **не** отключается этим флагом:

- итоговая строка потокового ответа с полным собранным текстом и `finish_reason: streaming_complete` — она пишется всегда при включенном `--enable-log-outputs`;
- логирование непотоковых ответов;
- логирование запросов (`--enable-log-requests`).

Значение прокидывается в обслуживающий класс чата (`enable_log_deltas=args.enable_log_deltas`) при инициализации состояния приложения.

## Значения и формат

- Не задан — `true`, дельты логируются.
- `--no-enable-log-deltas` — оставить только итоговые строки.
- `--enable-log-deltas` — явно включить (например, чтобы перебить значение из YAML в `--config`).
- Длина каждой записи ограничивается общим `--max-log-len`.

## Когда использовать

- `--no-enable-log-deltas` — стандартный выбор, если логирование ответов вообще нужно: итоговой строки достаточно, а объем записи падает на порядки.
- Оставлять дельты включенными стоит только при отладке потокового формата: порядка фрагментов, границ рассуждений, сборки аргументов инструментов.
- На управляемом инстансе arriero включенные дельты вредны вдвойне: они пишутся в файл лога в `runtime/logs/`, а разбор лога считает ошибкой строку с текстом вроде `Traceback` или `Exception`, пришедшую из самой генерации.

## Влияние на производительность и память

Основной эффект — ввод-вывод и размер файла лога: одна строка на дельту при потоковой генерации означает запись почти на каждый токен, умноженную на число одновременных запросов. На VRAM и на скорость генерации влияния нет, но при конкурентной нагрузке запись в лог может стать заметной.

## Взаимодействие с другими аргументами

- `--enable-log-outputs`: обязательное условие; без него флаг не проверяется.
- `--enable-log-requests`: требуется для `--enable-log-outputs`, то есть косвенно и для этого флага.
- `--max-log-len`: обрезает каждую строку дельты.

## Типовые проблемы и диагностика

- **Симптом:** `--no-enable-log-deltas` задан, а строки `Generated response ... (streaming complete)` остались. **Причина:** итоговая строка не управляется этим флагом. **Лечение:** отключить `--enable-log-outputs`.
- **Симптом:** флаг не дает никакого эффекта. **Причина:** логирование ответов не включено. **Проверка:** наличие строк `Generated response ...` в логе.
- **Симптом:** лог растет линейно по числу сгенерированных токенов. **Причина:** дельты включены по умолчанию. **Лечение:** `--no-enable-log-deltas`.

## Примеры

```bash
vllm serve /models/Qwen3-4B --host 127.0.0.1 --enable-log-requests --enable-log-outputs --no-enable-log-deltas
```

```bash
vllm serve /models/Qwen3-4B --host 127.0.0.1 --enable-log-requests --enable-log-outputs --enable-log-deltas --max-log-len 80
```
