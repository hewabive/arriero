# --sleep-preserve-parameter-names

## Кратко

Level-2 sleep освобождает VRAM вместе с весами, и после пробуждения веса приходится загружать или присылать заново. Если тренер обновляет только часть модели (например, LoRA-подобные или верхние слои), остальные веса заморожены, и пересылать их на каждом цикле бессмысленно. Флаг перечисляет, какие параметры перед level-2 sleep скопировать в хостовую RAM и вернуть на место при пробуждении весов.

Это ручка RL-цикла поверх sleep mode. Без `--enable-sleep-mode` и без level-2 sleep флаг ничего не делает.

## Оригинальная справка

```text
Parameter-name globs to preserve across level-2 sleep.
The sender must omit these parameters; loaders must preserve their storage.
```

## Паспорт аргумента

- Флаги: `--sleep-preserve-parameter-names`
- Группа argparse: `ModelConfig`
- Тип значения: список строк (`nargs="+"`, значения через пробел)
- Допустимые значения: glob-шаблоны `fnmatch` по runtime-именам из `model.named_parameters()`; каждый шаблон обязан совпасть хотя бы с одним параметром
- Значение по умолчанию: `field(default_factory=list)` — пустой список, ничего не сохраняется
- Эффективное значение: не переопределяется. Связь с `--enable-sleep-mode` при старте не проверяется; шаблоны проверяются только в момент первого level-2 sleep
- Где объявлен: `vllm/config/model.py:ModelConfig.sleep_preserve_parameter_names`
- Этап применения: runtime, по вызову sleep level 2 (`Worker.sleep`) и wake up с тегом `weights` (`Worker.wake_up`)

## Что меняет в движке

**Sleep level 2.** `Worker.sleep(level=2)` перед освобождением памяти вызывает `_save_sleep_parameters(model)`:

1. берет `dict(model.named_parameters())` целевой модели;
2. для каждого шаблона выполняет `fnmatch.filter`; если совпадений нет, поднимается `ValueError("No parameter matches sleep retention: <шаблон>")`;
3. все совпавшие параметры, которые лежат не на CPU, копируются `param.detach().to("cpu")` в обычную (pageable) хостовую память.

Параметры, уже находящиеся на CPU, не копируются. Буферы модели (`named_buffers()`) и черновой модели сохраняются при level 2 всегда, независимо от этого флага.

**Wake up.** При `wake_up()` без тегов или с тегом `weights`, после того как sleep-backend вернул память, `_restore_sleep_parameters` делает `model.get_parameter(name).copy_(value)` для каждого сохраненного параметра и освобождает копии. Восстановление идет **в существующее хранилище** параметра, поэтому код загрузки весов не должен заменять эти тензоры новыми объектами или meta-тензорами.

**Чего флаг не делает.** Он не фильтрует обновление весов: если тренер пришлет сохраненный параметр через weight transfer, новое значение перезапишет восстановленное. Отсюда требование справки: отправитель должен исключить эти параметры из обновления. Флаг действует только на целевую модель, параметры черновой модели спекулятивной генерации не сохраняются. На level 1 поведение не меняется: там все веса и так уходят в хост.

## Значения и формат

- Несколько шаблонов через пробел: `--sleep-preserve-parameter-names 'model.embed_tokens.*' 'lm_head.*'`.
- Шаблоны берите в одинарные кавычки, иначе shell раскроет `*` по файлам текущего каталога.
- Имена — runtime-имена vLLM после слияния слоев (например, `qkv_proj`, `gate_up_proj`), а не имена тензоров в checkpoint'е; `requires_grad` не учитывается. Список имен проще всего снять в offline-режиме: `LLM.collective_rpc` принимает callable, который получает worker как `self` и может вернуть `[n for n, _ in self.model_runner.model.named_parameters()]`.
- `fnmatch` поддерживает `*`, `?`, `[...]`; на Linux сравнение регистрозависимое.
- Пустой список (по умолчанию) — ничего не сохраняется.

## Когда использовать

- RLHF/RL-цикл с level-2 sleep между фазами, где обучаемая часть меньше всей модели: замороженные эмбеддинги, vision-tower, часть слоев. Экономится пересылка и загрузка этих весов на каждом цикле.
- Тренер, который сам решает, какие тензоры отправлять, и может гарантированно исключить сохраненные.
- Не используйте, если обновляется вся модель: копия в RAM будет перезаписана и только потратит время и память.
- Не используйте на управляемом сервере arriero как замену перезапуску: sleep-эндпоинты доступны только с `VLLM_SERVER_DEV_MODE=1`, а учет ресурсов arriero сна не видит (см. `--enable-sleep-mode`).

## Влияние на производительность и память

- **Хостовая RAM.** На время сна занимает размер всех совпавших GPU-параметров. При TP каждый ранг копирует только свой шард. Память pageable, не pinned.
- **Время усыпления и пробуждения.** Растет на D2H-копию при sleep и H2D-копию при wake up совпавших параметров. По сравнению с повторной пересылкой тех же весов через weight transfer обычно быстрее.
- **VRAM.** Во сне не меняется: память параметров освобождается вместе с остальными весами.
- **Работа в бодрствующем состоянии.** Не влияет.

## Взаимодействие с другими аргументами

- `--enable-sleep-mode`: обязательное условие; без него level-2 sleep недоступен и флаг инертен.
- `--weight-transfer-config`: типичный канал, по которому после пробуждения приходят обновленные веса. Отправитель должен исключить сохраненные параметры, а финальная обработка после загрузки — не трогать их значения и хранилище.
- `--enable-cumem-allocator`: включается sleep mode на CUDA/ROCm; на нем держится то, что после пробуждения параметры остаются по тем же адресам и `copy_` восстанавливает их на месте.

## Типовые проблемы и диагностика

- **Симптом:** `ValueError: No parameter matches sleep retention: <шаблон>` при первом `POST /sleep?level=2`. **Причина:** шаблон написан по имени из checkpoint'а, а не по runtime-имени, или опечатка. **Лечение:** сверить с `named_parameters()` и перезапустить с исправленным шаблоном; при старте ошибка не видна.
- **Симптом:** после цикла обновления замороженные веса оказались испорчены. **Причина:** тренер прислал эти параметры, или постобработка загрузки заменила их тензоры. **Проверка:** список отправляемых имен на стороне тренера. **Лечение:** исключить их из отправки.
- **Симптом:** хост ушел в своп при усыплении. **Причина:** шаблоны захватили слишком много весов. **Лечение:** сузить шаблоны.
- **Подтверждение принятого значения:** строка `non-default args: {...}` при старте содержит `sleep_preserve_parameter_names`; при усыплении `Sleep mode freed X GiB memory, Y GiB memory is still in use.`

## Примеры

```bash
VLLM_SERVER_DEV_MODE=1 vllm serve /models/Qwen3-4B --enable-sleep-mode --sleep-preserve-parameter-names 'model.embed_tokens.*' 'lm_head.*'
```

```bash
VLLM_SERVER_DEV_MODE=1 vllm serve /models/Qwen3-4B --enable-sleep-mode --weight-transfer-config '{"backend":"nccl"}' --sleep-preserve-parameter-names 'model.layers.[0-9].*'
```
