# --override-attention-dtype

## Кратко

`--override-attention-dtype` появился как способ задать dtype внимания на ROCm отдельно от `--kv-cache-dtype`. В стабильном релизе v0.27.1 значение доходит до `ModelConfig.override_attention_dtype` и на этом останавливается — потребителя у поля нет.

Практический вывод: аргумент задавать не нужно. Если он у вас в конфигурации инстанса — это скорее всего унаследованная строка, которая ничего не делает.

## Оригинальная справка

```text
Override dtype for attention
```

## Паспорт аргумента

- Флаги: `--override-attention-dtype`
- Группа argparse: `ModelConfig`
- Тип значения: str или `None`
- Допустимые значения: не ограничены; валидации нет — движок не проверяет, что строка вообще похожа на имя dtype
- Значение по умолчанию: `None`
- Эффективное значение: не переопределяется и не используется. Единственная реакция движка — `warnings.warn("override-attention-dtype is set but not using ROCm platform")` в `ModelConfig.__post_init__`, если значение задано и платформа не ROCm
- Где объявлен: `vllm/config/model.py:ModelConfig.override_attention_dtype`
- Этап применения: сборка `ModelConfig` (только предупреждение)

## Что меняет в движке

В v0.27.1 — ничего. Полный поиск по дереву исходников дает шесть точек: объявление поля в `ModelConfig`, предупреждение в `ModelConfig.__post_init__`, упоминание в списке `ignored_factors` хеша конфигурации (`compute_hash`), поле в `EngineArgs`, регистрация флага в `add_cli_args` и проброс в `create_engine_config()`. Ни один backend внимания, ни один worker и ни один слой значение не читают.

Последним потребителем был V0-бэкенд ROCm flash-attention, который сравнивал `get_current_vllm_config().model_config.override_attention_dtype` при выборе типа данных. Он удален вместе со всеми V0-бэкендами внимания в commit'е `bc6e542d9` («Remove V0 attention backends», upstream PR #25351). Сам аргумент при этом остался.

Поле входит в список факторов, **исключенных** из хеша вычислительного графа, — то есть его значение не влияет и на инвалидацию кеша компиляции.

## Значения и формат

- Любая строка проходит парсер без проверок.
- `None` (не задан) — нормальное состояние.
- Специальных значений нет; `auto` здесь не имеет смысла, потому что значение вообще не интерпретируется.

## Когда использовать

Не использовать. В текущем checkout'е аргумент не меняет поведение движка. Если требуется управлять точностью внимания:

- формат хранения KV задается `--kv-cache-dtype`;
- dtype весов и активаций — `--dtype`;
- конкретная реализация внимания (а с ней и поддерживаемые форматы) — `--attention-backend`.

Аргумент помечен в справке одной строкой без пояснений и, судя по истории, находится в состоянии «объявлен, но не подключен». Контракт может измениться без предупреждения — проверяйте наличие и поведение в своей сборке: `vllm serve --help` покажет флаг, но факт его использования проверяется только по исходникам установленной версии.

## Влияние на производительность и память

Не влияет ни на что, кроме одной строки предупреждения в логе старта на не-ROCm платформе.

## Взаимодействие с другими аргументами

- `--kv-cache-dtype`: реальная ручка формата KV-cache; исторически именно ее «триггер» этот аргумент и должен был заменить на ROCm.
- `--dtype`: dtype весов и активаций.
- `--attention-backend`: выбор бэкенда, который и определяет, в каком типе выполняется внимание.
- `--model`: архитектура и конфиг модели определяют, какие бэкенды вообще применимы.

## Типовые проблемы и диагностика

- **Симптом:** предупреждение `override-attention-dtype is set but not using ROCm platform` при старте на CUDA. **Причина:** аргумент задан, платформа не ROCm. **Лечение:** убрать аргумент.
- **Симптом:** аргумент задан на ROCm, предупреждения нет, но поведение не изменилось. **Причина:** значение не читается ни одним бэкендом в этой версии. **Проверка:** поиск `override_attention_dtype` по исходникам установленной версии — если совпадения только в `config/model.py` и `engine/arg_utils.py`, потребителя нет.
- **Симптом:** ожидался отказ на бессмысленном значении. **Причина:** валидации нет вовсе. **Лечение:** не полагаться на этот аргумент как на проверяемую настройку.

## Примеры

```bash
vllm serve /models/Qwen3-4B --kv-cache-dtype fp8 --gpu-memory-utilization 0.85
```

```bash
vllm serve /models/Qwen3-4B --override-attention-dtype bfloat16 --gpu-memory-utilization 0.85
```
