# --kv-events-config

## Кратко

`--kv-events-config` заполняет `KVEventsConfig` (`vllm/config/kv_events.py`). Он включает поток событий о блоках префикс-кэша: `BlockStored`, `BlockRemoved`, `AllBlocksCleared`. События формируются в `BlockPool` и публикуются отдельным потоком через ZeroMQ PUB-сокет, с опциональным ROUTER-эндпоинтом для повтора пропущенных пакетов.

Потребитель у этого потока один осмысленный — внешний балансировщик, который держит карту «какой префикс на каком инстансе» и направляет запрос туда, где кэш уже прогрет. На одиночном сервере включать нечего: события просто уходят в сокет, который никто не читает.

## Оригинальная справка

```text
The configurations for event publishing.
```

## Паспорт аргумента

- Флаги: `--kv-events-config`
- Группа argparse: `VllmConfig`
- Тип значения: JSON-объект (либо точечные под-флаги `--kv-events-config.<поле> <значение>`)
- Допустимые значения: поля `KVEventsConfig`; `publisher` — `null` или `zmq`
- Значение по умолчанию: `None` — публикация выключена
- Эффективное значение: `KVEventsConfig.__post_init__` доопределяет `publisher`: он объявлен со значением `None`, и при `enable_kv_cache_events: true` становится `zmq`, иначе `null`. При data-parallel порт эндпоинта смещается на индекс DP-ранга (`offset_endpoint_port`), чтобы ранги не дрались за один порт
- Где объявлен: `vllm/config/vllm.py:VllmConfig.kv_events_config`
- Этап применения: разбор CLI → инициализация планировщика (`EventPublisherFactory.create`) → каждый шаг планировщика, когда блоки кэшируются или вытесняются

## Что меняет в движке

| Ключ | По умолчанию | Что делает |
| --- | --- | --- |
| `enable_kv_cache_events` | `false` | главный переключатель. Пока `false`, `BlockPool` даже не накапливает события |
| `publisher` | `None` → `zmq`/`null` | транспорт публикации |
| `endpoint` | `"tcp://*:5557"` | PUB-адрес. `tcp://*:5557` означает bind на **все интерфейсы**; `tcp://host:5557` — connect к чужому сокету |
| `replay_endpoint` | `None` | ROUTER-адрес для повтора: подписчик присылает начальный порядковый номер восьмибайтовым big-endian числом и получает пропущенные пакеты |
| `buffer_steps` | `10000` | сколько последних пакетов хранить для повтора |
| `hwm` | `100000` | ZeroMQ high water mark для PUB-сокета: после стольких очередей события начинают отбрасываться, если потребитель не успевает |
| `max_queue_size` | `100000` | максимум событий во внутренней очереди перед публикацией |
| `topic` | `""` | тема для подписки |

`EventPublisherFactory.create()` возвращает `NullEventPublisher`, если конфиг `None`, если `enable_kv_cache_events` равен `false` или если `publisher` равен `null` — то есть задать конфиг и забыть включить флаг равносильно отсутствию конфига.

События `BlockStored` появляются только при кэшировании полных блоков, а оно происходит лишь при включенном prefix caching. Без `--enable-prefix-caching` поток вырождается.

## Значения и формат

- Обе формы: `--kv-events-config '{"enable_kv_cache_events":true,"endpoint":"tcp://127.0.0.1:5557"}'` и `--kv-events-config.enable_kv_cache_events true`. Точечные под-флаги должны использовать одно написание флага и не смешиваться с полной JSON-строкой.
- Значение валидируется на разборе CLI как датакласс.
- Адреса — обычные ZeroMQ-строки. `*` в хосте означает bind, конкретный адрес — connect.
- `buffer_steps: 0` фактически отключает повтор; `replay_endpoint: null` — тоже.
- Специальных значений вроде `auto` нет.

## Когда использовать

- **Внешний prefix-aware роутер поверх нескольких инстансов.** Единственный сценарий, ради которого это существует: балансировщику нужно знать, где лежит горячий префикс.
- **Отладка поведения префикс-кэша**, когда счетчиков `/metrics` недостаточно и нужен пофактный поток.
- **Не включайте на одиночном инстансе** — это чистые накладные расходы и открытый порт.
- **Не оставляйте `endpoint` со звездочкой на машине с внешним сетевым доступом.** По умолчанию сокет биндится на все интерфейсы и не имеет никакой аутентификации; содержимое событий раскрывает структуру кэша, а при `replay_endpoint` еще и позволяет вытянуть историю. Указывайте конкретный адрес (`tcp://127.0.0.1:5557`) либо закрывайте порт межсетевым экраном.

## Влияние на производительность и память

- **VRAM.** Нет.
- **RAM хоста.** Буфер повтора `buffer_steps` пакетов плюс очередь `max_queue_size` событий; при значениях по умолчанию это десятки мегабайт, а не гигабайты, но при большом `buffer_steps` расход растет линейно.
- **CPU.** Публикация вынесена в отдельный поток, но сериализация событий выполняется в тракте планировщика.
- **Throughput.** При медленном потребителе события отбрасываются по достижении `hwm`, а не блокируют движок — это осознанное решение апстрима: поток событий ненадежен по построению, и потребитель обязан уметь пережить пропуск (для этого и существует `replay_endpoint`).
- **Время старта.** Создание сокетов, миллисекунды.

## Взаимодействие с другими аргументами

- `--enable-prefix-caching`: без него события о сохранении блоков не генерируются.
- `--kv-transfer-config`: коннекторы выгрузки (`OffloadingConnector`, tiering-специи, Mooncake) публикуют собственные события в этот же поток, но только если он включен глобально здесь.
- `--kv-offloading-size`: включает выгрузку, чьи события тоже опираются на этот конфиг.
- `--data-parallel-size`: при значении больше 1 порт эндпоинта автоматически смещается на индекс ранга.
- `--block-size`: гранулярность событий совпадает с размером блока KV-cache.
- `--host`: не управляет ZeroMQ-сокетом — адрес публикации задается только здесь.

## Типовые проблемы и диагностика

- **Симптом:** конфиг задан, но событий нет. **Причина:** `enable_kv_cache_events` остался `false`, поэтому фабрика вернула `NullEventPublisher`. **Лечение:** включить флаг.
- **Симптом:** событий нет при включенном флаге. **Причина:** выключен prefix caching. **Лечение:** `--enable-prefix-caching`.
- **Симптом:** потребитель видит разрывы в нумерации. **Причина:** достигнут `hwm` или `max_queue_size`. **Лечение:** ускорить потребителя, поднять лимиты либо использовать `replay_endpoint`.
- **Симптом:** при data-parallel часть рангов не публикует события на ожидаемый порт. **Причина:** порт смещен на индекс ранга. **Лечение:** подписываться на диапазон портов.
- **Симптом:** порт занят при старте второго инстанса на той же машине. **Причина:** оба биндят `tcp://*:5557`. **Лечение:** задать разные порты явно.
- **Подтверждение принятого значения:** появление подписчика на заданном адресе; в логе движка отдельной строки о запуске publisher'а нет, отсутствие ошибки при старте — единственный сигнал.

## Примеры

```bash
vllm serve /models/Qwen3-4B --kv-events-config '{"enable_kv_cache_events":true,"endpoint":"tcp://127.0.0.1:5557","topic":"kv"}' --enable-prefix-caching
```

```bash
vllm serve /models/Qwen3-4B --kv-events-config.enable_kv_cache_events true --kv-events-config.replay_endpoint tcp://127.0.0.1:5558 --kv-events-config.buffer_steps 2000
```
