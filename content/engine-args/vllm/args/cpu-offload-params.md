# --cpu-offload-params

## Кратко

`--cpu-offload-params` управляет тем, **какие именно** параметры попадают под UVA-выгрузку. Пустое значение (дефолт) означает «любые, подряд, пока не исчерпан бюджет `--cpu-offload-gb`»; это почти всегда плохой выбор, потому что выгрузка начинается с первых слоев и без разбора хватает всё — от матриц внимания до нормализаций.

Практический смысл аргумента — выгружать только те тензоры, у которых объем большой, а частота обращения относительно низкая: веса экспертов MoE. Внимание, эмбеддинги и мелкие масштабирующие коэффициенты имеет смысл оставить на карте.

Аргумент не включает выгрузку сам по себе: без ненулевого `--cpu-offload-gb` он не делает ничего.

## Оригинальная справка

```text
The set of parameter name segments to target for CPU offloading.
Unmatched parameters are not offloaded. If this set is empty, parameters
are offloaded non-selectively until the memory limit defined by
`cpu_offload_gb` is reached.
Examples:
    - For parameter name "mlp.experts.w2_weight":
        - "experts" or "experts.w2_weight" will match.
        - "expert" or "w2" will NOT match (must be exact segments).
This allows distinguishing parameters like "w2_weight" and "w2_weight_scale".
```

## Паспорт аргумента

- Флаги: `--cpu-offload-params`
- Группа argparse: `OffloadConfig`
- Тип значения: список строк (`set[str]`); argparse получает `nargs="+"`, pydantic приводит список к множеству
- Допустимые значения: не ограничены — это произвольные сегменты имен параметров конкретной модели
- Значение по умолчанию: `Field(default_factory=set)`, то есть пустое множество — фильтра нет
- Эффективное значение: не переопределяется; полностью игнорируется, если активен prefetch-backend (там свой фильтр — `--offload-params`)
- Где объявлен: `vllm/config/offload.py:UVAOffloadConfig.cpu_offload_params`
- Этап применения: загрузка модели, внутри `UVAOffloader.wrap_modules` — то есть один раз, при построении слоев

## Что меняет в движке

Значение попадает в `UVAOffloader.cpu_offload_params`. В `_maybe_offload_to_cpu` для каждого параметра слоя проверка выглядит так:

```python
should_offload = any(f".{param}." in f".{name}." for param in self.cpu_offload_params)
```

Точки приписываются с обеих сторон и к искомому сегменту, и к полному имени параметра, поэтому совпадение всегда **по целым сегментам, разделенным точками**. Для параметра `mlp.experts.w2_weight` строка сравнения — `.mlp.experts.w2_weight.`:

- `experts` → `.experts.` найдено → совпадение;
- `experts.w2_weight` → `.experts.w2_weight.` найдено → совпадение;
- `w2` → `.w2.` не найдено → нет совпадения;
- `expert` → `.expert.` не найдено → нет совпадения.

Именно это и позволяет отделить `w2_weight` от `w2_weight_scale`: последний даст сравнение `.mlp.experts.w2_weight_scale.`, в котором подстроки `.w2_weight.` нет.

Фильтр применяется **до** учета бюджета в том смысле, что несовпавшие параметры просто пропускаются (`continue`) и бюджет не расходуют. Но бюджет по-прежнему проверяется на каждом шаге: если совпавших параметров больше, чем `--cpu-offload-gb`, выгрузятся только те, что успели уложиться, и снова — начиная с первых слоев.

Имена параметров берутся из `module.named_parameters()` относительно слоя, а не относительно всей модели: префикса вида `model.layers.12.` в имени нет.

## Значения и формат

- Один или несколько сегментов через пробел: `--cpu-offload-params experts` или `--cpu-offload-params experts.w13_weight experts.w2_weight`.
- Дубликаты безвредны — значение хранится как множество.
- Пустое значение задать нельзя: `--cpu-offload-params` без аргументов argparse отвергнет (`nargs="+"` требует минимум один элемент). «Без фильтра» — это просто не указывать аргумент.
- Регистр и точки значимы. Ошибка в сегменте не диагностируется: несовпавший фильтр просто ничего не выгрузит.
- Как узнать реальные имена: они специфичны для архитектуры модели. Быстрый способ — включить выгрузку без фильтра, посмотреть фактическое `Total CPU offloaded parameters:` и сверить имена весов в `model.safetensors.index.json` репозитория модели; в именах vLLM после загрузки сохраняется хвост имени из чекпоинта.

## Когда использовать

- MoE-модель, у которой веса экспертов занимают большую часть параметров, а активируется на токен лишь малая доля: выгрузка `experts` дает максимум экономии VRAM на единицу потерянной скорости.
- Нужна предсказуемость: без фильтра набор выгруженных параметров меняется от того, как поменялся размер весов или бюджет, и производительность прыгает между запусками.
- Не используйте, когда `--cpu-offload-gb` небольшой и модель плотная (не MoE): выборочность там ничего не улучшает, а риск выгрузить не то — реальный.
- Не подставляйте сюда имена из чужой модели: несовпадение молча приводит к нулевой выгрузке, и вы получите OOM там, где рассчитывали на экономию.

## Влияние на производительность и память

Сам по себе аргумент памяти не потребляет и времени не занимает: это фильтр, применяемый один раз при загрузке. Его влияние целиком косвенное — он определяет, какая часть весов уйдет за PCIe и, следовательно, насколько дорогим станет forward. Выгрузка редко используемых экспертов при том же объеме в GiB стоит существенно меньше по времени шага, чем выгрузка слоев внимания, через которые проходит каждый токен.

## Взаимодействие с другими аргументами

- `--cpu-offload-gb`: обязателен. При нулевом значении offloader'ом становится `NoopOffloader`, и фильтр не выполняется.
- `--offload-backend`: работает только при `uva` (в том числе при `auto`, когда `--offload-group-size` равен нулю). При `prefetch` поле игнорируется.
- `--offload-params`: тот же по смыслу фильтр, но для prefetch-backend'а; правило совпадения по сегментам идентично. Один из двух, не оба.
- `--enable-expert-parallel`: альтернатива для MoE — разложить экспертов по нескольким картам вместо выгрузки в RAM. Если карты есть, это быстрее.

## Типовые проблемы и диагностика

- **Симптом:** выгрузка включена, фильтр задан, но `Total CPU offloaded parameters:` в логе нет вовсе. **Причина:** ни один параметр не совпал. **Проверка:** временно убрать фильтр и посмотреть, появляется ли строка. **Лечение:** исправить сегменты; помнить, что совпадение только по целым сегментам между точками.
- **Симптом:** выгружено намного меньше, чем `--cpu-offload-gb`. **Причина:** совпавших параметров просто меньше бюджета. Это не ошибка.
- **Симптом:** выгружено ровно столько, сколько бюджет, но скорость упала сильнее ожидаемого. **Причина:** бюджет исчерпался на первых слоях, и под выгрузку попали слои внимания первых блоков. **Лечение:** сузить фильтр до весов экспертов.
- **Симптом:** `--cpu-offload-params w2` не работает, а `--cpu-offload-params experts` работает. **Причина:** `w2` не является целым сегментом имени `w2_weight`. **Лечение:** писать `experts.w2_weight` или `w2_weight`.

## Примеры

```bash
vllm serve /models/Qwen3-30B-A3B --cpu-offload-gb 12 --cpu-offload-params experts
```

```bash
vllm serve /models/Qwen3-30B-A3B --cpu-offload-gb 12 --cpu-offload-params experts.w13_weight experts.w2_weight --offload-backend uva
```
