# --tokenizer

## Кратко

`--tokenizer` указывает репозиторий или каталог токенизатора. Значение по умолчанию — не `None`, а «то же, что `--model`»: подстановка делается в `ModelConfig.__post_init__`, поэтому в конфиге поле всегда заполнено.

Токенизатор живет во фронтенд-процессе (API-сервер), а не в GPU-воркерах: он превращает текст в id и обратно, применяет chat template и участвует в structured outputs.

## Оригинальная справка

```text
Name or path of the Hugging Face tokenizer to use. If unspecified, model
name or path will be used.
```

## Паспорт аргумента

- Флаги: `--tokenizer`
- Группа argparse: `ModelConfig`
- Тип значения: str — идентификатор репозитория HF, локальный путь или URI объектного хранилища
- Допустимые значения: не ограничены
- Значение по умолчанию: объявлено как `tokenizer: str = None`, то есть в extract видно `null`; фактический дефолт — значение `--model`
- Эффективное значение: `__post_init__` подставляет `self.model`, затем применяет `maybe_model_redirect` (карта `VLLM_MODEL_REDIRECT_PATH`), при `HF_HUB_OFFLINE=1` заменяет идентификатор локальным путем (`get_model_path`), а для URI объектного хранилища выкачивает во временный каталог **без файлов весов** и подставляет его
- Где объявлен: `vllm/config/model.py:ModelConfig.tokenizer`
- Этап применения: сборка `ModelConfig` → загрузка токенизатора во фронтенде (`cached_tokenizer_from_config`) → рендеринг запросов, детокенизация, structured outputs

## Что меняет в движке

1. **Дефолт и нормализация.** Если аргумент не задан, `self.tokenizer = self.model`. Дальше значение проходит через тот же редирект и офлайн-подстановку, что и модель.
2. **Ревизия.** Если `--tokenizer-revision` не задан, он приравнивается к `--revision`. Когда токенизатор совпадает с моделью и ревизию удалось разрешить, в поле ложится уже резолвленный commit-хеш модели; иначе ревизия токенизатора резолвится отдельно (`resolve_revision`).
3. **Загрузка.** `cached_tokenizer_from_config` (`vllm/tokenizers/registry.py`) вызывает `get_tokenizer(tokenizer, runner_type=…, tokenizer_mode=…, revision=tokenizer_revision, trust_remote_code=…)`. Результат кешируется по аргументам (`lru_cache`).
4. **`truncation_side`.** Выставляется по типу runner'а: `left` для `generate`/`draft`, `right` для `pooling`.
5. **Валидация.** После сборки конфига `validate_model_config_after` требует строку: `tokenizer must be a string, got …: … Please provide a valid tokenizer path or HuggingFace model ID.`

Словарь токенизатора и словарь модели движок **не сверяет**. Несовпадение проявится либо ошибкой выхода за границы словаря, либо просто мусорным текстом.

## Значения и формат

- Идентификатор HF (`org/name`), локальный каталог, URI объектного хранилища — те же формы, что и у `--model`.
- Пустого/специального значения нет. Чтобы вообще не поднимать токенизатор, используется `--skip-tokenizer-init`, а не пустая строка.
- Файл (`tokenizer.json`) указывать нельзя: ожидается каталог/репозиторий, из которого `from_pretrained` соберет токенизатор.

## Когда использовать

- Веса лежат локально, а токенизатор удобнее брать из исходного репозитория (или наоборот).
- Чекпойнт опубликован без корректных файлов токенизатора, и известен совместимый источник.
- Спекулятивное декодирование с разделяемым словарем: draft-модель по умолчанию получает токенизатор целевой модели, и явная подмена нужна только при гетерогенных словарях.
- Не трогайте аргумент, если токенизатор лежит рядом с весами: подстановка по умолчанию делает то же самое, но без риска рассинхронизации ревизий.

## Влияние на производительность и память

- **VRAM.** Не влияет: токенизатор целиком на хосте.
- **RAM хоста.** Один объект токенизатора плюс, при `--renderer-num-workers > 1`, пул из `N+1` глубоких копий для потокобезопасности.
- **Latency.** Медленный (не-`fast`) токенизатор заметно удорожает обработку длинных промптов на фронтенде; движок предупреждает об этом отдельно (см. `--tokenizer-mode`).
- **Время старта.** Загрузка токенизатора выполняется до готовности HTTP-слоя; для удаленного репозитория добавляется сетевой запрос.

## Взаимодействие с другими аргументами

- `--model`: источник дефолта; при совпадении значений ревизии тоже совмещаются.
- `--tokenizer-mode`: какой класс токенизатора будет использован для этого пути.
- `--tokenizer-revision`: версия репозитория токенизатора; по умолчанию наследует `--revision`.
- `--skip-tokenizer-init`: полностью отключает загрузку — тогда значение этого аргумента ни на что не влияет.
- `--trust-remote-code`: нужен, если репозиторий токенизатора приносит собственный класс.
- `--renderer-num-workers`: определяет размер пула копий токенизатора во фронтенде.

## Типовые проблемы и диагностика

- **Симптом:** `tokenizer must be a string, got NoneType: None. Please provide a valid tokenizer path or HuggingFace model ID.` **Причина:** значение не разрешилось (например, при программном конструировании конфига). **Лечение:** задать путь явно.
- **Симптом:** модель отвечает связным текстом на «своих» промптах и мусором на других. **Причина:** словарь токенизатора не соответствует модели. **Проверка:** сравнить `vocab_size` в конфиге модели и размер словаря токенизатора. **Лечение:** взять токенизатор из репозитория модели.
- **Симптом:** `Using a slow tokenizer. This might cause a significant slowdown. Consider using a fast tokenizer instead.` **Причина:** в указанном репозитории нет быстрого токенизатора либо задан `--tokenizer-mode slow`. **Лечение:** источник с `tokenizer.json`.
- **Симптом:** при `HF_HUB_OFFLINE=1` в логе `HF_HUB_OFFLINE is True, replace tokenizer_id [...] to tokenizer_path [...]`. **Причина:** офлайн-подстановка локального пути. **Лечение:** если путь не тот, задать локальный каталог явно.

## Примеры

```bash
vllm serve /models/Qwen3-4B --tokenizer /models/Qwen3-4B-tokenizer --max-model-len 8192
```

```bash
vllm serve /models/Qwen3-4B --tokenizer Qwen/Qwen3-4B --tokenizer-revision main --tokenizer-mode hf
```
