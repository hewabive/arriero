# --seed

## Кратко

`--seed` устанавливает зерно для `random`, `numpy`, `torch` и платформенного генератора в каждом рабочем процессе. Это нужно не столько для воспроизводимости ответов, сколько для согласованности: при tensor parallel все ранги должны сэмплировать одно и то же, иначе результаты разойдутся.

Дефолт `0` — не «случайно», а конкретное фиксированное значение.

## Оригинальная справка

```text
Random seed for reproducibility.

We must set the global seed because otherwise,
different tensor parallel workers would sample different tokens,
leading to inconsistent results.
```

## Паспорт аргумента

- Флаги: `--seed`
- Группа argparse: `ModelConfig`
- Тип значения: int
- Допустимые значения: не ограничены парсером
- Значение по умолчанию: `0`
- Эффективное значение: не переопределяется. Отдельно стоит знать, что в V1 сид **нельзя не задать**: значение всегда есть, и `set_random_seed` вызывается безусловно. Draft-модель спекулятивного декодирования наследует сид целевой модели (`SpeculativeConfig`)
- Где объявлен: `vllm/config/model.py:ModelConfig.seed`
- Этап применения: инициализация воркера (до загрузки весов) и повторно после загрузки модели

## Что меняет в движке

`Worker` вызывает `set_random_seed(self.model_config.seed)` дважды: при инициализации устройства и после загрузки модели (`vllm/v1/worker/gpu_worker.py`). Функция (`vllm/utils/torch_utils.py`) выставляет:

- `random.seed(seed)`;
- `np.random.seed(seed)`;
- `torch.manual_seed(seed)`;
- `current_platform.manual_seed_all(seed)` — все устройства платформы.

Значение исключено из факторов хеша конфигурации (`ModelConfig.compute_hash`, список `ignored_factors`), то есть смена сида **не** инвалидирует кеш `torch.compile` и не приводит к перекомпиляции.

Сид сервера и сид запроса — разные вещи. Поле `seed` в теле запроса OpenAI-совместимого API уходит в `SamplingParams.seed` и создает отдельный `torch.Generator` на запрос; запросы без своего сида берут шум из глобального генератора батчем.

## Значения и формат

- Целое число. `--seed 0` — то же, что дефолт.
- Значения `auto`/`none`/пустой строки нет; отключить сид на уровне CLI невозможно.
- Отрицательные значения парсер пропустит, но `torch.manual_seed` ожидает неотрицательное — используйте неотрицательные числа.

## Когда использовать

- Когда нужно отличать прогоны друг от друга при повторяемых экспериментах: разные сиды дают разные, но воспроизводимые серии.
- Когда две одинаково сконфигурированные копии сервера должны вести себя одинаково — сид должен совпадать.
- Не рассчитывайте, что один только `--seed` даст побитовую воспроизводимость: апстрим-документация (`docs/usage/reproducibility.md`) явно оговаривает, что нужен тот же хост и та же версия vLLM, а на онлайн-сервере — batch invariance, потому что состав батча меняет результат.

## Влияние на производительность и память

На производительность и память не влияет: это одна установка состояния генераторов при старте воркера.

## Взаимодействие с другими аргументами

- `--tensor-parallel-size`: собственно причина существования глобального сида — без него ранги сэмплировали бы разные токены (это проговорено в справке).
- `--use-fp64-gumbel`: меняет источник шума на fp64, но не отменяет сид.
- `--enforce-eager`: не связан с сидом, но вместе с ним часто используется при отладке расхождений — CUDA graphs добавляют собственную ось недетерминизма планирования.
- `--model`: сид не влияет на загрузку весов; расхождения между прогонами при одинаковом сиде ищите в составе батча, а не здесь.

## Типовые проблемы и диагностика

- **Симптом:** ответы отличаются между прогонами при одинаковом сиде и `temperature > 0`. **Причина:** на онлайн-сервере состав батча зависит от планировщика. **Лечение:** batch invariance по апстрим-документации либо сид на уровне запроса.
- **Симптом:** ответы отличаются между двумя серверами. **Причина:** разные версии vLLM/PyTorch, разные GPU, разные значения `--seed`. **Проверка:** баннер конфигурации при старте содержит `seed=…` (`vllm/config/vllm.py`).
- **Симптом:** нужно «отключить» сид, чтобы получить разные ответы. **Причина:** в V1 это невозможно. **Лечение:** менять сид между запусками либо задавать `seed` в теле каждого запроса.

## Примеры

```bash
vllm serve /models/Qwen3-4B --seed 1234 --max-model-len 8192
```

```bash
vllm serve /models/Qwen3-4B --seed 0 --tensor-parallel-size 2 --gpu-memory-utilization 0.85
```
