# --allowed-origins

## Кратко

Значение уходит в `allow_origins` у `CORSMiddleware`, который подключается в `build_app()`. По умолчанию это `["*"]` — любой сайт, открытый в браузере, может прочитать ответ вашего сервера.

Два практических уточнения. Первое: аргумент принимает **JSON**, а не голую строку, поэтому `--allowed-origins '*'` завершается ошибкой парсера. Второе: CORS — контракт браузера, а не защита сервера; `curl`, скрипт и любой внешний сервис игнорируют эти заголовки полностью.

## Оригинальная справка

```text
Allowed origins.
```

## Паспорт аргумента

- Флаги: `--allowed-origins`
- Группа argparse: `Frontend`
- Тип значения: список строк, задаваемый строкой JSON (`type=json.loads`, `nargs` у аргумента удален)
- Допустимые значения: любой JSON-массив строк; `["*"]` означает «любой источник»
- Значение по умолчанию: `field(default_factory=lambda: ['*'])`, то есть `["*"]`
- Эффективное значение: не переопределяется движком; семантику сопоставления реализует `CORSMiddleware` из starlette
- Где объявлен: `vllm/entrypoints/openai/cli_args.py:FrontendArgs.allowed_origins`
- Этап применения: HTTP-слой, `build_app()` — подключение middleware при сборке приложения

## Что меняет в движке

`FrontendArgs._customize_cli_kwargs` подменяет тип аргумента на `json.loads` и удаляет `nargs`, поэтому значение читается как одна строка JSON. Дальше `build_app()` передает его в `app.add_middleware(CORSMiddleware, allow_origins=args.allowed_origins, ...)` вместе с `allow_credentials`, `allow_methods` и `allow_headers`.

Собственной логики сравнения источников в vLLM нет: сопоставление, ответ на preflight и подстановка заголовков `Access-Control-Allow-*` целиком принадлежат starlette.

Важен порядок: CORS подключается **первым** из middleware, а в starlette позднее добавленные middleware оказываются снаружи. Значит, ответы, сформированные аутентификацией (`401`) и пользовательскими middleware из `--middleware`, проходят мимо CORS-слоя и не получают заголовков `Access-Control-Allow-*`.

## Значения и формат

- Правильно: `--allowed-origins '["https://app.example"]'`, `--allowed-origins '["*"]'`.
- Неправильно: `--allowed-origins '*'` — `json.loads` не разберет строку, argparse ответит `error: argument --allowed-origins: invalid loads value: '*'`.
- Несколько источников — элементы одного массива: `'["https://a.example","https://b.example"]'`.
- Источник — это схема + хост + порт. `https://app.example` и `http://app.example` — разные значения, `https://app.example/` со слэшем не совпадет с заголовком `Origin`.
- Проверить фактический ответ: `curl -i -H "Origin: https://evil.example" http://127.0.0.1:8000/v1/models` и посмотреть, есть ли в ответе `Access-Control-Allow-Origin`.

## Когда использовать

- Когда с сервером работает браузерное приложение с известного домена — перечислите его явно вместо `["*"]`.
- Когда сервер обслуживается только серверными клиентами (в том числе прокси arriero), значение не имеет практического смысла: CORS-заголовки нужны только браузеру. Осмысленно сузить его до пустого массива, чтобы не отдавать разрешение случайной странице.
- Не считайте сужение списка мерой защиты API: она ограничивает только страницы в браузере и не мешает прямым запросам.

## Влияние на производительность и память

Не влияет: сравнение строки `Origin` на запрос.

## Взаимодействие с другими аргументами

- `--allow-credentials`: связка `["*"]` + разрешенные учетные данные — типовая ошибка конфигурации, подробности в документе этого аргумента.
- `--allowed-methods`, `--allowed-headers`: три параметра действуют совместно; ограничение только источников не мешает preflight по методам и заголовкам.
- `--api-key`: ответ `401` формируется снаружи CORS-middleware, поэтому в браузере отказ выглядит как CORS-ошибка.
- `--host`: реальная граница доступа — интерфейс прослушивания, а не список источников.

## Типовые проблемы и диагностика

- **Симптом:** `error: argument --allowed-origins: invalid loads value: '*'`. **Причина:** значение не является JSON. **Лечение:** `'["*"]'`.
- **Симптом:** браузер сообщает `has been blocked by CORS policy`. **Причина:** источник страницы не входит в список либо не совпадает по схеме/порту. **Проверка:** сравнить заголовок `Origin` в devtools с содержимым списка.
- **Симптом:** запрос из браузера блокируется, хотя источник в списке. **Причина:** отказ пришел от аутентификации (401) до CORS-слоя. **Проверка:** повторить запрос через `curl` и посмотреть реальный код.
- **Симптом:** сервер доступен «кому угодно», хотя список сужен. **Причина:** CORS не ограничивает не-браузерные клиенты. **Лечение:** `--host 127.0.0.1`, файрвол, обратный прокси.

## Примеры

```bash
vllm serve /models/Qwen3-4B --host 127.0.0.1 --allowed-origins '["https://app.example"]'
```

```bash
vllm serve /models/Qwen3-4B --host 127.0.0.1 --allowed-origins '[]' --allowed-methods '["POST"]'
```
