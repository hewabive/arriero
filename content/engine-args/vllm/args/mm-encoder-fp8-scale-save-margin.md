# --mm-encoder-fp8-scale-save-margin

## Кратко

Флаг применяется ровно в одной точке: при одноразовом сбросе динамически наблюдённых масштабов в файл (`--mm-encoder-fp8-scale-save-path`) каждое значение `q`, `k`, `v` умножается на этот коэффициент. Больше он не участвует нигде — ни при чтении готового файла, ни в динамическом режиме без сохранения.

Смысл — запас: калибровочный набор почти наверняка не содержит самых экстремальных активаций, которые встретятся в проде. Значение `> 1` оставляет место, чтобы такие активации не переполнили FP8-диапазон. Дефолт `1.5` апстрим проверял на переносимость между датасетами.

## Оригинальная справка

```text
Safety margin multiplied onto scales when auto-saving. A value > 1
leaves headroom so that inputs with larger activations than the
calibration set do not overflow FP8 range. Default 1.5.
```

## Паспорт аргумента

- Флаги: `--mm-encoder-fp8-scale-save-margin`
- Группа argparse: `MultiModalConfig`
- Тип значения: float (безразмерный множитель)
- Допустимые значения: `Field(default=1.5, gt=0.0)` — строго больше нуля
- Значение по умолчанию: `1.5`
- Эффективное значение: не переопределяется; вне сценария автосохранения не применяется вовсе. Модульная переменная `_fp8_scale_save_margin` в `mm_encoder_attention.py` инициализируется тем же дефолтом класса и перезаписывается только при `mm_encoder_fp8_scale_save_path is not None` и активном динамическом режиме
- Где объявлен: `vllm/config/multimodal.py:MultiModalConfig.mm_encoder_fp8_scale_save_margin`
- Этап применения: момент записи файла масштабов (первый оборот 16-элементного буфера amax)

## Что меняет в движке

`_maybe_save_fp8_scales` при срабатывании строит словарь так:

```python
scales = {
    name: {"q": q.item() * margin, "k": k.item() * margin, "v": v.item() * margin}
    for name, (q, k, v) in _fp8_saved_scale_refs.items()
}
```

и сразу пишет его в JSON. Дальнейшее чтение этого файла через `--mm-encoder-fp8-scale-path` берёт числа как есть — запас в них уже вшит, повторно он не применяется.

Обратите внимание на порядок инициализации: `_fp8_scale_save_margin` — модульная переменная, значение по умолчанию которой берётся прямо из `MultiModalConfig.mm_encoder_fp8_scale_save_margin`. Перезаписывается она только в `_init_fp8_attn`, и только когда автосохранение реально настроено. Поэтому задать флаг без `--mm-encoder-fp8-scale-save-path` можно (валидация не возражает), но эффекта не будет — писать нечего.

## Значения и формат

- Дробное число, строго больше нуля. `0` и отрицательные значения отвергает pydantic (`gt=0.0`).
- `1.0` — записать наблюдённые максимумы без запаса. Максимальная точность на калибровочном распределении, максимальный риск переполнения на чём-то другом. Дополнительно: масштаб ровно `1.0` в файле взводит `skip_scale_*` в слое, то есть соответствующее умножение пропускается — так что `1.0` здесь не безобидная «единица», а значение со своим побочным эффектом при загрузке.
- `< 1` формально допустимо, но означает намеренное занижение масштабов — это гарантированное переполнение и практического смысла не имеет.
- `1.5` — дефолт, проверенный апстримом: калибровка на VisionArena-Chat с этим запасом сохраняет точность BF16 на ChartQA.
- `2.0` и выше — больше запаса, меньше эффективная разрядность. Разумно, если калибровочный набор заведомо узкий.

## Когда использовать

- Оставляйте дефолт, если не видите проблем: он и подобран как компромисс между переполнением и потерей точности.
- Повышайте, если после перехода на статические масштабы появились артефакты на изображениях, отличающихся от калибровочного набора (другое разрешение, другой домен) — и перекалибруйте.
- Понижайте до значений, близких к `1.0`, только когда калибровочный набор полностью покрывает боевой трафик и вы измерили выигрыш в качестве. На практике это редкий случай.
- Не задавайте вне калибровочного запуска: без `--mm-encoder-fp8-scale-save-path` флаг ничего не делает, и его присутствие в конфиге вводит в заблуждение.

## Влияние на производительность и память

- **Скорость.** Не влияет: множитель применяется один раз при записи файла.
- **VRAM.** Не влияет.
- **Точность.** Единственная задетая величина. Слишком большой запас снижает эффективную разрядность FP8 (значения используют меньшую часть диапазона), слишком малый — приводит к насыщению на выбросах.
- **Время старта.** Не влияет.

## Взаимодействие с другими аргументами

- `--mm-encoder-fp8-scale-save-path`: обязательное условие применимости. Без него множитель не используется.
- `--mm-encoder-fp8-scale-path`: взаимоисключён с автосохранением, поэтому и с этим флагом сочетается только формально; в готовом файле запас уже учтён.
- `--mm-encoder-attn-dtype`: `fp8` — предпосылка всей схемы.
- `--mm-encoder-attn-backend`: FP8-путь доступен только на `FLASHINFER` (CUDA) и `ROCM_AITER_FA` (ROCm).

## Типовые проблемы и диагностика

- **Симптом:** ошибка валидации на старте из-за `gt=0.0`. **Причина:** передан ноль или отрицательное значение. **Лечение:** положительное число.
- **Симптом:** флаг задан, файл масштабов не изменился. **Причина:** нет `--mm-encoder-fp8-scale-save-path`, либо запуск идёт со статическими масштабами. **Лечение:** множитель имеет смысл только в калибровочном запуске.
- **Симптом:** после калибровки качество на некоторых входах хуже BF16. **Причина:** запас мал для реального распределения активаций. **Лечение:** поднять до `2.0`, перекалибровать, сравнить.
- **Симптом:** после калибровки качество равномерно чуть хуже на всём трафике. **Причина:** запас велик, диапазон FP8 используется не полностью. **Лечение:** снизить в сторону `1.2`–`1.5` и перекалибровать.
- **Подтверждение принятого значения:** прямой строки в логе нет; проверяется по числам в сохранённом файле — они должны быть примерно в `margin` раз больше наблюдённых amax. Факт записи подтверждает `Saved FP8 scales (N layers) to <path>`.

## Примеры

```bash
vllm serve /models/Qwen3-VL-8B-Instruct --mm-encoder-attn-backend FLASHINFER --mm-encoder-attn-dtype fp8 --mm-encoder-fp8-scale-save-path /models/scales/qwen3vl-8b-vit.json --mm-encoder-fp8-scale-save-margin 2.0
```

```bash
vllm serve /models/Qwen3-VL-8B-Instruct --mm-encoder-attn-backend FLASHINFER --mm-encoder-attn-dtype fp8 --mm-encoder-fp8-scale-save-path /models/scales/qwen3vl-8b-vit-tight.json --mm-encoder-fp8-scale-save-margin 1.2
```
