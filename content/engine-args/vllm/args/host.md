# --host

## Кратко

`--host` задает адрес, к которому привязывается слушающий сокет HTTP-фронтенда. Ключевой факт: **значение по умолчанию — не `localhost`**. Если аргумент не задан, `setup_server()` вызывает `bind(("", port))`, то есть сокет открывается на всех интерфейсах машины.

Сокет создается до инициализации движка, поэтому адрес и порт заняты уже на первых секундах старта, задолго до того, как сервер начнет отвечать.

## Оригинальная справка

```text
Host name.
```

## Паспорт аргумента

- Флаги: `--host`
- Группа argparse: `Frontend`
- Тип значения: str (IP-литерал или имя хоста), допускается `None`
- Допустимые значения: не ограничены парсером; фактически строка должна разрешаться в адрес локального интерфейса
- Значение по умолчанию: `None`
- Эффективное значение: `None` превращается в пустую строку в `sock_addr = (args.host or "", args.port)`, а `bind("")` для `AF_INET` — это `0.0.0.0`, то есть все интерфейсы. В логе стартовая строка печатает то же самое: `host_part = ... addr or "0.0.0.0"`
- Где объявлен: `vllm/entrypoints/openai/cli_args.py:FrontendArgs.host`
- Этап применения: HTTP-слой, `setup_server()` — создание сокета **до** сборки движка и загрузки весов

## Что меняет в движке

На вычисления не влияет вообще: значение уходит только в сетевой слой.

1. `setup_server()` выбирает семейство сокета: `AF_INET6`, если строка проходит `is_valid_ipv6_address`, иначе `AF_INET`. Затем `SO_REUSEADDR`, при `--api-server-count > 1` еще и `SO_REUSEPORT`, и `bind(addr)`.
2. Сокет биндится **до** запуска движка (комментарий в коде ссылается на гонку с ray, upstream-issue #8204). До того как uvicorn вызовет `listen()`, адрес уже занят для других процессов, но входящие соединения отбиваются — это и есть наблюдаемое «порт закрыт, пока грузится модель».
3. Готовый сокет передается в `serve_http(...)`; `host=args.host` уходит в `uvicorn.Config` только как метаданные, реальную привязку выполнил уже созданный сокет.
4. При заданном `--uds` вся эта ветка не выполняется: сокет создается как `AF_UNIX`, `--host` и `--port` игнорируются.

Стартовая строка `Starting vLLM server on http://<host>:<port>` — единственное подтверждение того, что адрес принят.

## Значения и формат

- Не задан — все интерфейсы IPv4 (`0.0.0.0`).
- `127.0.0.1` — только петля; единственный безопасный вариант для одного хоста.
- `0.0.0.0` — явная запись поведения по умолчанию.
- IPv6-литерал (`::1`, `::`) переключает семейство сокета на `AF_INET6`; поведение dual-stack определяется настройками ОС, а не vLLM.
- Имя хоста допустимо: его разрешает `bind`, отдельной валидации в vLLM нет.
- Адрес, которого нет на машине, приводит к падению на `bind` (`OSError: [Errno 99] Cannot assign requested address`) — до загрузки весов.

## Когда использовать

- Задавайте `--host 127.0.0.1` на любом инстансе, который обслуживается через прокси arriero: наружу смотрит менеджер, движку внешний интерфейс не нужен.
- Задавайте конкретный адрес интерфейса, если инстанс должен быть доступен другому узлу (например, при внешней балансировке) — но тогда закройте порт файрволом и не полагайтесь на `--api-key` как на единственную защиту.
- Не оставляйте аргумент незаданным «потому что дефолт безопасный»: дефолт открывает сервер во все сети, к которым подключена машина.

## Влияние на производительность и память

Нулевое: аргумент не влияет ни на VRAM, ни на RAM, ни на время старта. Единственный эффект — какой сокет создается.

## Взаимодействие с другими аргументами

- `--port`: пара, задающая точку прослушивания; проверка занятости и конфликтов идет по обоим значениям.
- `--uds`: полностью отменяет `--host` и `--port`.
- `--api-key`: не компенсирует открытый наружу интерфейс — ключ проверяется только на префиксах `/v1`, `/v2`, `/inference`, `/cohere`, а `/tokenize`, `/pause`, `/abort_requests`, `/score`, `/rerank` остаются без аутентификации.
- `--ssl-certfile`, `--ssl-keyfile`: если сервер слушает не только петлю, трафик должен идти по TLS; иначе ключ из заголовка `Authorization` уходит открытым текстом.
- `--root-path`: не влияет на привязку сокета, только на генерацию URL за обратным прокси.
- `--api-server-count`: при значении больше 1 сокет создается с `SO_REUSEPORT` и передается дочерним процессам.

## Типовые проблемы и диагностика

- **Симптом:** сервер доступен с других машин, хотя «ничего не настраивали». **Причина:** `--host` не задан, сокет на `0.0.0.0`. **Проверка:** строка `Starting vLLM server on http://0.0.0.0:8000` в логе и `ss -ltnp | grep <port>`. **Лечение:** `--host 127.0.0.1`.
- **Симптом:** `OSError: [Errno 99] Cannot assign requested address` на старте. **Причина:** указанного адреса нет ни на одном интерфейсе. **Лечение:** взять адрес из `ip -brief addr`.
- **Симптом (arriero):** preflight сообщает `Host X is not available on this machine` или `Port N is already in use on X`. **Причина:** менеджер проверяет привязку `host:port` перед запуском. **Лечение:** исправить адрес либо освободить порт.
- **Симптом (arriero):** инстанс работает, но менеджер не видит здоровье. **Причина:** значение `--host` указывает на интерфейс, недоступный менеджеру. **Как устроено:** менеджер строит адрес инстанса из `--host`/`--port`, подставляя `127.0.0.1` вместо `0.0.0.0` и `::`, и опрашивает `/health` и `/v1/models` (`docs/API_PROXY_FOUNDATION.md`, arriero). **Лечение:** оставить `127.0.0.1` или адрес, видимый менеджеру.
- **Отдельно:** привязка HTTP-порта к петле не закрывает служебные порты. `torch.distributed` поднимает `TCPStore`, который по умолчанию слушает на всех интерфейсах; это описано в `vllm/docs/usage/security.md` и лечится только файрволом.

## Примеры

```bash
vllm serve /models/Qwen3-4B --host 127.0.0.1 --port 8000
```

```bash
vllm serve /models/Qwen3-4B --host 127.0.0.1 --port 8000 --api-key local-only-key --disable-fastapi-docs
```
