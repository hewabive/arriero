# --offload-params

## Кратко

`--offload-params` сужает prefetch-выгрузку до конкретных тензоров. Без него каждый отобранный по раскладке слой выгружается целиком — все его параметры до единого. С фильтром выгружаются только совпавшие, а слой, в котором не совпало ничего, **исключается из выгрузки полностью** и не занимает место в буферном пуле.

Правило совпадения — по целым сегментам имени, разделенным точками, ровно как у `--cpu-offload-params` в UVA-режиме. Разница между двумя аргументами не в правиле, а в том, что означает пустое значение: у `--cpu-offload-params` пустой набор значит «все подряд до исчерпания байтового бюджета», здесь — «все параметры каждого выбранного слоя».

## Оригинальная справка

```text
The set of parameter name segments to target for prefetch offloading.
Unmatched parameters are not offloaded. If this set is empty, ALL
parameters of each offloaded layer are offloaded.
Uses segment matching: "w13_weight" matches "mlp.experts.w13_weight"
but not "mlp.experts.w13_weight_scale".
```

## Паспорт аргумента

- Флаги: `--offload-params`
- Группа argparse: `OffloadConfig`
- Тип значения: список строк (`set[str]`); argparse получает `nargs="+"`, pydantic приводит список к множеству
- Допустимые значения: не ограничены — произвольные сегменты имен параметров конкретной модели
- Значение по умолчанию: `Field(default_factory=set)`, то есть пустое множество — выгружаются все параметры выбранных слоев
- Эффективное значение: не переопределяется; не читается вне prefetch-режима (`--offload-group-size 0` или `--offload-backend uva`)
- Где объявлен: `vllm/config/offload.py:PrefetchOffloadConfig.offload_params`
- Этап применения: построение слоев в `make_layers` (`PrefetchOffloader.wrap_modules`)

## Что меняет в движке

Фильтр применяется при отборе, до создания `_ModuleOffloader`:

```python
whitelist = [name for name, _ in module.named_parameters()
             if any(f".{p}." in f".{name}." for p in self.offload_params)]
if not whitelist:
    continue
```

Три следствия, которые видно только здесь.

1. **Совпадение по сегментам.** И искомая строка, и полное имя параметра обрамляются точками, поэтому `w13_weight` совпадает с `mlp.experts.w13_weight`, но не с `mlp.experts.w13_weight_scale` — во втором случае искомая подстрока `.w13_weight.` отсутствует. Имена берутся относительно слоя, без префикса `model.layers.N.`.
2. **Слой без совпадений выпадает.** `continue` означает, что такой слой не попадает в `module_offloaders`, не получает hook на forward и не влияет на нумерацию оставшихся. Фактическая раскладка может оказаться сильно реже расчетной `num_in_group / group_size`.
3. **Пул считается по отфильтрованному набору.** `StaticBufferPool` аллоцирует слоты только под совпавшие параметры, поэтому узкий фильтр удешевляет `--offload-prefetch-step`: цена одного шага опережения падает пропорционально размеру фильтрованного набора.

Дополнительно, в `sync_cpu_storage()` из набора удаляются параметры, которых после `process_weights_after_loading` уже не существует (например, временные `k_scale`/`v_scale` при квантизации KV): они не участвуют ни в аллокации пула, ни в подкачке. Это происходит независимо от фильтра.

## Значения и формат

- Один или несколько сегментов через пробел: `--offload-params experts` или `--offload-params w13_weight w2_weight`.
- Дубликаты безвредны — хранится множество.
- Пустое значение задать нельзя: `nargs="+"` требует минимум один элемент. «Без фильтра» — просто не указывать аргумент.
- Опечатка не диагностируется как ошибка: несовпавший фильтр приводит к тому, что выгружается ноль слоев, и режим тихо становится пустой операцией.
- Имена специфичны для архитектуры. Ориентир для MoE — сегмент `experts` и имена весов экспертов (`w13_weight`, `w2_weight` у типовых слитых MoE-слоев vLLM); проверять их следует по фактическому набору весов конкретной модели.

## Когда использовать

- MoE-модель: выгрузка только `experts` дает наибольшую экономию VRAM на единицу потерянного времени, поскольку эксперты крупные, а на токен активируется малая их доля.
- Нужно уменьшить стоимость `--offload-prefetch-step`: чем уже фильтр, тем меньше один слот пула и тем дешевле поднять глубину опережения.
- Не используйте на плотной модели без замера: там все параметры слоя нужны каждому токену, и выборочность лишь усложняет конфигурацию.
- Не переносите фильтр между моделями: имена параметров разные, а несовпадение молча отключает выгрузку.

## Влияние на производительность и память

Сам фильтр ресурсов не потребляет — он применяется один раз при построении слоев. Косвенно он определяет три величины: объем выгруженных весов (экономия VRAM и рост занятой хостовой RAM), размер одного слота буферного пула (`prefetch_step × отфильтрованный объем слоя`) и то, сколько байт реально проходит по PCIe на каждый forward. Узкий фильтр по редко активируемым тензорам — единственный способ получить заметную экономию VRAM при умеренной просадке скорости.

## Взаимодействие с другими аргументами

- `--offload-group-size`: включает режим и задает, какие слои вообще рассматриваются; фильтр работает внутри них.
- `--offload-num-in-group`: расчетная доля выгруженных слоев; фактическая может быть меньше из-за слоев без совпадений.
- `--offload-prefetch-step`: размер слота пула считается по отфильтрованному набору параметров.
- `--offload-backend`: значение читается только при `prefetch` (или `auto` с ненулевой группой).
- `--cpu-offload-params`: тот же по смыслу фильтр для UVA-режима, с тем же правилом совпадения по сегментам. Действует ровно один из двух — тот, что соответствует выбранному backend'у.

## Типовые проблемы и диагностика

- **Симптом:** режим включен, но в логе `Initialized 0 modules` или строки `[PrefetchOffloader]` нет вовсе. **Причина:** ни один параметр не совпал с фильтром. **Проверка:** временно убрать фильтр и сравнить число модулей. **Лечение:** исправить сегменты.
- **Симптом:** выгружено меньше слоев, чем `число_слоев × num_in_group / group_size`. **Причина:** часть отобранных слоев не содержит совпавших параметров (типично для гибридных архитектур, где MoE есть не в каждом блоке). **Проверка:** `Initialized N modules`.
- **Симптом:** `--offload-params w13` не работает, `--offload-params w13_weight` работает. **Причина:** `w13` не является целым сегментом. **Лечение:** писать сегмент целиком.
- **Симптом:** экономия VRAM меньше ожидаемой при широком фильтре. **Причина:** размер буферного пула растет вместе с отфильтрованным объемом слоя. **Проверка:** пара `Total GPU memory saved` / `Static buffer pool` в итоговой строке.
- **Подтверждение принятого значения:** прямой печати фильтра нет; косвенное подтверждение — число модулей и объем сэкономленной памяти в строке `[PrefetchOffloader] Initialized N modules. Total GPU memory saved: X GB, Static buffer pool: Y GB (...)`.

## Примеры

```bash
vllm serve /models/Qwen3-30B-A3B --offload-group-size 4 --offload-num-in-group 1 --offload-params experts
```

```bash
vllm serve /models/Qwen3-30B-A3B --offload-backend prefetch --offload-group-size 4 --offload-num-in-group 2 --offload-prefetch-step 2 --offload-params w13_weight w2_weight
```
