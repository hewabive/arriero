# --ssl-certfile

## Кратко

`--ssl-certfile` — половина пары, включающей TLS. Значение уходит в `uvicorn.Config(ssl_certfile=...)`, где на его основе строится `SSLContext`. Без `--ssl-keyfile` пара неполна, и стартовая строка лога останется `http://...`.

Файл читается процессом движка при старте, поэтому он должен быть доступен пользователю, от имени которого запущен инстанс.

## Оригинальная справка

```text
The file path to the SSL cert file.
```

## Паспорт аргумента

- Флаги: `--ssl-certfile`
- Группа argparse: `Frontend`
- Тип значения: str (путь), допускается `None`
- Допустимые значения: путь к PEM-файлу сертификата (при необходимости с цепочкой промежуточных)
- Значение по умолчанию: `None` — TLS выключен
- Эффективное значение: не переопределяется; `is_ssl = args.ssl_keyfile and args.ssl_certfile` в `setup_server()` определяет только схему в печатаемом адресе, реальный `SSLContext` собирает uvicorn
- Где объявлен: `vllm/entrypoints/openai/cli_args.py:FrontendArgs.ssl_certfile`
- Этап применения: HTTP-слой, `serve_http()` → `uvicorn.Config(...).load()`

## Что меняет в движке

vLLM только пробрасывает путь: `serve_http(..., ssl_certfile=args.ssl_certfile, ...)` → `uvicorn.Config`. Загрузка сертификата, проверка соответствия ключу и все ошибки формата принадлежат uvicorn и стандартному модулю `ssl`.

Существование файла vLLM не проверяет: неверный путь всплывет как исключение при построении контекста, то есть после инициализации движка и загрузки весов — самая обидная точка отказа при старте.

При `--enable-ssl-refresh` этот же путь попадает в `SSLCertRefresher`, который следит за изменениями файла и перезагружает цепочку через `load_cert_chain`.

## Значения и формат

- PEM-файл. Если нужны промежуточные сертификаты, они кладутся в тот же файл после серверного.
- Абсолютный путь надежнее относительного: рабочий каталог управляемого процесса задается менеджером.
- Не задан — TLS выключен независимо от остальных `--ssl-*`.
- Задан без `--ssl-keyfile` — конфигурация неполна; в логе адрес останется `http://`, а построение контекста упадет.

## Когда использовать

- Когда сервер слушает не только петлю и трафик идет по сети, в которой его могут прочитать.
- Не используйте для управляемых инстансов arriero: менеджер строит адрес инстанса как `http://<host>:<port>` и опрашивает `/health` и `/v1/models` по обычному HTTP (`docs/API_PROXY_FOUNDATION.md`, arriero). После включения TLS инстанс перестанет быть здоровым в панели и недоступен через прокси. TLS правильно завершать на самом arriero или на обратном прокси перед ним.

## Влияние на производительность и память

VRAM и время загрузки модели не затрагивает. TLS добавляет рукопожатие на соединение и шифрование потока; для длинных SSE-ответов это заметно только на очень слабом CPU. Соединения, открытые до перезагрузки сертификата, продолжают работать со старым.

## Взаимодействие с другими аргументами

- `--ssl-keyfile`: обязательная пара.
- `--ssl-ca-certs`, `--ssl-cert-reqs`: нужны только для проверки клиентских сертификатов (mTLS).
- `--ssl-ciphers`: набор шифров для TLS 1.2 и ниже.
- `--enable-ssl-refresh`: перечитывает этот файл при изменении.
- `--host`: TLS нужен там, где сервер слушает не только `127.0.0.1`.

## Типовые проблемы и диагностика

- **Симптом:** в логе `Starting vLLM server on http://...`, хотя сертификат задан. **Причина:** не задан `--ssl-keyfile`. **Лечение:** задать оба пути.
- **Симптом:** `FileNotFoundError` или `ssl.SSLError: [SSL] PEM lib` при старте, уже после загрузки модели. **Причина:** неверный путь, неверный формат или несоответствие ключа сертификату. **Лечение:** проверить `openssl x509 -in cert.pem -noout -subject -dates` и совпадение модуля ключа с сертификатом.
- **Симптом:** клиент ругается на неизвестный удостоверяющий центр. **Причина:** не приложена цепочка промежуточных сертификатов. **Лечение:** добавить их в тот же PEM.
- **Симптом (arriero):** после включения TLS инстанс запускается, но остается без здоровья. **Причина:** менеджер обращается по `http://`. **Лечение:** снять TLS с управляемого инстанса.

## Примеры

```bash
vllm serve /models/Qwen3-4B --host 0.0.0.0 --ssl-certfile /etc/ssl/vllm/fullchain.pem --ssl-keyfile /etc/ssl/vllm/privkey.pem
```

```bash
vllm serve /models/Qwen3-4B --host 0.0.0.0 --ssl-certfile /etc/ssl/vllm/fullchain.pem --ssl-keyfile /etc/ssl/vllm/privkey.pem --enable-ssl-refresh
```
