# --ssl-keyfile

## Кратко

`--ssl-keyfile` задает приватный ключ, парный сертификату из `--ssl-certfile`. Оба значения уходят в `uvicorn.Config`, где собирается `SSLContext`. Один аргумент без другого TLS не включает.

Ключ — секрет: он читается процессом инстанса, поэтому права на файл должны быть минимальными (`0600` у пользователя, от которого запускается движок), а путь не должен попадать в общедоступные каталоги.

## Оригинальная справка

```text
The file path to the SSL key file.
```

## Паспорт аргумента

- Флаги: `--ssl-keyfile`
- Группа argparse: `Frontend`
- Тип значения: str (путь), допускается `None`
- Допустимые значения: путь к PEM-файлу приватного ключа
- Значение по умолчанию: `None` — TLS выключен
- Эффективное значение: не переопределяется; вместе с `--ssl-certfile` определяет `is_ssl` для печатаемого адреса, контекст строит uvicorn
- Где объявлен: `vllm/entrypoints/openai/cli_args.py:FrontendArgs.ssl_keyfile`
- Этап применения: HTTP-слой, `serve_http()` → `uvicorn.Config(...).load()`

## Что меняет в движке

Путь пробрасывается в `serve_http(..., ssl_keyfile=args.ssl_keyfile, ...)` и дальше в `uvicorn.Config`. vLLM не читает файл сам, не проверяет его существование и не поддерживает пароль на ключе через собственный аргумент — вся обработка на стороне uvicorn и модуля `ssl`.

При `--enable-ssl-refresh` путь также передается в `SSLCertRefresher`; наблюдение ведется за парой ключ+сертификат, и при изменении любого из файлов вызывается `load_cert_chain(cert_path, key_path)`.

## Значения и формат

- PEM-файл с приватным ключом без пароля: аргумента для пароля у vLLM нет.
- Абсолютный путь; права `0600`, владелец — пользователь процесса.
- Не задан — TLS выключен, даже если сертификат указан.
- Ключ должен соответствовать сертификату, иначе построение контекста завершится ошибкой.

## Когда использовать

- Всегда вместе с `--ssl-certfile`, когда сервер обслуживает сетевые клиенты напрямую.
- Не используйте на управляемых инстансах arriero: менеджер обращается к инстансу по `http://<host>:<port>` (`docs/API_PROXY_FOUNDATION.md`, arriero), и после включения TLS опрос перестает работать.

## Влияние на производительность и память

На память не влияет. Рукопожатие TLS добавляет работу CPU на каждое новое соединение; для потоковых ответов это разовая стоимость на соединение.

## Взаимодействие с другими аргументами

- `--ssl-certfile`: обязательная пара.
- `--enable-ssl-refresh`: перечитывает пару при изменении файлов.
- `--ssl-ca-certs`, `--ssl-cert-reqs`: включают проверку клиентских сертификатов.
- `--ssl-ciphers`: ограничивает наборы шифров для TLS 1.2 и ниже.

## Типовые проблемы и диагностика

- **Симптом:** `ssl.SSLError: [SSL: KEY_VALUES_MISMATCH] key values mismatch`. **Причина:** ключ не соответствует сертификату. **Лечение:** сверить пару, например по совпадению хешей модуля через `openssl`.
- **Симптом:** `PermissionError` при старте. **Причина:** файл ключа недоступен пользователю процесса. **Лечение:** выдать доступ ровно этому пользователю, а не всем.
- **Симптом:** запрашивается пароль ключа. **Причина:** ключ зашифрован; отдельного аргумента для пароля в vLLM нет. **Лечение:** использовать незашифрованный ключ с ограниченными правами.
- **Симптом:** адрес в логе остался `http://`. **Причина:** задан только один из двух путей.

## Примеры

```bash
vllm serve /models/Qwen3-4B --host 0.0.0.0 --ssl-keyfile /etc/ssl/vllm/privkey.pem --ssl-certfile /etc/ssl/vllm/fullchain.pem
```

```bash
vllm serve /models/Qwen3-4B --host 0.0.0.0 --ssl-keyfile /etc/ssl/vllm/privkey.pem --ssl-certfile /etc/ssl/vllm/fullchain.pem --ssl-ca-certs /etc/ssl/vllm/clients-ca.pem --ssl-cert-reqs 2
```
