# --kv-cache-metrics-sample

## Кратко

Значение — вероятность, с которой каждый вновь выделенный блок попадает под наблюдение. Дефолт `0.01` означает, что состояние заводится примерно для одного блока из ста, и все три гистограммы KV-резидентности строятся по этой выборке.

Чего значение **не** делает: не убирает проверку. `random.random()` вызывается на каждый выделенный блок независимо от доли, поэтому уменьшение значения снижает потребление памяти под состояния и точность гистограмм, но не убирает базовую стоимость хука.

## Оригинальная справка

```text
Sampling rate for KV cache metrics (0.0, 1.0]. Default 0.01 = 1% of blocks.
```

## Паспорт аргумента

- Флаги: `--kv-cache-metrics-sample`
- Группа argparse: `ObservabilityConfig`
- Тип значения: float (доля, не проценты)
- Допустимые значения: `Field(default=0.01, gt=0, le=1)` — строго больше 0 и не больше 1
- Значение по умолчанию: `0.01`
- Эффективное значение: не переопределяется. Диапазон проверяется дважды: pydantic-валидацией поля и `assert 0 < sample_rate <= 1.0` в конструкторе `KVCacheMetricsCollector`
- Где объявлен: `vllm/config/observability.py:ObservabilityConfig.kv_cache_metrics_sample`
- Этап применения: инициализация планировщика (передаётся в коллектор) → выделение каждого блока KV-cache

## Что меняет в движке

Значение попадает в конструктор `KVCacheMetricsCollector`, где становится полем `sample_rate`. Единственный потребитель — `should_sample_block()`:

```text
return random.random() < self.sample_rate
```

Метод вызывается из `on_block_allocated()` для каждого блока, выданного `BlockPool.get_new_blocks()`. При попадании в выборку заводится `BlockMetricsState` (время рождения, время последнего обращения, кольцевой буфер на 4 отметки доступа); блок вне выборки не отслеживается, и последующие `on_block_accessed`/`on_block_evicted` для него сводятся к промаху словаря.

Выборка независима для каждого блока и не сохраняется между переиспользованиями одного и того же `block_id`: при повторном выделении жребий бросается заново.

Если `--kv-cache-metrics` не задан, коллектор не создаётся и значение аргумента вообще никем не читается.

## Значения и формат

- Дробное число в интервале `(0, 1]`. `0.05` — 5 % блоков, `1` — все блоки.
- `0` и отрицательные значения отвергаются валидацией; больше `1` — тоже.
- Специальных значений нет; «выключить» через этот аргумент нельзя — для этого есть `--no-kv-cache-metrics`.
- Значение указывается долей, а не процентами: `5` будет отвергнуто.

## Когда использовать

- Поднимайте, когда гистограммы пусты или слишком «зернисты»: на инстансе с небольшим числом блоков и редкими вытеснениями 1 % даёт единицы наблюдений за интервал.
- Ставьте `1` на коротком контролируемом замере, когда нужна полная картина резидентности блоков и вы готовы к дополнительной памяти под состояния.
- Оставляйте дефолт на долгоживущем инстансе с большим KV-cache: там 1 % — это уже тысячи блоков.
- Не меняйте в надежде снизить накладные расходы: проверка выполняется на каждом блоке в любом случае.

## Влияние на производительность и память

- **CPU планировщика.** Не зависит от значения: один вызов `random.random()` на выделенный блок при любой доле. Отслеживаемые блоки дополнительно платят записью времени при каждом обращении.
- **RAM хоста.** Линейно по значению: верхняя граница — `sample_rate × число блоков KV-cache` состояний, каждое из которых хранит два таймстампа и `deque` максимум на 4 элемента. При `1` отслеживаются все блоки.
- **Объём событий.** Пропорционален доле: чем больше выборка, тем длиннее список `KVCacheEvictionEvent` между вычитываниями и тем больше наблюдений попадает в гистограммы.
- **VRAM.** Не влияет.

## Взаимодействие с другими аргументами

- `--kv-cache-metrics`: без него значение не используется вовсе.
- `--disable-log-stats`: события не вычитываются; при большой доле выборки список растёт быстрее.
- `--enable-prefix-caching`: без него события вытеснения почти не появляются, и повышение доли выборки картину не исправит.
- `--block-size`, `--gpu-memory-utilization`: определяют общее число блоков, то есть абсолютное количество отслеживаемых.

## Типовые проблемы и диагностика

- **Симптом:** `--kv-cache-metrics-sample 5` отвергается валидацией. **Причина:** значение задаётся долей. **Лечение:** `0.05`.
- **Симптом:** гистограммы `vllm:kv_block_*` почти пусты. **Причина:** доля слишком мала для наблюдаемого объёма вытеснений, либо вытеснений нет вовсе. **Проверка:** счётчик `_sum`/`_count` гистограммы `vllm:kv_block_lifetime_seconds` за интервал. **Лечение:** поднять долю; если и при `1` пусто — проверять `--enable-prefix-caching`.
- **Симптом:** аргумент задан, а поведение не изменилось. **Причина:** `--kv-cache-metrics` не включён. **Лечение:** включить.
- **Симптом:** рост RSS процесса движка после подъёма доли до `1`. **Причина:** состояния заводятся для всех блоков. **Лечение:** вернуть меньшую долю после замера.
- **Подтверждение принятого значения:** отдельной строки в логе нет; проверяется по темпу роста `vllm:kv_block_lifetime_seconds_count` в `/metrics`.

## Примеры

```bash
vllm serve /models/Qwen3-4B --kv-cache-metrics --kv-cache-metrics-sample 0.05
```

```bash
vllm serve /models/Qwen3-4B --kv-cache-metrics --kv-cache-metrics-sample 1 --enable-prefix-caching
```
