# --kv-cache-metrics

## Кратко

Метрики отвечают на вопрос «имеет ли смысл prefix caching на этой нагрузке»: если блоки живут доли секунды и вытесняются, ни разу не переиспользованные, кэш не работает. Учёт выборочный — по умолчанию отслеживается 1 % блоков (`--kv-cache-metrics-sample`).

Важная деталь реализации: события вытеснения складываются в список внутри планировщика и вычитываются только в `Scheduler.make_stats()`, который при `--disable-log-stats` сразу возвращает `None`. Справка говорит «требуется включённая статистика», но проверки в коде нет: с выключенной статистикой список растёт неограниченно.

## Оригинальная справка

```text
Enable KV cache residency metrics (lifetime, idle time, reuse gaps).
Uses sampling to minimize overhead.
Requires log stats to be enabled (i.e., --disable-log-stats not set).
```

## Паспорт аргумента

- Флаги: `--kv-cache-metrics`, `--no-kv-cache-metrics`
- Группа argparse: `ObservabilityConfig`
- Тип значения: bool (`argparse.BooleanOptionalAction`)
- Допустимые значения: флаг без значения; выключается парной формой из списка выше
- Значение по умолчанию: `false`
- Эффективное значение: не переопределяется. Заявленная в справке зависимость от статистики нигде не проверяется — коллектор создаётся и при `--disable-log-stats`
- Где объявлен: `vllm/config/observability.py:ObservabilityConfig.kv_cache_metrics`
- Этап применения: инициализация планировщика (создание коллектора) → выделение/обращение/вытеснение каждого блока → сборка `SchedulerStats` → Prometheus

## Что меняет в движке

**Коллектор.** `Scheduler.__init__` создаёт `KVCacheMetricsCollector(kv_cache_metrics_sample)` и передаёт его в `KVCacheManager` → координатор → `BlockPool`. Без флага все вызовы в `BlockPool` защищены проверкой `if self.metrics_collector` и не выполняются.

**Хуки в `BlockPool`.**

- `get_new_blocks()` — `on_block_allocated(block)` на каждый выданный блок. Внутри выполняется `random.random() < sample_rate`, и только при попадании в выборку создаётся `BlockMetricsState` с временем рождения.
- `touch()` — `on_block_accessed(block)` на каждый «тронутый» блок: словарный `get` и, для отслеживаемых блоков, запись времени в кольцевой буфер `deque(maxlen=4)`.
- `_maybe_evict_cached_block()` — `on_block_evicted(block)`: отслеживаемый блок удаляется из словаря, и в список событий добавляется `KVCacheEvictionEvent(lifetime_seconds, idle_seconds, reuse_gaps_seconds)`. Из-за `maxlen=4` в событии не больше трёх интервалов переиспользования.
- `reset_prefix_cache()` — `reset()`: словарь и накопленные события очищаются.

Ключ словаря — `block_id`, поэтому число отслеживаемых состояний ограничено сверху числом блоков KV-cache: повторное выделение того же блока перезаписывает запись, и утечки здесь нет.

**Вычитывание.** `Scheduler.make_stats()` вызывает `drain_events()` и кладёт список в `SchedulerStats.kv_cache_eviction_events`. `PrometheusStatLogger` при включённом флаге заводит три гистограммы с общей сеткой бакетов от 1 мс до 1800 с:

- `vllm:kv_block_lifetime_seconds` — от выделения до вытеснения;
- `vllm:kv_block_idle_before_evict_seconds` — простой с последнего обращения до вытеснения;
- `vllm:kv_block_reuse_gap_seconds` — промежутки между последовательными обращениями.

**Зависимость от prefix caching.** `on_block_evicted` вызывается из `_maybe_evict_cached_block()`, а этот путь работает при включённом prefix caching (плюс отдельный вызов из `evict_blocks_from_cache()` для KV-коннекторов). С `--no-enable-prefix-caching` события вытеснения практически не появляются, и все три гистограммы остаются пустыми, хотя выборка блоков продолжает вестись.

## Значения и формат

- Значение по умолчанию `false`; «не задан» и `--no-kv-cache-metrics` эквивалентны.
- Долю выборки задаёт отдельный аргумент `--kv-cache-metrics-sample`.
- Отдельного способа включить только одну из трёх гистограмм нет.

## Когда использовать

- Решение «включать ли prefix caching» и «хватает ли KV-cache»: короткое время жизни блоков при большом idle означает, что кэш заполняется мусором, который не переиспользуется.
- Подбор `--gpu-memory-utilization` под кэш-ориентированную нагрузку: если блоки вытесняются раньше, чем к ним возвращаются, кэш мал.
- Диагностика сценариев с длинными системными промптами: `reuse_gap` показывает, укладываются ли обращения в окно жизни блока.
- Не включайте вместе с `--disable-log-stats`: события накапливаются, а результата вы не увидите.
- Не включайте надолго на нагрузке с высокой частотой аллокаций без нужды — накладные расходы небольшие, но не нулевые и приходятся на горячий путь планировщика.

## Влияние на производительность и память

- **CPU планировщика.** Один вызов `random.random()` на **каждый** выделенный блок, независимо от `--kv-cache-metrics-sample`: доля влияет только на то, заводить ли состояние. Плюс словарный `get` на каждое обращение к блоку и `pop` на вытеснение. Всё это в однопоточном цикле планировщика.
- **RAM хоста.** Словарь состояний ограничен числом блоков KV-cache; каждое состояние — время рождения, время последнего обращения и `deque` максимум на 4 отметки. Список событий между вычитываниями пропорционален числу вытеснений за интервал — и растёт неограниченно, если статистика выключена.
- **VRAM.** Не влияет.
- **`/metrics`.** Три гистограммы по 21 бакету на движок.

## Взаимодействие с другими аргументами

- `--kv-cache-metrics-sample`: доля отслеживаемых блоков.
- `--disable-log-stats`: делает метрики бесполезными и превращает накопитель событий в растущий список.
- `--enable-prefix-caching`: без него события вытеснения практически не генерируются.
- `--block-size`: определяет, сколько токенов приходится на один блок, то есть масштаб «времени жизни блока».
- `--gpu-memory-utilization`: определяет число блоков и тем самым частоту вытеснений.

## Типовые проблемы и диагностика

- **Симптом:** флаг задан, гистограммы `vllm:kv_block_*` в `/metrics` отсутствуют. **Причина:** метрики создаются только при включённом флаге в `PrometheusStatLogger`; если их нет, значение флага до логгера не дошло. **Проверка:** `curl -s localhost:8000/metrics | grep kv_block`. **Лечение:** проверить фактическую командную строку процесса.
- **Симптом:** гистограммы есть, но все нулевые. **Причина:** нет вытеснений — либо prefix caching отключён, либо KV-cache не заполняется, либо выборка слишком мала для наблюдаемого объёма. **Лечение:** проверить `--enable-prefix-caching`, поднять `--kv-cache-metrics-sample`.
- **Симптом:** рост потребления RAM процессом движка при включённом флаге. **Причина:** `--disable-log-stats` — события не вычитываются. **Лечение:** убрать `--disable-log-stats` или флаг.
- **Симптом:** после `POST /v1/reset_prefix_cache` гистограммы перестали пополняться. **Причина:** `reset()` очистил и состояния, и накопленные события. **Лечение:** ожидаемое поведение, данные наберутся заново.
- **Подтверждение принятого значения:** наличие серий `vllm:kv_block_lifetime_seconds_bucket` в `/metrics`.

## Примеры

```bash
vllm serve /models/Qwen3-4B --kv-cache-metrics --enable-prefix-caching
```

```bash
vllm serve /models/Qwen3-4B --kv-cache-metrics --kv-cache-metrics-sample 0.05 --gpu-memory-utilization 0.85
```
