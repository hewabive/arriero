# --fingerprint-value

## Кратко

Аргумент имеет смысл ровно в одной комбинации — с `--fingerprint-mode custom`. Тогда `system_fingerprint` во всех ответах становится этой строкой, без версии, топологии и хеша конфигурации.

Обратная сторона: отпечаток перестает быть сигналом об изменении конфигурации. Он меняется только тогда, когда вы сами поменяете значение.

## Оригинальная справка

```text
Literal fingerprint string used when ``--fingerprint-mode=custom``.
```

## Паспорт аргумента

- Флаги: `--fingerprint-value`
- Группа argparse: `Frontend`
- Тип значения: str
- Допустимые значения: не ограничены; никакой валидации формата нет
- Значение по умолчанию: `None`
- Эффективное значение: читается только при `--fingerprint-mode custom`; при `None` в этом режиме `build_system_fingerprint` возвращает `None`, и поле сериализуется как `null` — то же, что режим `none`
- Где объявлен: `vllm/entrypoints/openai/cli_args.py:BaseFrontendArgs.fingerprint_value`
- Этап применения: инициализация состояния генеративного роутера → сборка каждого ответа

## Что меняет в движке

`set_default_fingerprint_mode(mode, custom_value)` сохраняет пару в модульных переменных `vllm/entrypoints/serve/utils/fingerprint.py`. Дальше `build_system_fingerprint` для режима `custom` возвращает `custom_value` вторым же условием — до того, как вообще импортируется версия vLLM и вычисляется `compute_hash()`.

Значение кэшируется в `self.system_fingerprint` каждого serving-класса при его конструировании. Изменить его на живом сервере нельзя — только перезапуском.

Место в ответе то же, что у любого отпечатка: нестриминговые ответы чата и completions, а в стриминге — терминальный чанк или финальный usage-чанк.

## Значения и формат

- Произвольная строка: `--fingerprint-value prod-chat-2026-08`.
- Проверок нет: длина, символы и уникальность на совести оператора. Пробелы допустимы, но их придется экранировать в shell.
- Пустая строка — это не `None`: `""` уйдет в ответ как пустое значение поля.
- В режимах `full`, `hash` и `none` значение не читается вовсе.

## Когда использовать

- Отпечаток должен идентифицировать ваш сервис, а не сборку vLLM: версия релиза вашего API, идентификатор развертывания.
- Нужно скрыть версию движка и топологию параллелизма от клиента, но оставить непустое поле для совместимости с клиентским кодом, который его читает.
- Не используйте, если клиент опирается на смену отпечатка для инвалидации своего кэша: статичная строка эту функцию убивает. В таком случае берите `--fingerprint-mode hash`.
- Не кладите сюда ничего чувствительного: поле уходит в каждый ответ, включая ответы неаутентифицированных клиентов, если сервер открыт.

## Влияние на производительность и память

Не влияет: строка подставляется без вычислений, а `compute_hash()` в режиме `custom` вообще не вызывается — старт даже чуть дешевле.

## Взаимодействие с другими аргументами

- `--fingerprint-mode`: единственный аргумент, который активирует это значение; `custom` без значения равнозначен `none`.
- `--served-model-name`: другое поле ответа, которым отвязывают публичный контракт от внутренней конфигурации; их удобно менять согласованно.

## Типовые проблемы и диагностика

- **Симптом:** значение задано, а в ответе прежний `vllm-...`-отпечаток. **Причина:** режим не `custom`. **Лечение:** добавить `--fingerprint-mode custom`.
- **Симптом:** `system_fingerprint` равен `null`, хотя режим `custom`. **Причина:** значение не задано. **Лечение:** задать `--fingerprint-value`.
- **Симптом:** клиент перестал замечать смену модели. **Причина:** статичный отпечаток. **Лечение:** включать в строку версию вашего развертывания и менять ее при каждой смене конфигурации либо перейти на `--fingerprint-mode hash`.
- **Подтверждение принятого значения:** поле `system_fingerprint` в обычном нестриминговом ответе.

## Примеры

```bash
vllm serve /models/Qwen3-4B --fingerprint-mode custom --fingerprint-value prod-chat-2026-08
```

```bash
vllm serve /models/Qwen3-4B --fingerprint-mode custom --fingerprint-value arriero-qwen3-4b-r7 --served-model-name qwen3-4b
```
