# --config

## Кратко

`--config` — не обычный аргумент. Его значение никогда не читается из разобранного namespace: `FlexibleArgumentParser.parse_args` перехватывает пару токенов `--config <path>` **до** вызова argparse, разворачивает YAML в плоский список флагов и вставляет его в командную строку, а сами два токена удаляет.

Место вставки и определяет приоритет: значения из файла попадают сразу после подкоманды и позиционной модели, то есть **левее** всех явных флагов. Argparse при повторе одного и того же флага сохраняет последнее значение — поэтому явный флаг в командной строке перебивает файл, а порядок приоритетов получается `командная строка > файл > дефолты`.

## Оригинальная справка

```text
Read CLI options from a config file. Must be a YAML with the following options: https://docs.vllm.ai/en/latest/configuration/serve_args.html
```

## Паспорт аргумента

- Флаги: `--config`
- Группа argparse: без группы (объявлен напрямую в `make_arg_parser`)
- Тип значения: путь к файлу YAML
- Допустимые значения: путь к существующему файлу с расширением `.yaml` или `.yml`
- Значение по умолчанию: нет; при отсутствии аргумента подстановка не выполняется
- Эффективное значение: не применимо — `args.config` не читает ни один потребитель, вся работа делается препроцессором командной строки
- Где объявлен: `vllm/entrypoints/openai/cli_args.py:make_arg_parser`
- Этап применения: предобработка `sys.argv` в `FlexibleArgumentParser.parse_args`, до разбора argparse и до любого создания конфигов

## Что меняет в движке

`_pull_args_from_config` (`vllm/utils/argparse_utils.py`) выполняет следующее.

1. Проверяет, что `--config` встречается не более одного раза (`assert args.count("--config") <= 1, "More than one config file specified!"`), и что за ним есть путь.
2. `load_config_file` читает YAML через `yaml.safe_load` и разворачивает словарь верхнего уровня в плоский список аргументов по правилам, разобранным ниже.
3. Вставляет полученный список в командную строку. Для `vllm serve` с позиционной моделью результат выглядит как `["serve", "<model>", *config_args, *остальные_явные_флаги]`; если модели в командной строке нет, конфигурационные аргументы идут сразу после `serve`.
4. Пара токенов `--config <path>` из командной строки удаляется.

Только после этого запускается нормализация имен (дефис и подчеркивание в именах флагов взаимозаменяемы) и собственно argparse. Поэтому ключ `tensor_parallel_size` в YAML работает так же, как `tensor-parallel-size`.

Модель разрешается особо: если позиционной модели нет ни в командной строке, ни в файле (ключ `model`), препроцессор падает с `No model specified! Please specify model either as a positional argument or in a config file.` Если модель есть и там, и там — выигрывает позиционная из командной строки.

Ключевое ограничение реализации: перехват срабатывает по точному сравнению токена (`if "--config" in args`). Форма `--config=file.yaml` до препроцессора не доходит, попадает в argparse как обычная строковая опция и оседает в `args.config`, которую никто не читает. Внешне это выглядит как «конфиг проигнорирован без единого сообщения» — сервер стартует полностью на дефолтах.

## Значения и формат

Расширение обязано быть `.yaml` или `.yml`, иначе `Config file must be of a yaml/yml type. <ext> supplied`. Ошибка чтения файла логируется как `Unable to read the config file at <path>. Check path correctness` и пробрасывается наружу.

Правила разворачивания значений верхнего уровня:

- **скаляр** → `--key`, `str(value)`. Числа, строки и пути пишутся как есть;
- **`true`** → добавляется голый флаг `--key`;
- **`false`** → добавляется `--no-key`, **но только если такой флаг зарегистрирован**. Для `store_true`-флагов (например `disable-log-stats`) парной `--no-` половины нет, и ключ молча пропадает — «выключить» через файл нельзя, потому что он и так выключен по умолчанию, а вот попытка отменить файлом флаг, заданный в командной строке, не сработает;
- **список** → `--key item1 item2 ...`; **пустой список молча пропускается**;
- **словарь** → `--key '<JSON>'`. Так задаются вложенные `compilation-config`, `speculative-config` и другие JSON-аргументы;
- **`null`** → превращается в строку `None`. Для аргументов, объявленных как `optional`, движок принимает это как «не задано»; для остальных приведет к ошибке типа.

Вложенность глубже одного уровня работает только внутри значения-словаря: он целиком уходит в JSON. Дробить JSON-аргумент на точечные под-флаги в YAML нельзя.

## Когда использовать

- Когда конфигурация повторяется между запусками и ее удобнее держать одним файлом рядом с моделью, а не длинной командной строкой.
- Когда нужен базовый профиль плюс несколько точечных отличий: базу — в YAML, отличия — явными флагами, они выиграют.
- **Не используйте в инстансах arriero.** Аргументы инстанса живут в `config/instances/<name>.json` и версионируются через Configuration Git; вынесенный YAML не отслеживается ничем. Следствия конкретные: детектор дрейфа конфигурации сравнивает аргументы, окружение, бинарь и `numa` из снимка запуска, поэтому правка YAML при живом процессе не даст бейджа `config drift`; оценщик памяти `vllm-gpu-util` читает `--gpu-memory-utilization`, `--tensor-parallel-size` и `--max-model-len` из списка аргументов инстанса и не увидит их, если они спрятаны в файле; подстановка плейсхолдеров `${ARRIERO_*}` к содержимому YAML не применяется, поэтому абсолютные пути внутри него ломаются при переносе каталога приложения. См. `docs/PORTABLE_PATHS.md` и `docs/MEMORY_ESTIMATION.md` (arriero).

## Влияние на производительность и память

На работу движка не влияет: к моменту создания любого конфига `--config` уже не существует — есть только развернутые из него флаги. Единственный измеримый эффект — чтение одного небольшого файла при старте.

## Взаимодействие с другими аргументами

- Со **всеми** аргументами разом: файл может содержать любой длинный флаг `vllm serve`. Явный флаг в командной строке всегда перебивает файл.
- `--model`: ключ `model` в YAML заменяет позиционный аргумент; при наличии позиционного выигрывает позиционный. Отдельная тонкость — предупреждение об устаревании `--model` печатается только для формы из командной строки, ключ из файла его не вызывает.
- `--served-model-name`: если он задан, а модели нет ни позиционно, ни в файле, парсер требует позиционную модель; при наличии `--config` эта проверка пропускается, и ошибка вместо нее приходит из препроцессора конфига.
- `--compilation-config`, `--speculative-config` и прочие JSON-аргументы: в YAML записываются вложенным словарем и превращаются в одну JSON-строку.

## Типовые проблемы и диагностика

- **Симптом:** сервер стартовал так, будто конфига нет, никаких сообщений. **Причина:** использована форма `--config=file.yaml`. **Лечение:** писать через пробел: `--config file.yaml`.
- **Симптом:** `Config file must be of a yaml/yml type. json supplied`. **Причина:** расширение не `.yaml`/`.yml`. **Лечение:** переименовать файл; формат все равно должен быть YAML.
- **Симптом:** `No config file specified! Please check your command-line arguments.` **Причина:** `--config` стоит последним токеном без пути.
- **Симптом:** `AssertionError: More than one config file specified!` **Причина:** два `--config` в одной строке; слияние файлов не поддерживается.
- **Симптом:** `unrecognized arguments: --foo bar`. **Причина:** ключ в YAML не соответствует ни одному длинному флагу установленной версии. **Проверка:** `vllm serve --help=all` в том же окружении. Это тот же класс расхождения между декларацией и установленной сборкой, что описан в `docs/CASE_PHANTOM_HELP_ARGS.md` (arriero).
- **Симптом:** `No model specified! Please specify model either as a positional argument or in a config file.` **Лечение:** добавить ключ `model` в YAML либо позиционную модель в команду.
- **Симптом:** ключ со значением `false` не дал никакого эффекта. **Причина:** у флага нет парной `--no-` формы, ключ отброшен. **Лечение:** просто не указывать ключ.
- **Подтверждение принятого значения:** прямой строки «конфиг прочитан» нет. Проверяйте по строке `non-default args: {...}`, которую сервер печатает при старте (`log_non_default_args` в `setup_server`): развернутые из файла аргументы попадают в нее наравне с явными.

## Примеры

```bash
vllm serve /models/Qwen3-4B --config /etc/vllm/qwen3-4b.yaml
```

```bash
vllm serve /models/Qwen3-4B --config /etc/vllm/qwen3-4b.yaml --gpu-memory-utilization 0.7
```
