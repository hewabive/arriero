# --tokenizer-revision

## Кратко

`--tokenizer-revision` — ветка, тег или коммит репозитория токенизатора. Отдельный аргумент существует потому, что токенизатор может браться не оттуда, откуда веса.

Если он не задан, движок сначала приравнивает его к `--revision`, а затем, если токенизатор и модель — один и тот же репозиторий, подставляет уже разрешенный commit-хеш модели, чтобы не ходить в Hub дважды.

## Оригинальная справка

```text
The specific revision to use for the tokenizer on the Hugging Face Hub.
It can be a branch name, a tag name, or a commit id. If unspecified, will
use the default version.
```

## Паспорт аргумента

- Флаги: `--tokenizer-revision`
- Группа argparse: `ModelConfig`
- Тип значения: str или `None`
- Допустимые значения: имя ветки, имя тега или commit-хеш; не ограничены парсером
- Значение по умолчанию: `None` — «версия по умолчанию репозитория»
- Эффективное значение: определяется в `ModelConfig.__post_init__`. Если аргумент не задан, берется `--revision`. Далее: если токенизатор совпадает с моделью, ревизию модели удалось разрешить и пользователь не задавал ревизию токенизатора явно — подставляется резолвнутая ревизия модели; иначе вызывается `resolve_revision(tokenizer, tokenizer_revision, hf_token)`, который превращает ветку/тег в commit-хеш и молча возвращает исходное значение при любой ошибке Hub, для локального пути и при `VLLM_USE_MODELSCOPE`
- Где объявлен: `vllm/config/model.py:ModelConfig.tokenizer_revision`
- Этап применения: сборка `ModelConfig` → загрузка токенизатора и вспомогательных конфигов во фронтенде

## Что меняет в движке

Значение используется везде, где читается репозиторий токенизатора:

- `cached_tokenizer_from_config` передает его в `get_tokenizer(..., revision=...)`;
- `try_get_tokenizer_config(...)` читает `tokenizer_config.json` для pooling-моделей с абсолютными позиционными эмбеддингами — оттуда берется `model_max_length`, который может понизить выведенный `--max-model-len`;
- автодетект Mistral-репозитория (`is_mistral_model_repo`, `any_pattern_in_repo_files`) проверяет наличие `tekken.json`/`tokenizer.model.v*` **для указанной ревизии**;
- при `HF_HUB_OFFLINE=1` `get_model_path(tokenizer, tokenizer_revision)` разрешает локальный путь в кеше именно для этой ревизии.

Ревизия входит в ключ кеша токенизатора (`lru_cache` на `get_tokenizer` и `resolve_tokenizer_args`), поэтому смена значения приводит к повторной загрузке, а не к переиспользованию.

## Значения и формат

- Ветка (`main`), тег (`v1.0`) или полный commit-хеш.
- `None` (не задан) — унаследовать `--revision`, а если и он не задан — версия по умолчанию репозитория.
- Для локального пути значение фактически игнорируется: `resolve_revision` возвращает его как есть, а `from_pretrained` по локальному каталогу ревизию не использует.
- Пустая строка — не то же самое, что `None`: она уйдет в Hub как имя ревизии.

## Когда использовать

- Токенизатор берется из другого репозитория (`--tokenizer` указывает не на модель), и его версию надо зафиксировать отдельно.
- Токенизатор в том же репозитории, но нужная версия отличается от версии весов (исправление шаблона чата в отдельной ветке).
- В остальных случаях аргумент трогать не нужно: наследование от `--revision` уже дает воспроизводимость.

## Влияние на производительность и память

На память не влияет. На время старта влияет однократно: разрешение ревизии — сетевой запрос к Hub, который пропускается для локальных путей и в офлайн-режиме. Косвенно значение может изменить `--max-model-len` у pooling-моделей, если в новой ревизии `tokenizer_config.json` объявляет другой `model_max_length`.

## Взаимодействие с другими аргументами

- `--revision`: источник значения по умолчанию.
- `--tokenizer`: репозиторий, к которому применяется ревизия; при совпадении с `--model` ревизии совмещаются.
- `--code-revision`: пинит ревизию удаленного кода — это третья, независимая ось версионирования.
- `--tokenizer-mode`: автодетект `mistral` проверяет файлы в указанной ревизии.
- `--model`: если ревизия модели не разрешилась, ревизия токенизатора резолвится самостоятельно.

## Типовые проблемы и диагностика

- **Симптом:** ошибка Hugging Face Hub «Revision Not Found» при загрузке токенизатора, хотя модель загрузилась. **Причина:** ревизия существует в репозитории модели, но не в репозитории токенизатора. **Лечение:** задать корректное значение явно.
- **Симптом:** после смены `--revision` токенизатор остался прежним. **Причина:** `--tokenizer-revision` задан явно и не наследует новую ревизию. **Лечение:** убрать явное значение или обновить его.
- **Симптом:** в офлайн-режиме токенизатор не находится. **Причина:** в локальном кеше нет снапшота для этой ревизии. **Проверка:** запись `HF_HUB_OFFLINE is True, replace tokenizer_id [...] to tokenizer_path [...]` в логе старта. **Лечение:** прогреть кеш онлайн или указать локальный каталог.
- **Симптом (pooling):** после смены ревизии токенизатора изменилась выведенная длина контекста. **Причина:** `model_max_length` из `tokenizer_config.json` учитывается для pooling-моделей с абсолютными позиционными эмбеддингами. **Лечение:** задать `--max-model-len` явно.

## Примеры

```bash
vllm serve /models/Qwen3-4B --tokenizer Qwen/Qwen3-4B --tokenizer-revision v1.0
```

```bash
vllm serve Qwen/Qwen3-4B --revision 8dc1b7b3a1b3e4b2b0a4a7e2f6c9b1d0e3f5a7c9 --tokenizer-revision 8dc1b7b3a1b3e4b2b0a4a7e2f6c9b1d0e3f5a7c9
```
