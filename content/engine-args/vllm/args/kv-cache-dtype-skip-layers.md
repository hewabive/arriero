# --kv-cache-dtype-skip-layers

## Кратко

Аргумент перечисляет слои, которые должны остаться вне квантования KV-cache, даже если `--kv-cache-dtype` задает квантованный формат. Такие слои получают `kv_cache_dtype = "auto"`, то есть хранят K/V в dtype модели.

Это точечный инструмент для восстановления точности на чувствительных слоях. Плата за него не только в памяти самих слоев: смешанные dtype в одном block pool вынуждают движок увеличить `--block-size` и дополнить страницы skip-слоев паддингом.

## Оригинальная справка

```text
Layer patterns to skip KV cache quantization. Accepts layer indices
(e.g., '0', '2', '4') or attention type names (e.g., 'sliding_window').
```

## Паспорт аргумента

- Флаги: `--kv-cache-dtype-skip-layers`
- Группа argparse: `CacheConfig`
- Тип значения: список строк (`nargs="+"`, элементы разделяются пробелами)
- Допустимые значения: не ограничены списком; распознаются два вида элементов — десятичный индекс слоя в виде строки и имя типа внимания `sliding_window`. Неизвестный элемент не вызывает ошибку, он просто ни с чем не совпадет
- Значение по умолчанию: `field(default_factory=list)`, то есть пустой список
- Эффективное значение: при `--kv-cache-dtype turboquant_*` `create_engine_config` **дописывает** в список граничные слои из `TurboQuantConfig.get_boundary_skip_layers(model_config)` — итоговый список является объединением заданного пользователем и вычисленного
- Где объявлен: `vllm/config/cache.py:CacheConfig.kv_cache_dtype_skip_layers`
- Этап применения: `create_engine_config` → выравнивание размера блока (`_align_heterogeneous_kv_block_size`) → построение attention-слоев → построение KV-cache spec

## Что меняет в движке

Список читается в конструкторе `Attention` (`vllm/model_executor/layers/attention/attention.py`) и в MLA-аналоге. Слой считается пропущенным, если выполнено хотя бы одно:

- `sliding_window` есть в списке, а у слоя задано окно (`sliding_window is not None`);
- строковое представление индекса слоя (`extract_layer_index(prefix)`) присутствует в списке.

Для такого слоя `kv_cache_dtype` принудительно становится `"auto"`, и его KV-cache spec строится в dtype модели.

Дальше вступает выравнивание страниц. Пока список пуст, все слои имеют одинаковый размер страницы, и block pool тривиален. Как только список непуст, `Platform.update_block_size_for_backend` вызывает `_align_heterogeneous_kv_block_size`:

1. считает per-token-страницу «основного» квантованного формата и per-token-страницу неквантованного skip-слоя;
2. если они равны — ничего не делает (страницы сводятся целочисленным масштабированием);
3. иначе поднимает `cache_config.block_size` до ближайшего кратного kernel-выравниванию размера, при котором квантованная страница покрывает страницу skip-слоя, и пишет в лог `Setting attention block size to %d tokens so the quantized primary KV page covers the higher-precision padded-spec page.`;
4. записывает получившуюся общую страницу в `cache_config.skip_page_size_padded`, чтобы skip-слои добивались паддингом ровно до нее.

`skip_page_size_padded` затем используется при построении spec слоев со скользящим окном: там выбирается наибольший kernel-блок, влезающий в общую страницу, чтобы уменьшить долю паддинга.

## Значения и формат

- Элементы разделяются пробелами: `--kv-cache-dtype-skip-layers 0 1 31`.
- Индекс слоя пишется как десятичное число без префиксов; сравнение строковое, поэтому `01` не совпадет со слоем `1`.
- `sliding_window` — не индекс, а класс слоев: пропускаются все слои со скользящим окном.
- Пустое значение задать нельзя — просто не указывайте аргумент.
- Совпадения проверяются независимо: слой попадет под пропуск, если совпал хотя бы по одному критерию.

## Когда использовать

- Когда квантование KV-cache в целом дает нужную экономию, но качество проседает на конкретных слоях — обычно на первом и последнем — и вы готовы вернуть им полную точность.
- Когда модель смешивает полное внимание и скользящее окно, а деградация локализована в SWA-слоях: `sliding_window` выводит их из-под квантования одной записью.
- Не используйте с `--kv-cache-dtype auto` или другим неквантованным форматом: пропускать нечего, зато включается лишняя ветка выравнивания страниц.
- Не задавайте вручную при `turboquant_*`, если не понимаете, что делаете: граничные слои движок уже добавит сам, а ваш список с ними объединится.

## Влияние на производительность и память

- **VRAM.** Skip-слои занимают полную точность вместо квантованной; плюс к этому паддинг до общей страницы. Итоговый `GPU KV cache size: N tokens` будет ниже, чем при чистом квантовании всех слоев.
- **Размер блока.** Может вырасти принудительно, что ухудшает гранулярность prefix caching и увеличивает внутреннюю фрагментацию.
- **Скорость.** Kernel'ы для skip-слоев работают в неквантованном режиме; заметного замедления от самого факта пропуска не возникает.
- **Выбор backend'а.** Не меняется напрямую этим списком, но зависит от того, какой `--kv-cache-dtype` остался у основных слоев.

## Взаимодействие с другими аргументами

- `--kv-cache-dtype`: без квантованного формата аргумент бессмысленен. Для `turboquant_*` список автоматически дополняется.
- `--block-size`: может быть поднят принудительно, перекрывая явно заданное значение.
- `--attention-backend`: skip-слои и основные слои должны обслуживаться одним и тем же backend'ом, поэтому он обязан поддерживать оба формата.
- `--gpu-memory-utilization`: бюджет тот же, а средняя цена токена выше — доступная concurrency падает.

## Типовые проблемы и диагностика

- **Симптом:** после добавления списка `--block-size` в логе вырос, а prefix cache стал реже попадать. **Причина:** `_align_heterogeneous_kv_block_size` подняла блок под общую страницу. **Проверка:** строка `Setting attention block size to %d tokens so the quantized primary KV page covers the higher-precision padded-spec page.` **Лечение:** уменьшить число skip-слоев либо смириться и настроить `--prefix-match-unit`, если групп несколько.
- **Симптом:** список задан, но качество не изменилось. **Причина:** индексы не совпали (нумерация слоев берется из имени модуля через `extract_layer_index`, а не из вашего представления о нумерации). **Проверка:** debug-строка `Layer %s: kv_cache_dtype=%s, sliding_window=%s` для каждого слоя. **Лечение:** сверить индексы по этой строке.
- **Симптом:** `GPU KV cache size` заметно меньше ожидаемого при том же `--gpu-memory-utilization`. **Причина:** паддинг skip-слоев до общей страницы. **Лечение:** сократить список.
- **Симптом:** при `turboquant_*` в конфиге видны skip-слои, которых вы не задавали. **Причина:** штатное дополнение граничными слоями в `create_engine_config`.

## Примеры

```bash
vllm serve /models/Qwen3-4B --kv-cache-dtype fp8 --kv-cache-dtype-skip-layers 0 1
```

```bash
vllm serve /models/gemma-3-12b-it --kv-cache-dtype fp8 --kv-cache-dtype-skip-layers sliding_window
```
