# --root-path

## Кратко

`--root-path /llm` выставляет `app.root_path`. Это чисто презентационная настройка ASGI: она нужна, чтобы схема OpenAPI и Swagger UI строили ссылки с учетом префикса, под которым сервер опубликован обратным прокси.

Аргумент **не** переносит маршруты: `/v1/chat/completions` продолжает отвечать и без префикса. И он не создает дыры в аутентификации — `AuthenticationMiddleware` снимает `root_path` из пути до сверки с защищенными префиксами.

## Оригинальная справка

```text
FastAPI root_path when app is behind a path based routing proxy.
```

## Паспорт аргумента

- Флаги: `--root-path`
- Группа argparse: `Frontend`
- Тип значения: str, допускается `None`
- Допустимые значения: не ограничены; осмысленно — путь с ведущим слэшем и без завершающего (`/llm`)
- Значение по умолчанию: `None`
- Эффективное значение: присваивается как `app.root_path = args.root_path`; при `None` FastAPI просто не выставляет `scope["root_path"]`
- Где объявлен: `vllm/entrypoints/openai/cli_args.py:FrontendArgs.root_path`
- Этап применения: HTTP-слой, `build_app()` — после регистрации всех роутеров и до добавления middleware

## Что меняет в движке

Единственная строка в `build_app()` — `app.root_path = args.root_path`. Дальше значение живет в ASGI-scope и влияет на две вещи:

1. **Генерация URL.** Swagger UI, ReDoc и `openapi.json` учитывают префикс, поэтому «Try it out» бьет по правильному адресу за прокси.
2. **Проверка ключа.** `AuthenticationMiddleware` делает `url_path = scope["path"].removeprefix(root_path)` и только потом сверяет с `GUARDED_PREFIX`. Благодаря этому запрос `/llm/v1/chat/completions` защищен так же, как `/v1/chat/completions`. Upstream-тест `tests/entrypoints/openai/chat_completion/test_root_path.py` проверяет обе формы адреса с правильным и неправильным ключом.

Обратите внимание: uvicorn запускается **без** собственного `--root-path`, vLLM его не передает. Снятие префикса из входящего пути (если прокси его не снял сам) выполняет обработка `root_path` в starlette, а не vLLM.

## Значения и формат

- Строка вида `/llm`. Ведущий слэш обязателен для осмысленного результата, завершающий не нужен.
- Не задан — префикса нет, ссылки в документации строятся от корня.
- Значение не проверяется на существование маршрутов и вообще не валидируется.
- Оба адреса — с префиксом и без — продолжают отвечать; аргумент не «переносит» API.

## Когда использовать

- Когда vLLM опубликован обратным прокси по подпути (`https://host/llm/v1/...`) и нужно, чтобы Swagger UI и схема OpenAPI выдавали работающие ссылки.
- Не используйте как способ «спрятать» API: путь без префикса продолжает работать, это не механизм ограничения доступа.
- На управляемых инстансах arriero аргумент бесполезен: менеджер обращается к инстансу напрямую по `http://<--host>:<--port>` и префикс пути для движка `vllm` не поддерживает. Публичный подпуть решается на стороне arriero (`docs/SUBPATH_DEPLOY.md`, arriero).

## Влияние на производительность и память

Не влияет: одна строка в scope запроса.

## Взаимодействие с другими аргументами

- `--api-key`: префикс снимается до проверки, обхода аутентификации не возникает.
- `--disable-fastapi-docs`: если документация отключена, основной смысл `--root-path` (правильные ссылки в Swagger) пропадает.
- `--enable-offline-docs`: офлайн-документация подключает статику по абсолютному пути `/static/...`, поэтому за прокси с подпутем эти ссылки надо проверять отдельно.
- `--host`, `--port`: адрес прослушивания не меняется, префикс существует только на уровне HTTP-пути.

## Типовые проблемы и диагностика

- **Симптом:** Swagger UI за обратным прокси шлет запросы не туда. **Причина:** `--root-path` не задан, ссылки строятся от корня. **Лечение:** задать префикс, под которым сервер опубликован.
- **Симптом:** запросы с префиксом отвечают 404. **Причина:** обратный прокси снимает префикс сам, а клиент шлет его повторно, или наоборот. **Проверка:** `curl -i http://127.0.0.1:8000/llm/v1/models` и `curl -i http://127.0.0.1:8000/v1/models` напрямую к инстансу.
- **Симптом:** ожидали, что после `--root-path` корневые пути закроются. **Причина:** так это не работает — оба варианта отвечают. **Лечение:** ограничивать доступ прокси или файрволом.
- **Симптом (arriero):** после добавления `--root-path` инстанс выглядит здоровым, но модель не находится. **Причина:** менеджер опрашивает корневые пути; если прокси перед движком не участвует, поведение не меняется, а если ожидалось смещение путей — оно не наступит.

## Примеры

```bash
vllm serve /models/Qwen3-4B --host 127.0.0.1 --port 8000 --root-path /llm
```

```bash
vllm serve /models/Qwen3-4B --host 127.0.0.1 --port 8000 --root-path /llm --api-key edge-key
```
