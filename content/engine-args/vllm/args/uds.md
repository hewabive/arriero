# --uds

## Кратко

`--uds <path>` создает сокет `AF_UNIX` вместо TCP: сервер становится доступен только через файл в файловой системе, `--host` и `--port` не используются. Это самая надежная изоляция для сценария «клиент на том же хосте» — сетевого доступа нет вообще.

Цена — прав доступа теперь два уровня: сам сокет-файл и его каталог. vLLM не выставляет им ни режима, ни владельца и не удаляет файл при завершении.

## Оригинальная справка

```text
Unix domain socket path. If set, host and port arguments are ignored.
```

## Паспорт аргумента

- Флаги: `--uds`
- Группа argparse: `Frontend`
- Тип значения: str (путь к файлу сокета), допускается `None`
- Допустимые значения: не ограничены; действуют лимиты ОС на длину пути `sun_path` (около 100 байт)
- Значение по умолчанию: `None` — используется TCP
- Эффективное значение: не переопределяется; при непустом значении отключает всю TCP-ветку (`--host`, `--port`)
- Где объявлен: `vllm/entrypoints/openai/cli_args.py:FrontendArgs.uds`
- Этап применения: HTTP-слой, `setup_server()` — создание сокета до сборки движка

## Что меняет в движке

`setup_server()` разветвляется по `if args.uds:` и вызывает `create_server_unix_socket(path)` — `socket(AF_UNIX, SOCK_STREAM)` плюс `bind(path)`. Ни `unlink` перед привязкой, ни `chmod`, ни `os.umask` не выполняются, права наследуются от umask процесса. Адрес в логе печатается как `unix:<path>`.

Сокет-файл не удаляется при остановке: `run_server_worker` закрывает сокет (`sock.close()`), а путь остается в файловой системе. Следующий старт по тому же пути падает на `bind`.

Явный запрет: `--data-parallel-multi-port-external-lb` вместе с `--uds` отвергается с сообщением `Error: --data-parallel-multi-port-external-lb does not support --uds`.

## Значения и формат

- Абсолютный путь в существующем каталоге: `/run/user/1000/vllm-qwen.sock`.
- Каталог должен существовать заранее — vLLM его не создает.
- Файл не должен существовать на момент старта.
- Клиент должен уметь работать с unix-сокетом: `curl --unix-socket <path> http://localhost/v1/models`, `httpx.HTTPTransport(uds=...)` (так это делает и upstream-тест `vllm/tests/entrypoints/openai/test_uds.py`).
- Ограничение доступа — задача файловой системы: права на сокет и на каталог. Ключ `--api-key` поверх unix-сокета работает, но защищает те же префиксы, что и в TCP-режиме, то есть не все.

## Когда использовать

- Когда клиент живет на том же хосте и нужно исключить любую сетевую доступность (в том числе случайную привязку к `0.0.0.0`).
- Когда доступ надо ограничить средствами POSIX: каталог `0700` под конкретным пользователем.
- **Не используйте на управляемых инстансах arriero.** Менеджер строит адрес инстанса как `http://<--host>:<--port>` и опрашивает `/health` и `/v1/models` по TCP; про `--uds` он не знает, поэтому инстанс запустится, но никогда не станет здоровым и не будет доступен через прокси (`docs/API_PROXY_FOUNDATION.md`, arriero).

## Влияние на производительность и память

На память не влияет. Unix-сокет обычно чуть дешевле петлевого TCP (нет разбора IP/TCP-заголовков), но для трафика LLM-инференса это неизмеримо на фоне генерации.

## Взаимодействие с другими аргументами

- `--host`, `--port`: игнорируются полностью.
- `--data-parallel-multi-port-external-lb`: несовместим, старт прерывается с явной ошибкой.
- `--api-key`: применяется так же, как в TCP-режиме, но при unix-сокете основной контур защиты — права файловой системы.
- `--ssl-certfile`, `--ssl-keyfile`: TLS поверх локального unix-сокета смысла не имеет, шифровать нечего.

## Типовые проблемы и диагностика

- **Симптом:** `OSError: [Errno 98] Address already in use` при повторном старте, TCP-порт при этом свободен. **Причина:** сокет-файл остался от прошлого запуска, vLLM его не удаляет. **Лечение:** удалить файл перед стартом или класть сокет в каталог, который создается заново.
- **Симптом:** `OSError: [Errno 2] No such file or directory` на `bind`. **Причина:** каталога нет. **Лечение:** создать каталог заранее.
- **Симптом:** `OSError: [Errno 36] File name too long`. **Причина:** превышен лимит `sun_path`. **Лечение:** короткий путь, например под `/run/user/<uid>/`.
- **Симптом:** клиент получает `Connection refused` по HTTP на 8000. **Причина:** в режиме `--uds` TCP-сокета нет вообще. **Проверка:** строка `Starting vLLM server on unix:/path/to.sock` в логе.
- **Симптом (arriero):** инстанс запущен, но остается в состоянии без здоровья, а цель прокси не переходит в `ready`. **Причина:** менеджер опрашивает TCP-адрес, которого нет. **Лечение:** убрать `--uds` у управляемых инстансов.

## Примеры

```bash
vllm serve /models/Qwen3-4B --uds /run/user/1000/vllm-qwen.sock
```

```bash
curl --unix-socket /run/user/1000/vllm-qwen.sock http://localhost/v1/models
```
