# --mm-hasher-algorithm

## Кратко

Каждый мультимодальный элемент получает `mm_hash` от своего содержимого (плюс id модели и kwargs процессора). Этот хеш — ключ кэша препроцессора, ключ IPC-кэша и идентификатор элемента в encoder cache. Алгоритм задаётся здесь.

По умолчанию `blake3` — он не входит в FIPS 140-3, поэтому в регулируемых средах предусмотрены `sha256` и `sha512`. Никакого другого практического смысла у переключения нет: на качество и на попадания в кэш алгоритм не влияет, влияет только на скорость хеширования.

## Оригинальная справка

```text
Hash algorithm to use for multi-modal input caching. Use `"sha256"` or
`"sha512"` for FIPS-compliant deployments.
```

## Паспорт аргумента

- Флаги: `--mm-hasher-algorithm`
- Группа argparse: `MultiModalConfig`
- Тип значения: enum (строка)
- Допустимые значения: `blake3`, `sha256`, `sha512` (`MMHasherAlgorithm`)
- Значение по умолчанию: `Field(default_factory=_get_mm_hasher_algorithm)` — фабрика, а не константа: она читает устаревшую переменную окружения `VLLM_MM_HASHER_ALGORITHM` и, если та не задана, возвращает `blake3`
- Эффективное значение: при заданной `VLLM_MM_HASHER_ALGORITHM` дефолт берётся из неё, с предупреждением `Using VLLM_MM_HASHER_ALGORITHM environment variable is deprecated and will be removed in v0.27. Please use mm_hasher_algorithm instead.` Явный CLI-флаг переменную перебивает
- Где объявлен: `vllm/config/multimodal.py:MultiModalConfig.mm_hasher_algorithm`
- Этап применения: препроцессинг мультимодальных входов (вычисление `mm_hash`) в API-процессе

## Что меняет в движке

`_get_hasher_factory(algorithm)` (`vllm/multimodal/hasher.py`, кэшируется через `lru_cache`) возвращает конструктор хешера: `blake3.blake3`, `hashlib.sha256` или `hashlib.sha512`. Пакет `blake3` — опциональная зависимость; апстрим намеренно держит её необязательной, потому что в средах со строгими требованиями безопасности её могут не разрешить устанавливать.

Полученный хешер используется в `MultiModalHasher.hash_kwargs`, который вызывается из `BaseMultiModalProcessor` двумя путями:

- `_apply_hf_processor` — когда кэша нет, хеш всё равно считается, чтобы получить `mm_hashes` для запроса;
- `_cached_apply_hf_processor` — хеш считается **до** обращения к кэшу и определяет, какие элементы нужно обрабатывать.

Тот же алгоритм применяется в `vllm/renderers/hf.py` к `prompt_embeds` и в отдельных моделях (`terratorch`, transformers-backend). Хеширование выполняется в API-процессе, то есть тратит его CPU.

Хеш не персистится между запусками: он служит ключом in-memory (или shm) кэшей текущего процесса. Поэтому смена алгоритма — не миграция, а просто холодный кэш после рестарта.

## Значения и формат

- `blake3` — дефолт. Быстрее SHA-семейства на больших буферах; требует установленного пакета `blake3`.
- `sha256` — FIPS 140-3, `hashlib` из стандартной библиотеки, зависимостей нет.
- `sha512` — FIPS 140-3; на 64-битных системах обычно быстрее `sha256`.
- Значение проверяется argparse по `choices`; регистр важен (в конфиге ожидается нижний). Значение из переменной окружения приводится к нижнему регистру фабрикой, значение из CLI — нет.
- Специальных значений (`auto`, `none`) нет; отключить хеширование этим флагом нельзя — для этого выключается сам кэш.

## Когда использовать

- Регулируемая среда (госсектор, финансы), где разрешены только FIPS-алгоритмы: `sha256` или `sha512`.
- Хост, на котором пакет `blake3` не установлен и не может быть установлен: переключение снимает зависимость.
- Не трогайте ради «безопасности»: `mm_hash` — ключ локального кэша, а не подпись. Коллизионная стойкость blake3 для этой задачи избыточна.
- Не трогайте ради производительности в обратную сторону: SHA медленнее blake3, и на видео это заметно в API-процессе.

## Влияние на производительность и память

- **CPU API-процесса.** Единственная реально задетая величина. Хешируется полный буфер медиа-элемента, поэтому на видео и больших изображениях разница между blake3 и sha512 измерима.
- **RAM хоста.** Не влияет: размер ключа несопоставим с размером кэшируемых данных.
- **VRAM.** Не влияет.
- **Latency.** Хеширование лежит на пути запроса до кэша; на мелких изображениях разница незаметна, на видео — добавляет миллисекунды.
- **Попадания в кэш.** Не меняются: ключ детерминирован по содержимому при любом алгоритме.

## Взаимодействие с другими аргументами

- `--mm-processor-cache-gb`: при `0` кэш процессора не создаётся, но `mm_hash` всё равно считается для идентификации элементов — если только не выключено ещё и prefix caching.
- `--enable-prefix-caching`: при `--mm-processor-cache-gb 0` **и** выключенном prefix caching рендерер перестаёт идентифицировать медиа по содержимому и подставляет синтетические uuid; тогда алгоритм хеширования перестаёт что-либо значить для медиа.
- `--mm-processor-cache-type`: ключи в обоих режимах считаются одинаково, меняется только хранилище значений.

## Типовые проблемы и диагностика

- **Симптом:** `ModuleNotFoundError: No module named 'blake3'` при первом мультимодальном запросе. **Причина:** опциональная зависимость не установлена, а алгоритм остался дефолтным. **Лечение:** установить `blake3` в окружение движка либо задать `--mm-hasher-algorithm sha256`.
- **Симптом:** предупреждение `Using VLLM_MM_HASHER_ALGORITHM environment variable is deprecated and will be removed in v0.27.` **Причина:** алгоритм задан переменной окружения. **Лечение:** перенести значение в CLI-флаг; переменная удаляется в v0.27.
- **Симптом:** заметный CPU-оверхед в API-процессе на видео-нагрузке после перехода на SHA. **Причина:** ожидаемая цена FIPS-алгоритма. **Лечение:** если регламент допускает — вернуть `blake3`; иначе увеличить `--api-server-count`, чтобы распараллелить препроцессинг.
- **Подтверждение принятого значения:** значение видно в стартовой строке конфига (`mm_hasher_algorithm=...`); косвенно — по отсутствию импорта `blake3` при `sha256`/`sha512`.

## Примеры

```bash
vllm serve /models/Qwen2.5-VL-7B-Instruct --mm-hasher-algorithm sha256 --mm-processor-cache-gb 4
```

```bash
vllm serve /models/Qwen2.5-VL-7B-Instruct --mm-hasher-algorithm sha512 --mm-processor-cache-type shm --mm-processor-cache-gb 8
```
