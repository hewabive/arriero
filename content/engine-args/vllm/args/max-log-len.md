# --max-log-len

## Кратко

`--max-log-len` — единственная встроенная защита от того, чтобы содержимое запросов и генераций уходило в лог целиком. Значение применяется срезом `[:max_log_len]` и к тексту (символы), и к спискам идентификаторов токенов (элементы).

Аргумент имеет смысл только вместе с логированием запросов или ответов: без `--enable-log-requests` объект `RequestLogger` вообще не создается.

## Оригинальная справка

```text
Max number of prompt characters or prompt ID numbers being printed in
log. The default of None means unlimited.
```

## Паспорт аргумента

- Флаги: `--max-log-len`
- Группа argparse: `Frontend`
- Тип значения: int, допускается `None`
- Допустимые значения: неотрицательное целое; `0` даст пустую строку и пустой список
- Значение по умолчанию: `None` — без ограничения
- Эффективное значение: используется только при созданном `RequestLogger`, то есть при `--enable-log-requests`
- Где объявлен: `vllm/entrypoints/openai/cli_args.py:BaseFrontendArgs.max_log_len`
- Этап применения: HTTP-слой, `init_app_state()` — `RequestLogger(max_log_len=args.max_log_len)`

## Что меняет в движке

`RequestLogger` использует значение в двух местах:

- `log_inputs` — обрезает `prompt` (символы) и `prompt_token_ids` (элементы) перед печатью. Эта строка пишется **только на уровне DEBUG**: без `VLLM_LOGGING_LEVEL=DEBUG` промпт в лог не попадает вовсе, на INFO печатаются лишь идентификатор запроса, параметры сэмплирования и LoRA-запрос.
- `log_outputs` — обрезает текст генерации и список идентификаторов токенов. Текст с finish reason пишется на уровне **INFO**, то есть при включенном `--enable-log-outputs` сгенерированный текст оказывается в обычном логе; идентификаторы токенов уходят отдельной строкой на **DEBUG**.

Асимметрия важна: промпты требуют DEBUG, ответы — нет. Соответственно `--max-log-len` в первую очередь ограничивает утечку **ответов** модели.

## Значения и формат

- Целое число символов/элементов: `--max-log-len 200`.
- Не задан — без ограничения, то есть в лог уйдет весь текст.
- Единица измерения зависит от того, что логируется: для строки это символы, для списка идентификаторов — количество элементов.
- Обрезка выполняется без пометки: увидеть в логе, что строка усечена, невозможно.

## Когда использовать

- Всегда, когда включено любое логирование запросов или ответов на сервере с реальными данными. Значение порядка 100-300 символов достаточно, чтобы опознать запрос, и не сохраняет содержимое.
- В arriero это прямо влияет на объем чувствительных данных на диске: лог инстанса пишется в `runtime/logs/` и доступен в интерфейсе. Собственный сбор тел запросов у прокси включается отдельными узлами конвейера и хранится в другом месте (`docs/API_PROXY_FOUNDATION.md`, arriero).
- Не полагайтесь только на этот аргумент как на анонимизацию: первые сотни символов промпта тоже могут быть чувствительными.

## Влияние на производительность и память

Уменьшает объем записи в лог. На VRAM и генерацию не влияет. Ощутимая выгода — на длинных контекстах, где без ограничения одна строка лога может весить десятки килобайт.

## Взаимодействие с другими аргументами

- `--enable-log-requests`: без него `RequestLogger` не создается и аргумент не действует.
- `--enable-log-outputs`: главный потребитель ограничения, поскольку пишет генерации на INFO.
- `--enable-log-deltas`: при потоковой генерации каждая дельта логируется отдельной строкой и обрезается тем же лимитом.
- `--log-error-stack`: на длину трассировок не влияет.

## Типовые проблемы и диагностика

- **Симптом:** аргумент задан, а промптов в логе нет вообще. **Причина:** `log_inputs` пишет на DEBUG. **Лечение:** `VLLM_LOGGING_LEVEL=DEBUG`, если промпты действительно нужны.
- **Симптом:** в логе целые ответы модели, хотя лимит задан. **Причина:** значение слишком велико или аргумент не применился (нет `--enable-log-requests`). **Проверка:** длина текста в строках `Generated response ...`.
- **Симптом:** при старте предупреждение `--enable-log-requests is set but the minimum log level is higher than DEBUG. Only limited information will be logged`. **Смысл:** нормальное поведение, детальный вывод отключен уровнем логирования.

## Примеры

```bash
vllm serve /models/Qwen3-4B --host 127.0.0.1 --enable-log-requests --max-log-len 200
```

```bash
vllm serve /models/Qwen3-4B --host 127.0.0.1 --enable-log-requests --enable-log-outputs --max-log-len 120
```
