# --port

## Кратко

`--port` задает TCP-порт слушающего сокета. Сокет создается в `setup_server()` до инициализации движка, поэтому порт «занят» с первых секунд старта, но соединения начинают приниматься только после того, как uvicorn перейдет к `listen()` — уже после загрузки весов, компиляции и выделения KV-cache.

На хосте с несколькими инстансами это первый аргумент, который надо распределить осознанно: конфликт по порту виден только на старте второго процесса.

## Оригинальная справка

```text
Port number.
```

## Паспорт аргумента

- Флаги: `--port`
- Группа argparse: `Frontend`
- Тип значения: int
- Допустимые значения: парсером не ограничены; ядро отвергнет значение вне `1..65535`, а порт ниже 1024 требует привилегий
- Значение по умолчанию: `8000`
- Эффективное значение: не переопределяется; полностью игнорируется при заданном `--uds`
- Где объявлен: `vllm/entrypoints/openai/cli_args.py:FrontendArgs.port`
- Этап применения: HTTP-слой, `setup_server()` — привязка сокета до сборки движка

## Что меняет в движке

Значение уходит в `sock_addr = (args.host or "", args.port)` и в `bind()`. Дальше готовый сокет передается в `serve_http()`, а `port=args.port` в `uvicorn.Config` дублирует то же значение для логов и для диагностики при аварийном завершении: в `except asyncio.CancelledError` launcher вызывает `find_process_using_port(port)` и печатает `port %s is used by process %s launched with command: ...`.

Между `bind()` и `listen()` порт находится в промежуточном состоянии: другой процесс уже не может его занять (`EADDRINUSE`), но клиент получает отказ в соединении. Именно поэтому наблюдаемая картина при старте vLLM — «порт не отвечает почти минуту», хотя процесс жив и грузит модель.

При `--api-server-count > 1` сокет создается с `SO_REUSEPORT` и передается всем процессам API-сервера; один порт обслуживают несколько процессов.

## Значения и формат

- Целое число. По умолчанию `8000`.
- Порты ниже 1024 требуют `CAP_NET_BIND_SERVICE` или root; управляемые инстансы arriero запускаются от обычного пользователя, поэтому такие порты для них не подходят.
- Значение игнорируется, если задан `--uds`.
- Порты сопутствующих подсистем задаются **отдельными** аргументами и не производны от `--port`: `--data-parallel-rpc-port`, `--data-parallel-supervisor-port`.

## Когда использовать

- Всегда задавайте явно, если на хосте больше одного инстанса движка: дефолт `8000` одинаков у всех vLLM-процессов.
- Меняйте, когда порт конфликтует с другим сервисом; определить владельца можно `ss -ltnp | grep <port>`.
- Не пытайтесь «зарезервировать» порт заранее: он занимается процессом инстанса и освобождается при его остановке.

## Влияние на производительность и память

Не влияет ни на память, ни на скорость. Значение определяет только точку прослушивания.

## Взаимодействие с другими аргументами

- `--host`: вторая половина адреса; проверка занятости выполняется для пары.
- `--uds`: отменяет `--port` целиком.
- `--api-server-count`: несколько процессов разделяют один порт через `SO_REUSEPORT`.
- `--data-parallel-supervisor-port`, `--data-parallel-rpc-port`: отдельные служебные порты, которые тоже надо разводить между инстансами.

## Типовые проблемы и диагностика

- **Симптом:** `OSError: [Errno 98] Address already in use` на старте. **Причина:** порт занят другим процессом (часто — предыдущим, не до конца остановленным инстансом). **Проверка:** `ss -ltnp | grep <port>`. **Лечение:** сменить порт или снять старый процесс.
- **Симптом:** при остановке в логе появляется `port 8000 is used by process ... launched with command: ...`. **Причина:** launcher нашел владельца порта при отмене серверной задачи. **Смысл:** строка помогает опознать конкурирующий процесс.
- **Симптом:** клиент получает `Connection refused` первые десятки секунд после запуска. **Причина:** сокет забинден, но uvicorn еще не слушает — идет загрузка весов и выделение KV-cache. **Лечение:** ждать `Application startup complete.` в логе, а не опрашивать порт агрессивно (`docs/VLLM_OPERATIONS.md`, arriero).
- **Симптом (arriero):** preflight выдает `Port 8000 conflicts with <instance> (running)` или `Port 8000 is already in use on 127.0.0.1`. **Причина:** менеджер сверяет порт со всеми инстансами и пробует привязку перед запуском. **Лечение:** развести порты между инстансами.

## Примеры

```bash
vllm serve /models/Qwen3-4B --host 127.0.0.1 --port 8010
```

```bash
vllm serve /models/Qwen3-4B --host 127.0.0.1 --port 8010 --disable-access-log-for-endpoints "/health,/v1/models"
```
