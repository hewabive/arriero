# --h11-max-header-count

## Кратко

Значение записывается в поле `h11_max_header_count` объекта `uvicorn.Config` до вызова `config.load()`. Смысл — не дать клиенту прислать запрос с тысячами заголовков и заставить сервер тратить на них память и время разбора.

Два ограничения, о которых стоит знать заранее. Первое: лимит относится к реализации h11; какой парсер выберет uvicorn, vLLM не задает. Второе: значение не валидируется — слишком маленькое число отсечет обычные запросы, идущие через цепочку прокси.

## Оригинальная справка

```text
Maximum number of HTTP headers allowed in a request for h11 parser.
Helps mitigate header abuse. Default: 256.
```

## Паспорт аргумента

- Флаги: `--h11-max-header-count`
- Группа argparse: `Frontend`
- Тип значения: int
- Допустимые значения: парсером не ограничены
- Значение по умолчанию: `H11_MAX_HEADER_COUNT_DEFAULT` из `vllm/entrypoints/serve/utils/constants.py`, то есть `256`
- Эффективное значение: `serve_http()` дополнительно подставляет то же значение по умолчанию, если параметр пришел как `None`; фактическое применение зависит от того, читает ли установленная версия uvicorn это поле
- Где объявлен: `vllm/entrypoints/openai/cli_args.py:FrontendArgs.h11_max_header_count`
- Этап применения: HTTP-слой, `serve_http()` — настройка `uvicorn.Config` перед `load()`

## Что меняет в движке

`serve_http()` извлекает параметр из `uvicorn_kwargs` (в конструктор `uvicorn.Config` он не передается) и присваивает его атрибутом:

```python
config = uvicorn.Config(app, **uvicorn_kwargs)
config.h11_max_incomplete_event_size = h11_max_incomplete_event_size
config.h11_max_header_count = h11_max_header_count
config.load()
```

Дальше все зависит от uvicorn. vLLM **не** передает параметр `http=`, поэтому реализация HTTP-парсера выбирается автоматически: при установленном `httptools` uvicorn возьмет его, а не h11. `httptools` приезжает транзитивно вместе с `fastapi[standard]` (см. `requirements/common.txt`), так что в типичном окружении этот лимит может быть неактивен.

Проверить на своей сборке:

```bash
python -c "import httptools; print(httptools.__version__)"
python -c "import uvicorn, pathlib; print(any('h11_max_header_count' in p.read_text() for p in pathlib.Path(uvicorn.__file__).parent.rglob('*.py')))"
```

Первая команда покажет, будет ли выбран httptools; вторая — знает ли установленный uvicorn вообще про это поле.

## Значения и формат

- Целое число, по умолчанию `256`.
- Разумный диапазон — сотни. Обычный запрос несет десятки заголовков, но цепочка обратных прокси, трассировка и служебные заголовки платформ добавляют свои.
- Слишком маленькое значение (единицы, десятки) отсечет легитимный трафик.
- Отдельный аргумент `--h11-max-incomplete-event-size` ограничивает суммарный размер незавершенного HTTP-события (заголовков или тела) — 4 МиБ по умолчанию; эти два лимита дополняют друг друга.

## Когда использовать

- Когда порт доступен недоверенной сети и нужно ограничить дешевую атаку на разбор заголовков.
- Когда, наоборот, длинная цепочка прокси добавляет много заголовков и запросы начинают отвергаться — тогда значение поднимают.
- На инстансе за прокси arriero трогать нечего: менеджер пересылает заголовки клиента, отбрасывая hop-by-hop, и их количество остается обычным.

## Влияние на производительность и память

Ограничивает объем памяти, который парсер выделит под заголовки одного запроса. На VRAM, время старта и скорость генерации не влияет.

## Взаимодействие с другими аргументами

- `--h11-max-incomplete-event-size`: второй лимит той же группы, размер вместо количества.
- `--middleware`: пользовательское middleware может добавлять собственные заголовки, но лимит проверяется раньше, на разборе запроса.
- `--uvicorn-log-level`: отказ на уровне парсера виден в логах uvicorn; при повышенном уровне такие строки могут не печататься.

## Типовые проблемы и диагностика

- **Симптом:** часть запросов обрывается ошибкой протокола, тогда как тот же запрос с меньшим числом заголовков проходит. **Причина:** превышен лимит. **Лечение:** поднять значение до числа, покрывающего вашу цепочку прокси.
- **Симптом:** значение задано, но поведение не изменилось. **Причина:** uvicorn использует httptools либо установленная версия не знает этого поля. **Проверка:** команды из раздела «Что меняет в движке».
- **Симптом:** нужно понять, сколько заголовков реально приходит. **Проверка:** временно поднять уровень логирования uvicorn или посчитать заголовки на обратном прокси.

## Примеры

```bash
vllm serve /models/Qwen3-4B --host 127.0.0.1 --h11-max-header-count 128
```

```bash
vllm serve /models/Qwen3-4B --host 127.0.0.1 --h11-max-header-count 512 --h11-max-incomplete-event-size 2097152
```
