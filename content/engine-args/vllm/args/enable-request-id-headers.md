# --enable-request-id-headers

## Кратко

Флаг подключает `XRequestIdMiddleware`: при формировании ответа в его заголовки дописывается `X-Request-Id` — значение одноименного заголовка запроса, а если клиент его не прислал, случайный `uuid4().hex`.

Важное уточнение, которое экономит время при отладке: **входящий** `X-Request-Id` используется движком как идентификатор запроса в логах независимо от этого флага — так работает `_base_request_id` в слое обслуживания. Флаг отвечает только за возврат идентификатора клиенту.

## Оригинальная справка

```text
If specified, API server will add X-Request-Id header to responses.
```

## Паспорт аргумента

- Флаги: `--enable-request-id-headers`, `--no-enable-request-id-headers`
- Группа argparse: `Frontend`
- Тип значения: bool (`argparse.BooleanOptionalAction`)
- Допустимые значения: флаг без значения либо парная отрицательная форма
- Значение по умолчанию: `false`
- Эффективное значение: не переопределяется
- Где объявлен: `vllm/entrypoints/openai/cli_args.py:FrontendArgs.enable_request_id_headers`
- Этап применения: HTTP-слой, `build_app()` — подключение middleware после аутентификации

## Что меняет в движке

`XRequestIdMiddleware` — чистое ASGI-middleware. Оно оборачивает `send` и на сообщении `http.response.start` выполняет `response_headers.append("X-Request-Id", request_headers.get("X-Request-Id", uuid.uuid4().hex))`.

Три следствия:

1. Используется `append`, а не `set`: если заголовок уже проставлен обработчиком или внешним слоем, в ответе окажутся два значения.
2. Middleware работает и для `http`, и для `websocket`-scope.
3. Идентификатор в заголовке ответа совпадает с идентификатором в логах только тогда, когда клиент прислал `X-Request-Id` сам. Если заголовка не было, middleware сгенерирует **свой** uuid, а внутренний идентификатор запроса будет сгенерирован отдельно — эти значения не связаны.

## Значения и формат

- Не задан — `false`, заголовок в ответах не появляется.
- `--enable-request-id-headers` — включить.
- `--no-enable-request-id-headers` — явно выключить.
- Формат значения не проверяется: что прислал клиент, то и вернется. Это же означает, что заголовок нельзя считать доверенным — его контролирует клиент.

## Когда использовать

- Когда сквозная корреляция «клиент → лог движка» нужна, а клиент сам идентификатор не задает.
- Для устойчивой корреляции лучше противоположный подход: пусть клиент (или прокси) генерирует `X-Request-Id` и шлет его в запросе — тогда значение попадет и в логи движка, и обратно в ответ.
- В arriero свой сквозной идентификатор запроса ведет прокси: у каждого запроса есть трасса с собственным id (`docs/API_PROXY_FOUNDATION.md`, arriero). Заголовки ответа от инстанса прокси пропускает клиенту, поэтому `X-Request-Id` дойдет до потребителя, но с трассой arriero он не связан.

## Влияние на производительность и память

Один заголовок и, в худшем случае, генерация uuid на ответ. Незаметно.

## Взаимодействие с другими аргументами

- `--enable-log-requests`, `--enable-log-outputs`: строки в логе печатаются с идентификатором запроса; смысл флага — дать клиенту тот же ключ поиска.
- `--allowed-headers`: чтобы браузерный клиент мог **прислать** свой `x-request-id`, заголовок должен быть в списке разрешенных CORS.
- `--middleware`: если нужен другой формат идентификатора или связь с внешней трассировкой, это делается собственным middleware.

## Типовые проблемы и диагностика

- **Симптом:** в ответе два заголовка `X-Request-Id`. **Причина:** `append` поверх уже проставленного значения (например, обратным прокси). **Лечение:** снимать дубликат на прокси.
- **Симптом:** идентификатор из ответа не находится в логах движка. **Причина:** клиент не прислал заголовок, middleware сгенерировало собственное значение. **Лечение:** задавать `X-Request-Id` на стороне клиента.
- **Симптом:** заголовка нет вообще. **Причина:** флаг не включен либо ответ сформирован снаружи этого middleware (например, отказ `401` от аутентификации).

## Примеры

```bash
vllm serve /models/Qwen3-4B --host 127.0.0.1 --enable-request-id-headers
```

```bash
curl -i -H "X-Request-Id: trace-42" -H "Content-Type: application/json" -d '{"model":"/models/Qwen3-4B","messages":[{"role":"user","content":"ping"}]}' http://127.0.0.1:8000/v1/chat/completions
```
