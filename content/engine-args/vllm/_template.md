# --argument-name

## Кратко

Что аргумент меняет и в какой момент о нем вспоминает человек, эксплуатирующий сервер. Два-четыре предложения, без вступления про важность vLLM.

## Оригинальная справка

```text
Дословный help из extract, без перевода, без переносов «по вкусу» и без правок.
```

## Паспорт аргумента

- Флаги: `--argument-name` (все элементы `flags` из extract, включая короткий алиас и `--no-*` половину пары)
- Группа argparse: `ModelConfig` (поле `group`; если `null` — так и пиши)
- Тип значения: int / float / str / bool / путь / JSON-объект / список
- Допустимые значения: перечень из `choices`; если `choices: null` — «не ограничены» либо «список собирается в runtime из реестра ...»
- Значение по умолчанию: из `default`; для `kind: expression` — раскрытое значение плюс ограничения (`ge`, `le`, `default_factory`)
- Эффективное значение: чем и на каком шаге дефолт переопределяется (`create_engine_config`, `VllmConfig.__post_init__`, платформенный хук), если это так
- Где объявлен: `vllm/config/model.py:ModelConfig.field` (поле `origin` из extract, дословно)
- Этап применения: разбор CLI / сборка `VllmConfig` / загрузка модели / профилирование и выделение KV-cache / планировщик / forward / HTTP-слой

## Что меняет в движке

Какая подсистема затрагивается и в какой момент. Куда именно попадает значение (поле config-датакласса), кто его читает дальше (worker, model runner, планировщик, KV-cache manager, endpoint), что происходит, если аргумент не задан. Здесь же — переопределения по модели и по платформе, если они есть.

## Значения и формат

Форма записи, единицы, границы, поведение специальных значений (`0`, `-1`, `auto`, `None`, пустая строка). Что отвергает парсер и что отвергает валидация конфига уже после парсинга. Для JSON-аргументов — обе формы записи: одной строкой и точечными под-флагами.

## Когда использовать

- Сценарий, в котором значение по умолчанию не подходит, и признак, по которому это видно.
- Сценарий, в котором аргумент трогать не надо, хотя соблазн есть.

## Влияние на производительность и память

VRAM (веса, KV-cache, активации, CUDA graphs), RAM хоста, время старта (компиляция, прогрев, профилирование), throughput и latency под конкурентной нагрузкой. Если влияния нет — одна конкретная фраза об этом.

## Взаимодействие с другими аргументами

- `--related-argument`: как связаны, какие комбинации осмысленны и какие взаимно исключены.
- Аргументы, которые тянут ту же память или ту же квоту планировщика.

## Типовые проблемы и диагностика

- Симптом (сообщение об ошибке, OOM на старте, просадка throughput, обрезанный ответ).
- Причина.
- Чем подтвердить: строка в логе движка, поле в `/metrics`, вывод `vllm serve --help` установленной версии.
- Как исправить, с конкретными значениями.

## Примеры

```bash
vllm serve /models/model --argument-name value
```

```bash
vllm serve /models/model --argument-name value --related-argument other-value
```
