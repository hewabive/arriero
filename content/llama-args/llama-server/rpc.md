# --rpc

## Кратко

`--rpc` подключает удалённые `ggml-rpc-server` по адресам `host:port` и регистрирует экспортируемые ими устройства в backend registry llama.cpp. После этого удалённые устройства участвуют в обычном выборе устройств и offload модели.

Флаг добавляется в `--help` только когда `llama_supports_rpc()` находит backend `RPC`. И клиентский `llama-server`, и удалённые RPC-серверы должны быть собраны с `-DGGML_RPC=ON`.

## Оригинальная справка llama.cpp

```text
comma-separated list of RPC servers (host:port)
```

## Паспорт аргумента

- Основное имя: `--rpc`
- Значение: список `host:port` через запятую
- Переменная окружения: `LLAMA_ARG_RPC`
- Условие доступности: зарегистрирован backend `RPC`
- Этап применения: парсинг аргументов до выбора устройств и загрузки модели
- Поле в `common_params`: отсутствует; обработчик сразу регистрирует удалённые backend-устройства

## Что меняет в llama-server

Обработчик делит строку по запятым, загружает backend plugins, находит registry с именем `RPC`, получает функцию `ggml_backend_rpc_add_server` и регистрирует backend для каждого endpoint.

Если `--device` не задан, llama.cpp включает RPC-устройства в автоматический список offload-устройств. Веса и KV-cache могут распределяться между локальными и удалёнными устройствами пропорционально доступной памяти. Явные `--device` и `--tensor-split` позволяют ограничить список и задать пропорции.

## Значения и формат

Используйте адреса вида `192.168.88.10:50052` или CSV:

```text
192.168.88.10:50052,192.168.88.11:50052
```

Пустой список отклоняется как `no RPC servers specified`. Если backend не собран или plugin не загрузился, флаг не появится в `--help`; принудительная передача завершится как неизвестный аргумент.

## Когда использовать

Используйте для распределённого offload на ускорители других хостов, когда локальной VRAM недостаточно. RPC backend upstream считает экспериментальным, хрупким и небезопасным: не публикуйте `ggml-rpc-server` в открытой сети и не используйте без сетевой изоляции.

## Влияние на производительность и память

Удалённая память расширяет доступный объём устройств, но обмен тензорами и KV по сети добавляет latency и требует высокой пропускной способности. На Linux с RoCEv2-capable NIC upstream может автоматически использовать RDMA, если поддержка найдена при сборке.

## Взаимодействие с другими аргументами

- `--list-devices` показывает имена зарегистрированных RPC-устройств.
- `--device` ограничивает offload конкретными локальными или RPC-устройствами.
- `--gpu-layers` задаёт общий объём offload.
- `--tensor-split` задаёт пропорции распределения между выбранными устройствами.

## Router-режим

Передавайте `--rpc` внешнему router-процессу: устройства регистрируются глобально при разборе его аргументов, а model presets затем могут выбирать их через `device` и `tensor-split`.

## Типовые проблемы и диагностика

- `unknown argument: --rpc`: сборка не содержит RPC backend; пересоберите с `-DGGML_RPC=ON`.
- `failed to find RPC backend`: plugin RPC не загрузился или недоступен текущему процессу.
- Нет удалённых устройств: проверьте адреса, firewall и вывод `--list-devices`.
- Для подробных RPC-сообщений запустите с `GGML_RPC_DEBUG=1`.

## Пример

```bash
llama-server --model /models/model.gguf \
  --rpc 192.168.88.10:50052,192.168.88.11:50052 \
  --gpu-layers all
```
